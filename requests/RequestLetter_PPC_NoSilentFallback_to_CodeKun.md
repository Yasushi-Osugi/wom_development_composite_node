## B. 直すこと

### B.1 規則の出どころを 1 か所で決める

- 新しい関数（例：`wom/ppc/ppc_rules.py` の `resolve_ppc_rules(model_dir)`）で、規則のフォルダ・共有の規則の宣言（K1）・各ファイルの出どころを決める。返り値に、ファイルごとの出どころ（`model`／`shared:<dir>`）と、足りないファイルを持たせる。
- headless の `_run_ppc()`、GUI の PPC の実行、Value Chain の為替（`FxTable.load()` の呼び出し）、`run_ppc_from_psi()` は、すべてこの関数を使う。S1 の判定を 2 か所に書かない。
- `PPCRuleSet.load()` の黙ったファイルごとの切り替え（S2）は、宣言のあるときだけ行う。宣言の無いときに足りないファイルがあれば、未評価の理由として返す（例外で計画を止めない）。
- **ファイルの優先**：モデルにあるファイルを使い、モデルに無いファイルだけを宣言の場所から読む。宣言の場所にも無ければ、別の場所へ切り替えず、未評価の理由にする。
- **パスの解決**：宣言の相対パス（`data/ppc`）は、**リポジトリの根**から解決する（作業のフォルダによって変わらないように）。絶対パスも受ける。
- **チャネルの対応方式は別に扱う**：今は規則のフォルダの選択と同時に、チャネル名の対応（`use_node_name`）も切り替えている（`_run_ppc()`・GUI）。規則の出どころの判定と、製品・チャネルの対応方式の判定を**別の関数・別の記録**にする。対応方式は今の結果を保つ（市場価格のファイルがモデルにあれば `use_node_name=True`、共有の規則から読んだなら今までどおり False）。§A2 の表のモデルごとの方式が変わらないことを確かめる。
- **経路ごとに要る入力だけを見る**：PPC は規則の 9 ファイル、Value Chain の為替は `ppc_fx_rate.csv` だけ、というように、経路ごとに要るファイルを決める。Value Chain は、PPC 用のほかのファイルが足りないことを理由に止めない。

### B.2 評価の状態を持たせる

PPC の結果に `valuation_status` を持たせる。

| 値 | いつ | 金額の値 |
|---|---|---|
| `評価済み` | 全ての販売記録について、**製品 × 市場 × 適用の週の組合せごとに**、要る価格・仕入れの原価・為替が規則から取れた | 今までどおり |
| `一部未評価` | 評価できない組合せがあり、その記録を除いて評価した（S3） | 評価できた範囲の値。除いた製品・市場ごとの量を、**PPC の記録の件数・WOM の lot 数・物量（lot × `cpu_size`）を分けて**持たせる（今の `total_lots` は集約した販売記録の件数で、WOM の lot 数ではない） |
| `未評価` | 規則のファイルが足りない（宣言なし）、または評価できる記録が 1 件も無い（S4） | **持たない**（0 も入れない）。理由を持たせる |

- **未設定と明示の 0 を分ける**：価格・仕入れの原価が規則に無い組合せを 0 円で計算しない（今の `get_market_price()`・`get_supplier_cost()` の 0 を返す動きを、評価の判定では「未設定」として扱う）。規則に 0 と書いてあるものは明示の 0 として評価する。
- **費用の規則**（ノード・区間・関税・利益ゾーン）は、規則が無いことが「この費用は発生しない」の意味で使われている。今は未設定と区別できないので、**評価済みの判定には使わない**が、規則の当たらない組合せの数を報告書に書く（扱いは大杉さんが後で決める）。
- `ppc_kpi_summary.json`・`ppc_run_info.json` に、状態・理由・除いた製品と市場・規則の出どころを書く。
- **前回の出力を残さない**：`未評価` で終えるとき、出力のフォルダに前回の台帳・P&L・KPI のファイルが残らないようにする（消す、または今回の結果でないことを `ppc_run_info.json` で判定できるようにし、読む側がそれを守る）。`ppc_run_info.json` に評価の状態を入れ、GUI・headless・計画案の記録は、今回の計画の ID と評価の状態を確かめてから金額を読む（今の `ppc_run_info.py` の照合を広げる）。
- **snapshot の `ppc`**：状態が `評価済み` のときは、**今のキーと値を 1 バイトも変えない**（golden）。`一部未評価`・`未評価` のときだけ、`valuation_status`・`reason` などのキーを足す。`未評価` のときは金額のキーを入れない。
- S4 の見本の販売データの生成を `run_ppc_from_psi()` から外す（K4）。`wom/ppc/__main__.py` の実演はそのまま。

### B.3 読む側

- `attach_realized()`（金額の経路）：PPC が `未評価` なら、`realized.ppc` を `{"valuation_status": "未評価", ...}` にし、`gap_decomposition` などの金額の比較を作らない。0 として計算しない。`一部未評価` のときも、**計画の利益との差・比率の比較を作らず**、保留したことと理由を `realized` に残す。
- Value Chain：PPC が `未評価` でも、Value Chain は自分の価格・原価の設定で評価できる範囲を計算し、出力を保存する。`compare_with_ppc()`（PPC の台帳と金額のキーが有ることを前提にしている）は、PPC が評価済みでなければ実行せず、比較の結果を「比較不可（理由）」と記録して最後まで終える。
- GUI：PPC の状態の表示（今の「サンプルの販売データ」の警告の所）を、`未評価`（理由）・`一部未評価`（除いた製品・市場）に置き換える。見本で計算した、という表示は無くなる。
- headless の CLI の 1 行の表示（`GM=… trust=…`）：`未評価` なら「財務：未評価（理由）」と出す。
- §A4 で見つけたほかの読む所も、値が無いときに 0 として扱わないようにする。

### B.4 既存のサンプルに宣言を足す（K5）

§A2 の表で共有の規則を使っていたモデルの `planning_config.csv` に `ppc_shared_rules_dir,data/ppc` を足す（rice、Cookie、smartphone の見込み）。**金額の値が変わらないこと**を golden で確かめる。`planning_config.csv` の知らないキーで止まる読み込みが無いかも確かめる。
