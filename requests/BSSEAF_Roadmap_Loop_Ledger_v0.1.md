## 0. 一言で

**開発のテーマから、業務の問い、要件、Loop の記録までを、一つの表でたどれるようにする。要件ごとに「決めた意味の当てはめ」か「新しい意味を含む」かを書き、前者は自動の Loop へ、後者は大杉さんへ戻す。**

## 1. なぜ要るか

- **入口が決まっていないと、自動化は「頼まれたことを速くやる」だけになる。** 今の Loop の入口は、その日の大杉さんの問題意識である（G1〜G5 も、化粧品の金額の試行で見つかった穴から始まった）。下流の受け渡しだけを自動にすると、「次に何をやるか」を決める所が詰まる。
- **新しい意味は、テーマを要件に分ける時点で生まれる。** 分けるのは段階 1・2（業務の目的と意味）の仕事で、GPT-MC君が案を書けても、決めるのは大杉さんである。自動ループの「人へ戻す条件」（自動ループの設計案 §3・§4）を、Loop に入る前の入口に置くのがこの台帳の役割。
- **今は未決の事項が二か所に分かれている**（Start Here §7、進め方の知識 §7）。どれがどのテーマのどの段階か、一目では分からない。

## 2. 台帳の形

### 2.1 三つの層

| 層 | 中身 | 書き方 | 先まで分けるか |
|---|---|---|---|
| テーマ | 経営の問い・開発の目標（例：「化粧品の事業で、法人ごとの損益を正しく出せるか」） | 問いの形で書く。作業の一覧にしない | 分けない。テーマは試行の結果で書き換わる |
| 業務の問い | テーマを答えるために要る問い（例：「代理店向けの販促費は、誰が、いつ負担するか」） | 一文の問い | **1〜2 歩先まで** |
| 要件 | Loop で扱う単位。ID を付ける（例：`COS-VC-G2`） | 下の §2.2 の欄 | 着手するものだけ |

WOM はこれまで、試行で見つかったことが方向を変えてきた。先まで細かく分けると、すぐ古くなる。**逆に、Loop の結果がテーマや問いを書き換える上りの矢印**（§2.2 の「上り」の欄）も持つ。

### 2.2 要件の欄

| 欄 | 中身 |
|---|---|
| 要件 ID | `<事例>-<領域>-<番号>`（例：`COS-VC-G2`） |
| 業務の問い | 一文 |
| 区分 | **既決の当てはめ**（使う意味と適用条件がすべて決まっている）／**新しい意味を含む**（どれかが未決）。§3 で判定する |
| 使う知識 | 知識の ID・版・適用条件（自動ループの設計案 §2 の `knowledge_used` と同じ書き方） |
| 新しい意味（人が決めること） | 区分が「新しい意味を含む」のとき、何が未決か。決まったら、一言の決定と日付 |
| 状態 | 自動ループの設計案 §3 の状態（調査中・提案作成中・試行可能・試行中・検証中・修正待ち・Owner 判断待ち・完了） |
| Loop の記録 | Loop の番号、依頼書・報告書のパス |
| 次の担当 | design／implement／verify／owner、または GPT-MC |
| 上り | この要件の結果が、テーマや他の問いに返したこと（新しい問い、取り下げ、前提の書き換え） |

## 3. 区分の判定（どこまで機械で判定できるか）

| 判定 | 方法 |
|---|---|
| 使う知識が見つかるか | 索引（Start Here、意味体系）から辿る。見つからなければ「新しい意味を含む」（進め方の知識 §3.2 の「知識が見つからないときの扱い」） |
| 適用条件が合うか | 知識の適用条件を、照らせる項目として書いておく（例：取引の種類〔直販・外部卸売・法人間〕、チャネルの種類〔own・online・external〕、売り手と買い手の法人の関係、区間の種類、SKU）。要件の条件がすべて一致すれば「既決の当てはめ」。**一つでも外れれば「新しい意味を含む」** |
| 変更を許す範囲に収まるか | 変更するパスで判定する（自動ループの設計案 §8.5 と同じ）。保護対象のコア・golden・意味体系に触れるなら、区分によらず人へ戻す |

**自動化の本当の課題はクリック操作ではなく、この適用条件を照らせる形で書き出すことにある。** 今の意味体系・設計 MD の適用条件の多くは文章で書かれていて、機械では照らせない。台帳を回しながら、よく使う知識から順に項目にしていく。

例：G1 で決めた「売上比率の費用は、その売上の週に、売り手の販売費として費目ごとに 1 行」を、別の直販のチャネルに当てはめる要件は、取引の種類（直販）・チャネルの種類（own・online）・売り手がグループの法人、の三つが一致すれば「既決の当てはめ」。外部の代理店への卸売（G2）は取引の種類が違うので「新しい意味を含む」になり、実際に「いつ負担が確定するか」を大杉さんが決めた。

|---|---|---|---|---|---|---|---|
| `COS-VC-G3` | 代理店への卸売の売上は、どの週に立つか | 新しい意味を含む | **出荷の時点で認識する（D-2）**〔大杉さん 2026-11-08〕 | 完了 | Loop No.005：`docs/design/drafts/WOM_G3_SellIn_Business_Definition_v0.1.md`、`docs/development/WOM_BSSEAF_Cosmetics_G3_SellIn_Verify_Report.md` | — | 業務定義を検証の条件にする作法（進め方の知識 §3.2）。G2 の算定の基準になった |

**このテーマで見えたこと**：G1〜G5 はどれも「新しい意味を含む」で、自動の Loop にそのまま流せるものは無い。ただし、意味が決まった後の対応表・検証・実装（G3 は検証だけ、G1 は改修あり）は、どれも同じ形で回った。**意味を決める所が人、その後が自動の候補**という線引きは、この 3 件の実績と合っている。

## 6. 置き場所と運用（大杉さんに決めてほしいこと）

| 一言で | 中身 | 推奨 |
|---|---|---|
