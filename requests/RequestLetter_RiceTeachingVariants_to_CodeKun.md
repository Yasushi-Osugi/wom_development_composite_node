## 0. 目的

Rice のサンプル（`data/sample/rice-japan-2027-2028`）で、「不足の原因は収穫か、精米か」を、**前提を一つずつ変えた比較**で示したい。授業の試行で使うので、結果は事前に出して、1 枚ずつの説明にまとめる。

**置き場所**：`docs/business/lesson000/`（git の対象外）。公開のリポジトリには入れない。

## 1. 作る変種（コシヒカリの値だけを変える。ゆめぴりかは変えない）

すべて `data/sample/rice-japan-2027-2028` を丸ごと写してから直す。上位の層とエンジンの両方の上限を**揃えて**変える（片方だけ変えると効かない。実装報告 §5.2）。

### V1 `rice_harvest_plus30`：新潟の収穫 +30%

| ファイル | 変える行 | 前 → 後 |
|---|---|---|
| `rice_resource_capacity.csv` | `FIELD_NIIGATA` の収穫週（各年 W41〜W43） | 15,500 → 20,150 |
| `rice_crop_limit.csv` | `FIELD_NIIGATA` の 2026・2027・2028 | 46,500 → 60,450 |
| `capacity_plan.csv` | `Koshihikari,Tanbo_Niigata` の収穫週（15,500 の行） | 15,500 → 20,150 |

46,500 × 1.3 ＝ 60,450 は、設定後の年の要求 61,215 にまだ届かない。**不足がゼロになることを前提にしない。**

### V2 `rice_mill_plus30`：精米センター +30%（二品目で共用）

| 同 | `MILL_W` の default_capacity | 1,000 → 1,300 |
| `capacity_plan.csv` | `Seihaku_E` の全行（両品目） | 1,300 → 1,690 |
| 同 | `Seihaku_W` の全行（両品目） | 1,000 → 1,300 |

`rice_resource_capacity.csv` に精米の行があれば、それも揃える。

## 2. 実行と確かめること

基準（`data/sample/rice-japan-2027-2028`）と V1〜V3 の 4 つを、headless で `--plugins` を省いて実行する（推奨のプラグインの組）。

```
python -m tools.rice_seasonal_check --model-dir <フォルダ> --out docs/business/lesson000/results/<名前>
```

**確かめること**（照合で誤りが出たら止めて報告）：
- flow identity の誤り 0、資源・年産上限の超過 0、早出し 0
- 基準の結果が今までと同じ（コシヒカリの報告期間：当週 93,874・注文残 28,556）

**全テスト・LOVEM の照合・GUI の確認は不要**（コードを変えないため。利用の上限への配慮）。
