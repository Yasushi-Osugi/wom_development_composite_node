# Request Letter — 公開の前のサンプルの見直し：実在の名前を一般名にする

- 宛先：Claude Code君
- 依頼者：大杉（WOM Project Owner）／起草：Claude君、2026-10-09
- 基準：`wom-v1r5m1_cap_trial`、**de8e18d**（feat(plugins): recommended plugin set per model …）
- 種別：データ・golden・文書・道具・テスト。**保護対象のコアは変えない。計算の値（需要・能力・価格・LT）は変えない。**

## 0. 目的と背景

このリポジトリ（default branch）は、Owner の note の記事から既に公開されている。
守秘の方針は「固有の企業名とクリティカルな数字は出さない」。ところがサンプルと文書に、実在の企業・団体・ブランドの名前が残っている。
Claude 君の予備の検索では、EMS・半導体・電機・自動車・電池・アパレル・菓子・コンビニ・農業団体の実名がある。中でもスマートフォンの 2 つのモデルは、製品名・会社名・工場名が実名で、能力・原価・移転価格（すべて仮の値）が実在の企業のものに見える形で公開されている。

**この依頼書にも実名を書かない**（依頼書もリポジトリに入るため）。予備の検索の語と、名前に実名を含むモデル・ファイルの一覧は、git の対象外の **`output/sample_names/preliminary_terms.txt`** に置いた。以下ではそこを「予備の一覧」と呼ぶ。

**目的**：最新の版（HEAD）から実名を無くし、一般名にそろえる。計算の結果（数値）は変えない。再発を防ぐテストを入れる。
git の履歴の書き換えはしない（判断は Owner。今回の範囲外）。

## 1. 守ること（重要）

1. **元の名前と新しい名前の対応表を、リポジトリに入れない。** 公開の場所に「A＝実名」の表を置くと、見直しの意味が無くなる。対応表は git の対象外の `output/sample_names/mapping.csv` にだけ書き、Owner が手元で確かめる。報告書にも元の名前を書かない（件数と、置き換えた後の名前だけ）。
2. **計算の値を変えない。** 名前を変えるだけで、需要・能力・価格・LT・ID の数は同じであること。
3. **名前を推測でつけない。** 一般名は役割が分かる名前にする（例：`EMS_A`、`Foundry_A`、`Retailer_A`、`産地の集荷団体`、`コンビニ`）。同じ実名には全ファイルで同じ一般名を使う。

## 2. 作業

### 2.1 棚卸し

1. git が追跡しているすべてのテキストのファイル（コード・`data/`・`tests/`・`docs/`・`requests/`・README・`index.html` など）で、実在の企業・団体・ブランド・製品の名前を探す。地図のデータ（`data/worldmap_ne/` の Natural Earth の国・都市の名前）と画像は対象外。
2. 予備の一覧の語を探す（大文字・小文字を問わない）。**これだけで終わらせず**、ノード名・説明・note 列・コメント・ファイル名・関数名も見て、ほかの実名を探す。
3. 結果を `output/sample_names/inventory.csv`（git の対象外）に、ファイル・行・実名・提案する一般名で書く。

### 2.2 置き換え

1. 2.1 で見つけた実名を、一般名に置き換える（データ・コード・テスト・文書・依頼書。過去の報告書も、名前だけを置き換える。中身の文は変えない）。
2. **ファイル名・フォルダ名**に実名があるものは名前を変える（予備の一覧の file の行など）。参照しているところも直す。
3. **スマートフォンのモデル（golden のある方）**：フォルダ名と製品名を一般名にする（例：フォルダ `smartphone-global-2026-2029`、製品 `Phone15`。Owner が別の名前を望めば従う）。golden も新しい名前で作り直す。**作り直す前後で、名前以外の値（psi の集計・ppc・forward・period）がすべて同じであること**を、対応表で名前を置き換えて比べる。
4. **スマートフォンのモデルの古い方（golden 無し、PPC が CNY の為替で止まる）は削除する。** 参照しているところ（道具・テスト・文書）を直すか、過去の記録なら「削除済み」と注記する。
5. CLAUDE.md・AGENTS.md・各 README・`docs/README.md`・`docs/WOM_Start_Here.md` のモデルの名前も直す。**`docs/WOM_Start_Here.md` は名前の置き換えだけにする**（ほかの書き換えは Claude 君がする）。

### 2.3 golden の無いモデル

`ev-thailand-2026_update`・`soysauce-jpy-2027-alloc` の golden を作る（identity、`recommended_plugins` の組、`--plugins` を明示）。`soysauce-jpy-2027-alloc` は Value Chain の手本なので特に守りたい。作れない、または作る価値が無いと思うモデルがあれば、理由を書いて報告する（削除の判断は Owner）。

### 2.4 再発を防ぐテスト

1. `tests/test_no_real_names.py` を足す。追跡しているテキストのファイルに、禁止の語が無いことを確かめる（地図のデータ・画像・このテストの語の一覧のファイル自身は除く）。
2. 語の一覧は二つ：
   - **公開の一覧** `tests/data/real_name_denylist.txt`：2.1 で見つけた有名なブランド・企業の名前（世間に広く知られた名前だけ）。
   - **手元だけの一覧** `private/real_name_denylist.txt`（`.gitignore` に `/private/` を足す）：Owner がコンサルの顧客などの名前を書く。**ファイルがあれば読み、無ければ黙って飛ばす。** この一覧の語は、テストが失敗したときのメッセージにも出さない（「手元の一覧の 3 番目の語」のように番号で示す）。
3. 一般名にした後のサンプル（`EMS_A` など）が、誤って禁止にならないこと。
4. 依頼書・報告書・CLAUDE.md などの文書も検査の対象に含める（この依頼書も含めて、実名が無いこと）。
