## 1. 何を表すか（世代の切り替えの経営課題）

- SmartX の需要は 2026-W01〜**2030-W26**、SmartXNext の需要は **2028-W27**〜2030-W52 で、**約 2 年重なる**。1 本のラインで混流しないので、この期間に両方を同時には作れない。
- そのため、次の 3 つが避けられない：
  1. **切り替えの時期**（SmartX の生産をいつ止め、SmartXNext をいつ始めるか）
  2. **旧世代の最終の作りだめ**（切り替えの後にも残る SmartX の需要を、前もって作って在庫で持つ。2028-W27 以降の SmartX の需要は 22,798 lot）
  3. **新世代の立ち上げの遅れ**（空き期間の 4 週は、どちらも作れない）
- 本件は、この選択を WOM の数字で見えるようにする。

## 2. ラインの能力（決定 ②）

- 世代ごとのラインの週の能力 ＝ その世代のピークの週の需要（全市場の合計）× **1.1**（係数は設定）。今の需要での目安：

| 世代 | ピークの週の需要 | × 1.1 |
|---|---:|---:|
| SmartX（`AssemblyCN_g1`） | 1,307（2026-W01） | 1,438 |
| SmartXNext（`AssemblyCN_g3`） | 3,375（2030-W27） | 3,713 |

- 世代ごとに能力が違ってよい（新世代向けに設備を入れ替える前提）。値と計算のしかたを報告書に載せ、大杉さんが確かめる。
- SmartXPro_CN（`AssemblyCN`、別のライン）は、今の CSV の能力のまま（前の依頼書で 0 の意味が揃った後の値）。

## 3. データでの表し方

切り替えの週を `s`、空き期間を `g`（4 週）とすると：

| 週 | `AssemblyCN_g1`（SmartX） | `AssemblyCN_g3`（SmartXNext） |
|---|---|---|
| `s` より前 | SmartX のライン能力 | **0** |
| `s` 〜 `s+g-1`（空き期間） | **0** | **0** |
| `s+g` 以降 | **0** | SmartXNext のライン能力 |

- 前の依頼書で「0 ＝ 能力ゼロ」になるので、エンジンを変えずに「混流しない」ことを表せる。
- この能力の行を、`(s, g, 世代ごとの能力)` から作る道具を用意する（例：`tools/gen_generation_line_capacity.py`）。

## 4. 上位の層（`wom/capacity_layer/`）

Astra君の試作（汎用の解き方と smartx の変換）を土台に、テスト付きの本実装にする。

### 4.1 切り替えの週を選ぶ

- 候補の `s` を並べ（範囲は SmartXNext の需要の始まりの前後。例：2027-W27〜2030-W27。刻みは計算時間を見て決め、報告する）、**候補ごとに**線形計画を解く。
- 各候補の目的（決定 d）：①元の市場の要求週までに割り当てられる lot 数の最大化 → ②同じ最大量のなかで前倒しの lot・週の最小化（Astra君の試作と同じ 2 段）。
- 候補ごとに出すもの：要求週に間に合う lot 数、割り当てられない lot 数（世代別）、SmartX の作りだめの在庫の lot・週、SmartXNext の立ち上げの不足。
- **切り替えの週と結果の関係の図**（横軸 `s`、縦軸に未割当と在庫）を作る。最良の `s*` は「未割当が最小、同じなら在庫の lot・週が最小」で選ぶ。2 つの基準が離れる場合（未割当をわずかに減らすために在庫が大きく増えるなど）は、その様子を図と表で示す（どちらを取るかは大杉さんの判断）。
- 離散の選択（切り替えの週）を並べて、それぞれを線形計画で解く。Phase 6-1 で関税の崖の on/off を並べたのと同じ考え方で、どの週を選ぶと何が起きるかを説明できる形にする。

### 4.2 エンジンへの渡し方

- **市場の要求（週と Lot_ID）は変えない**。上位の層の結果は、内部の計画の位置（Backward の後の配置）としてだけ渡す（Astra君の試作の「元 ID を保つ方式」）。需要の CSV を書き換える方式は使わない（元の顧客の要求から見て早出しになるため）。
- 渡し方は、既定では OFF のプラグイン（例：Capacity Layer）として GUI と headless の両方で選べるようにする。OFF のときの計画は今と同じ。
- 前倒しの窓（試作では最大 17 週）は設定にし、`s*` の作りだめが窓に収まるかを報告する（収まらない場合は窓を広げた結果も出す）。

### 4.3 Pro_CN と Pro_IN

- SmartXPro_CN（別のライン）と SmartXPro_IN も、同じ上位の層で扱う（今の遅配 16,073 件は SmartXPro_IN の SensorIN・AssemblyIN の繰り延べ）。

## 5. サンプルの変更と golden

- `data/sample/smartx-2027-2029/capacity_plan.csv` の `AssemblyCN_g1`・`AssemblyCN_g3` を、§3 の形で `s*` を使って書き直す。`s*`・`g`・能力の値と決め方を `data/sample/smartx-2027-2029/README.md`（無ければ作る）に書く。
- smartx の golden は、**上位の層を OFF にした計画**（データだけが変わった状態）で再生成する。上位の層を ON にした結果は、報告書と別の出力で示す（golden にはしない）。
- smartx 以外の golden は変わらない。

## 6. 受入条件

1. **能力の値**：世代ごとのピークの週の需要と能力の表（§2）。
2. **混流しない**：どの週も、`AssemblyCN_g1` と `AssemblyCN_g3` の P が同時に正にならない。空き期間の 4 週はどちらも 0。
3. **切り替えの週の比較**：候補ごとの表と図、`s*` とその理由。
4. **`s*` での比較**（上位の層 OFF／ON）：元の市場の要求週に出荷した lot 数、遅配、早出し（0 であること）、期末の注文残、割り当てられない lot、能力による繰り延べ、在庫の lot・週、PPC の売上・粗利。世代別・製品別。
5. **元の要求を保つ**：上位の層 ON でも、市場の要求の Lot_ID と要求週が OFF と同じ。出荷の記録を LOVEM の観測と 1 対 1 で照合する。
6. **golden**：変わるのは smartx だけ。
7. **テスト**：解き方の単体テスト（Astra君の手計算のテストを含む）、能力の行を作る道具のテスト、プラグインの結合テスト。全テスト緑。
