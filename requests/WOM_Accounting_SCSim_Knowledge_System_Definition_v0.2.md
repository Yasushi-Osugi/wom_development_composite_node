# 会計とサプライチェーン・シミュレーションをつなぐ WOM の知識体系と初心者向けガイド

## 0. 一言で

**経営の打ち手（価格・投入・増産・配分など）が、週ごとのロットの動き（WOM 数量編）を通って、売上・原価・費用・利益（WOM 金額編）にどう出るか。それが財務会計（法人別の損益・連結）と管理会計（製品 × 市場の採算・意思決定の差額）でそれぞれどう見えるか。** この一本の筋を、経営者と経営学を学ぶ学生が腹落ちする言葉で説明できる知識体系と初心者向けガイドを作り、WOM が「カスタマイズ・フリーなサプライチェーン・シミュレータ」であること（§1.1）と合わせて、広く知らせる。

## 1. 目的：誰が、何に腹落ちするか

| 読み手 | 腹落ちしてほしいこと |
|---|---|
| 経営者 | 「この打ち手で、どの市場に何週に何ロット届き／届かず、利益がいくら動くか。それは決算（法人別・連結）ではこう見え、事業の採算ではこう見える。未確認の前提はこれ」と、自分の言葉で説明できる |
| 経営学を学ぶ学生 | 教科書の会計（財務会計・管理会計）と SCM が、1 ロットの動きでつながることを、手を動かして確かめられる |
| コンサルタント・実務家（第二の読み手） | 自社・顧客の構造を CSV で組み、同じ筋で検証できる。業務の定義と照合の手順を再利用できる |

### 1.1 「カスタマイズ・フリー」の意味（大杉さんの定義、GPT君・GPT-MC君が支持）

> WOM における「カスタマイズ・フリー」とは、利用者が経営課題や業務の意味を人と AI の対話で定義し、AI が必要なデータ・パラメータ・コードの変更と検証を担うことで、利用者自身に個別開発の専門作業を求めず、業務へ適応できることをいう。

- コードの改修が要る場合も含む（Code君が短い時間で改修・検証する）。BS-SEAF の三つの変更の手段（データ・パラメータ・中核の構造）と整合する。
- 裏付けとして、要求から検証済みの変更までの時間、利用者に要った作業、既存の機能を保てたかを記録していく（今の開発の記録がその実例）。
- 将来は、この適応の能力を WOM 自身に内蔵する方向（知識移転装置の構想）。

## 2. 課題の定義：今、何が足りないか

| # | 課題 | 今の状態 |
|---|---|---|
| P1 | **会計の言葉と SCM の言葉が分かれている** | 財務会計は「法人・期間・取引」、SCM は「品目・週・ロット」で考える。WOM はその橋（ロット → 取引 → 法人別の損益 → 連結の消去）を持つが、橋の説明がない |
| P2 | **WOM の機能と会計の概念の対応表がない** | 二つの軸がある：PPC と Value Chain は WOM の**計算・集計の方式**の違い、財務会計と管理会計は**誰に何のために見せるか**の違い。両者は固定的に対応しない（例：Value Chain の連結の試算利益は、投入週や増産を決める管理会計にも使う）。案の外の費用（確保費・維持費・保有費）は意思決定のための調整。この関係がどこにも一枚で書かれていない |
| P3 | **6 つのテーマが別々に作られ、別々に確かめられた** | 価格・E2E のコスト構造・Value Chain・関税・移転価格・連結は、化粧品の G1〜G5、金額基盤の棚卸し、PPC と Value Chain の照合などで個別に定義・検証済み。知識は設計書・報告書・業務定義に散らばっている |
| P4 | **初心者向けの語り口がない** | 今ある文書は開発者・設計者向け（依頼書・報告書・業務定義）。経営者操作ガイド（docx）は操作の説明で、会計との関係は扱っていない |
| P5 | **「カスタマイズ・フリー」を示す見せ方がない** | 16 の正式なモデル（化粧品・醤油・米・石油・スマートフォンなど）がコードを変えずに CSV だけで動く事実はあるが、読み手に伝わる形になっていない |
| P6 | **できないことの線引きが外に見えない** | 例：貸借対照表・資金繰りは未整備（比較値 A は Net Cash ではない）、週固定費は案の外、関税・移転価格は架空のサンプルの規則で税務の助言ではない。知識体系の信頼は、この線引きの明示にかかる |

## 3. 知識体系の骨格（提案）

### 3.1 三つの層と、層をつなぐ原則

| 層 | 中身 | 会計との関係 |
|---|---|---|
| A 経営の問い（コックピット） | 何を決めるか。案を作り、比べ、差の理由をたどる | 意思決定会計（差額の比較、境目、感度） |
| B WOM 数量編 | 二つの木（需要と供給）、需要の単位としてのロット、PSI、能力・配分・押し戻し、需要の三つの名前（①〜⑤） | 売上・原価が「いつ、何個」生じるかの源 |
| C WOM 金額編 | 価格・原価・費用の置き場所（ノード・区間）、PPC、Value Chain（法人・取引条件・移転価格・関税・連結の消去）、案の外の費用 | 財務会計（法人別・連結）と管理会計（製品 × 市場、差額）の両方の数字 |

層をつなぐ原則（例。体系の中で根拠つきで整理する）：

- **売上と原価**：採用した支配の移転の条件に従って、対象の取引の外部売上と、それに対応する売上原価を計上する。出荷・受入・下流での販売を、同じ取引の売上として重ねて計上しない（化粧品は G3 で出荷時に支配が移る条件を採用。IFRS 15 の考え方）。在庫として持つ間の原価と、販売に対応して費用になる売上原価は、計上する期間が違う（IAS 2 の考え方）。
- **移転価格と連結**：外部の売上・外部の費用などが同じで、内部取引と未実現利益を正しく消去するなら、内部の価格の付け替えだけでは連結の利益は増えない。関税などの外部の負担が変わる影響は、別に評価する（G4 の課税価格とつながる）。
- **同じロットに立つ別の取引**：法人間の売上と外部への卸売は、同じロットの上の正当な別取引。同一の取引の重複は、売り手・買い手・区間・Lot_ID の組で照合して防ぐ（G3）。
- 管理会計の採算（PPC）と財務会計の連結（Value Chain）は、同じ規則なら一致し、違うなら違いの出どころ（規則・区間・週・法人）を示せる。
- 未設定の金額は 0 にしない（未評価として出す）。費用は二重に数えない。
- 案の比較は、同じ版・同じ条件の対照と比べる。
- **「利益が増えた」には、何を含む数字かを添える**（GPT-MC君）：会計上の損益（例 `P0`：報告期間の連結の試算利益）と、経営判断のための調整後の比較値（例 `A`：確保費・維持費・在庫の保有費などを引いた値）を分ける。在庫の資本の拘束に置いた保有費は機会費用で、財務会計の費用と同じものではない。利益と現金（入金・支払の週）も違う。

### 3.1a 四つの視点（同じロットに、別の答えが要る）

| 視点 | 確かめたいこと |
|---|---|
| 物流・供給 | どこにあり、いつ出荷・受入されたか |
| 法人別の採算 | 誰が販売し、誰が費用を負担したか |
| 連結の採算 | 内部取引を消去した後、グループに何が残るか |
| 経営判断 | 発売の前倒しや増産で、何がどれだけ変わるか |

### 3.2 テーマごとの章の型（6 テーマ共通）

| 節 | 中身 |
|---|---|
| 1. 経営の問い | このテーマで経営者が決めたいこと |
| 2. 財務会計では | 法人別の損益・連結で、どう見えるか |
| 3. 管理会計では | 製品 × 市場の採算・意思決定の差額で、どう見えるか |
| 4. WOM 数量編では | どのロット・週・能力が関わるか |
| 5. WOM 金額編では | どのファイル・列・規則で表すか（PPC・Value Chain・案の外の費用） |
| 6. 例題 | 化粧品などの既存の試行から（架空のモデル）。代表の 1 ロットを手計算でたどる。**外部に売れる前の期末在庫の期間も含める**（§3.4） |
| 7. 落とし穴と、できないこと | 実際に起きた誤り、未整備の範囲 |

### 3.3 6 つのテーマと、使える既存の材料

| テーマ | 既存の材料（例） |
|---|---|
| 価格 | 市場価格と通貨（`ppc_market_price.csv`・`vc_price_rule.csv`）、4P の翻訳表。価格の変更と弾力性は業務定義が未着手 |
| E2E のコスト構造 | ノード・区間の費用、売上に比例する費用（G1）、販促協力金（G2）、運賃の置き場所（R8）、smartx の原価の直し、増産の確保費・保有費の業務定義 |
| Value Chain との関係 | 法人の割り当て・取引条件・連結の消去、PPC と Value Chain の照合（税率 0% で差 0） |
| 関税シミュレーション | 課税価格の定義（G4）、国境の区間、税率 30% の感度で残った差 |
| 移転価格税制 | `ppc_transfer_price_rule.csv`、法人別の利益が動き連結は不変という性質、CIF の運賃の負担（G5） |
| 連結会計 | 内部取引と未実現利益の消去、グループ在庫、報告通貨と為替 |

### 3.4 最初の 1 ロットの説明の土台（GPT-MC君の説明用の例）

グループの製造原価 100 円、法人間の価格 150 円、外部への販売価格 200 円（税・関税・為替・その他の費用は除く）。

| 段階 | 法人別の見え方 | 連結の見え方 |
|---|---|---|
| 第 1 週：グループ内で販売し、買い手が在庫として持つ | 売り手に粗利益 50 円 | 内部利益 50 円を消去。在庫 100 円、粗利益 0 円 |
| 第 2 週：外部の顧客へ販売 | 買い手に粗利益 50 円 | 外部売上 200 円 − 原価 100 円 ＝ 粗利益 100 円 |

この例に、法人間の価格の変更、関税などの外部の費用、販売の時期の変更を一つずつ加えると、6 つのテーマを同じ事例で説明できる。本文の例題は、化粧品の代表ロットの実際の出力と照合する。

### 3.5 知識の項目に残すもの

各項目に、**定義・適用の条件・WOM との対応・期待結果・検証の根拠・採否と確認の状態**を残す。用語の対応表は「会計の概念／WOM での表し方／確認済みの範囲／簡略化・未対応の部分」を列にする。移転価格は「設定した価格の影響を試算すること」と「税制上の妥当性を判定すること」を分ける。初心者向けの説明と、設計・検証で再利用する記録は、同じ知識の正本から作る。

## 4. 成果物と段階

| 段 | 成果物 | 使い道 |
|---|---|---|
| S1 | **体系の目次と用語の対応表**（会計の用語 ↔ WOM の概念・機能・ファイル・列）。正本は Markdown でリポジトリに置く | 以後のすべての章・ガイド・公開物の土台 |
| S2 | **テーマ別の章**（6 章、§3.2 の型）。既存の業務定義と報告から起こし、例題は手計算で照合する | 知識体系の本文 |
| S3 | **初心者向けガイド**（平易な語り口、1 テーマ 1 本、図つき） | 経営者・学生の入口 |
| S4 | **公開**：note の連載、WOM Academy のレッスン、学術の論文、動画の構想（下書きにある） | 広く知らせる |

S1 → S2 は最初の 1 テーマで型を作り、残りは同じ型で増やす。S3・S4 は、章が照合を通ってから起こす（公開の後に数字の誤りが見つかると、信頼を損なうため）。

**知識を別の条件で使えるかの確認（GPT君・GPT-MC君）**：章ができたら、新しい人や AI に、別の条件の問いを渡す。例「出荷時に支配が移る化粧品の事例を、受入時に支配が移る契約に当てはめると、どの定義と期待結果を変える必要があるか」。どの業務の条件が変わったか、どの数量・金額・計上の週が変わるか、何を追加で確かめないと判断できないかを説明できれば、知識を再利用できた証拠になる。結果は定義・適用の条件・索引に戻す（知識移転装置の育成の実例になる）。

**最初の章の進め方**：
1. Claude君が、体系の目次と、会計の概念 ↔ WOM の機能の対応表、代表 1 ロットの説明案を作る。
2. GPT-MC君が、会計上の意味・意思決定のための調整・適用の条件・重複を防ぐ条件を確かめる。
3. 化粧品の代表 1 ロットで、数量・取引・法人別の損益・連結の消去を一続きに整理する（期末在庫の期間を含む）。
4. Code君が既存の出力と照合し、別の条件での知識の利用も確かめる。
5. この一章の型が成り立ってから、残りのテーマと初心者向けガイドへ広げる。

## 6. 気をつけること

- 公開のリポジトリなので、実在の企業・団体・製品の名前を書かない（Start Here の落とし穴 11）。
- 関税・移転価格・連結は、架空のサンプルに採用した規則での説明であり、税務・会計の助言ではないと各章に明記する。
- 「できないこと」（貸借対照表・資金繰り・週固定費の本格的な扱い・価格弾力性の推定など）を、章ごとに隠さず書く。
- WOM はスタンドアロンの Windows で動く（企業の機密を扱うため）。公開物でもこの前提を示す。
