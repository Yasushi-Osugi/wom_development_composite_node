## 2. 道具 1：投入の表から週別需要を作る（`tools/gen_demand_from_entry_plan.py`）

入力 `market_entry_plan.csv`（モデルのフォルダに置く。1 行 ＝ 製品 × 販売先・チャネル）：

| 列 | 意味 |
|---|---|
| `sku_id`, `region` | `demand_forecast.csv` と同じ鍵。重複は止める |
| `launch_week` | 販売開始の週（ISO の週のラベル） |
| `steady_lots_per_week` | 定常の需要（0 以上の整数） |
| `ramp_weeks`, `ramp_ratio` | 立ち上がりの週数と比率。空欄は不可（今の値は 13・0.5 を明示する） |
| `price`, `currency` | 市場の価格の記録。書いてあれば `ppc_market_price.csv` のその鍵の価格・通貨と同じであること（違えば止める）。空欄は「記録なし」 |
| `promotion_note`, `basis_note` | 販促の前提と、数量の根拠（記録だけ） |

引数：`--model-dir`、`--plan-start`・`--plan-end`（需要 CSV に書く最初と最後の週。必須。黙った既定値を作らない）、`--out`（既定はモデルの `demand_forecast.csv`）。

規則：開始前は 0、開始から `ramp_weeks` 週は `steady × ramp_ratio` を四捨五入（0.5 は切り上げ）、その後は `steady`。全週・全鍵の行を書く（今のファイルと同じ並び・同じ書式）。あわせて `demand_generation_log.json`（入力の表の内容と hash、期間、鍵ごとの合計、書いた行数）を同じフォルダに書く。

止める条件（ファイル・行・値と直し方を出す）：列の不足、鍵の重複、鍵が計画の木の市場（`sc_tree_master.csv` の leaf_out の `region`）に無い、週のラベルが不正、`launch_week` が期間の外、数値でない・負、価格の食い違い。

## 3. 道具 2：2 案を並べる（`tools/compare_scenarios.py`）

**出力とモデルの CSV を読むだけ（WOM を import しない）。** 引数：`--base <後期案の実行結果>` `--alt <早期案の実行結果>` `--base-model` `--alt-model` `--out`。各案の実行結果は、同じプラグインの組で回した headless の結果・PPC の出力・`tools.valuechain_run` の出力・`tools.shelf_life_check` の出力・Flow Check の表 2。

出す表（CSV と、まとめの Markdown）：

| 表 | 中身 |
|---|---|
| 需要の差 | 鍵 × 週の需要（lot）の 2 案と差。入力の表の違い（どの鍵のどの列が違うか） |
| 要求週別の供給 | 鍵 × **要求週**ごとに、需要・当週の納品・遅配・期末の未充足。数え方：需要の Lot_ID（`<sku>:<region>:<要求週>:<連番>`）と、市場の leaf の実出荷（`vc_shipments.csv` の `kind=consumer_sale`）を Lot_ID で照合し、要求週へ戻す。**鍵ごとの合計を Flow Check の表 2 と突き合わせ、合わなければ止める** |
| 計上週別の金額 | 週 × SKU の、外部売上・売上原価（グループの基準）・費用・試算利益（消去後）。`vc_money_lines.csv` から集計し、**全 SKU の合計が `vc_v3_weekly.csv` の `profit_r2_hq_wk` と週ごとに一致することを確かめる**。報告期間（`in_report=1`）の合計と、全計画期間の合計を分ける。PPC の合計（`ppc_kpi_summary.json`）も並べる |
| 在庫と年齢 | 週末の在庫（場所 × SKU、lot 数とグループの原価）、期末の在庫、製品の年齢（最大・52 週超の件数） |
| 差の出た週 | 2 案で要求週別の供給か試算利益が違う最初の週と、差が最大の週。そこから代表の lot を 1 つずつ選び、需要 → 出荷の記録 → 金額の明細を並べる |
| 計画の境界 | 最後の 2 週・最初の週の差は分けて表示する（Start Here §4.3 の 12） |
| 固定費の逆転点（仮） | 「クリームの報告期間の試算利益の差 ÷ 追加の費用発生週数」。**分母の定義は GPT-MC君の業務定義を待つ**。今回は分母を引数（`--extra-fixed-cost-weeks`）で渡し、26 週（投入週の差）の場合を「仮」と明記して出す。差が 0 以下なら「早期案は固定費の前でも上回らない」と出す |
