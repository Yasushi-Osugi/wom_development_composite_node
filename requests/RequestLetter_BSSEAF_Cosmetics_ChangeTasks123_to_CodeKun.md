### 2.1 C3：タイの代理店

```
WH_JP_Released（判定済み倉庫）
  ├→ DC_SG …（今のまま）
  └→ DC_TH（dad、タイの DC、lt_wks 2 ＝ 海上）
       └→ TH_Distributor（leaf_out、タイの代理店、lt_wks 1）
```

- 需要（lot／週）：2028-W01 開始。立ち上げ 13 週は Serum 2・Cream 2（定常の 50% を切り上げ）、その後は定常 **Serum 4・Cream 3**。2027 年の週は 0 の行。

## 3. 確かめること

すべての写し（B2s・C1・C2・C3a・C3b）を、これまでと同じ道具で回す。残存期間は `python -m tools.shelf_life_check --model-dir <写し> --max-age-weeks 52`。

| ID | 確かめること |
|---|---|
| V01 | Flow Check の表 1：全ノードの数量の保存 |
| V02 | 直営店の開店週より前の実出荷が 0（C2 は 2027-W27 より前） |
| V03 | 直営店の開店週の直前の店頭在庫（`SG_Store` の I）の lot 数と、すべて需要の Lot_ID 付きか |
| V04 | 先入れ先出しの年齢：最小・最大・分布、52 週超の数（SKU 別・チャネル別）。参考の Lot_ID の滞留も |
| V06 | 工場の週の P の最大を hard と soft に分けて：floor（cap_hard × y）以下か、floor（cap_soft × y）を超えた週の数・`cap_soft_violation`・Backward の `cap_soft_envelope` |
| V07 | チャネル別の当週出荷・遅配・期末注文残（報告期間）。C3 はタイの代理店も |
| V08 | C3：Value Chain の法人・チャネルの区分（タイの代理店が外部の法人・external） |
| 在庫 | ノード別の在庫（I）の合計・最大。店頭（`SG_Store`）、工場の作り置き（supply point）、DC |
| 直販比率 | 数量基準（（`SG_Store`＋`SG_EC`）÷ 全チャネル）。C3 はタイの代理店を分母に入れる |
| warmup | warmup 17 週で足りたか（計画の最初の週に past due・期末注文残が出ないか。足りなければ D7a の 26 週を試し、両方を報告する） |

**見込み（Claude君の手計算。合わなくても写しを直さず、違いとして報告する）**：

- C1：判定 1＋海上 4＋DC→チャネル 1 で、年齢は 2 週ずつ延びる（直営店 8 週、ほかは 6 週）。17 週の warmup で足りる。それ以外の数字は B2s と同じ。
- C2：店頭在庫は 2027-W25 から立ち、開店の直前は 4・4 lot（立ち上げの 2 lot × 2 週）。2027 年の直販比率が下がる。工場のピークは変わらず、前倒しは起きない。
- C3a：工場の平準化の良品の上限（13・10）がピーク（17・13）を毎週 4・3 lot 下回る期間が長く続く。B3 と同じく前倒しが深く遡り、warmup の中でも作り切れないと期末注文残が出る。先入れ先出しの年齢がどこまで延びるか（52 週を超えるか）は、C3a で初めて分かる。
- C3b：能力が足りるので前倒しは起きない。年齢はタイの代理店で 4 週（判定 1＋海上 2＋DC→チャネル 1）、ほかは B2s と同じ。
