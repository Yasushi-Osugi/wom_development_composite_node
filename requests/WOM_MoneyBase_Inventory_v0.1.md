# WOM 金額基盤の棚卸し表 v0.1

- 作成：Claude君（設計担当）、2026-11-13。依頼：大杉さん・GPT君（ロードマップ案 v0.1 §2）
- 基準：`wom-v1r6m0_BS-SEAF`、`1814788`（G5 を正式サンプルに反映した版）
- 調べ方：`data/sample/` の全フォルダの CSV と、`wom/valuechain/`・`wom/ppc/` のコードを読んだ。**コードもデータも変えていない。実行もしていない**（「試行要」は、実行して確かめる必要があるもの）
- 方針（大杉さん・GPT君・Claude君の合意）：**確かめる範囲は全サンプル、直す順は影響で決める**。最初の事業計画比較（化粧品）の結論に効く不足を先に扱う。ただし、誤った金額が警告なしに出る共通の問題は、比較の対象外でも優先度を下げない

## 一言で

**金額が業務と合っていることを確かめたのは、化粧品の 1 モデルだけ。** ほかの 15 モデルは PPC（粗利の試算）は動くが、法人別・連結（Value Chain）で評価できるのは Cookie と soysauce-jpy-2027-alloc の 2 つだけ。7 モデルは運賃がノードの費用に残っていて、そのままでは Value Chain の読み込みで止まる。**先に確かめたいのは smartx の運賃の二重計上の疑い（3 か所）**。固定費・歩留まりの原価・在庫の保有費は、どのモデルにも入っていない。

## 3. 読み取れること

1. **最初の比較（化粧品）に効くのは #7・#9、次に #8。** ほかは化粧品の比較の結論を変えない。
2. **比較の対象外でも先に確かめるのは #1。** 二重計上なら、黙って誤った金額が golden に固定されている。確かめるのは小さな作業（意味の確認と、3 組の合計を出すだけ）。
3. **#2〜#6 は「モデルを Value Chain の題材にするときに寄せる」**という今の方針（Start Here R8・R9）のままでよい。全モデルに一度に入れると、golden の作り直しが大量に出るわりに、今の判断は変わらない。
4. 化粧品で作った表（売上比率の費用、課税価格、取引条件）は任意のファイルなので、ほかのモデルの今の結果を変えない。横展開は、題材にするモデルから順に、同じ手順（業務定義 → 対応 → 照合）で進められる。
