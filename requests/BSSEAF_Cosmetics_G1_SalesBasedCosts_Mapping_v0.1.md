# G1（売上比率の費用）業務定義案 v0.1 と、今の WOM の対応

- 版：v0.1（2026-11-08）
- 作成：Claude君（設計担当）
- 前提：G1 業務定義案 v0.1 の §7 推奨案（売上比率の費用は、値引き反映後・税抜の外部売上の認識週。配送・梱包費は、販社負担が確定した消費者向け発送の週）

---

## 0. 一言で

**配送・梱包費は、データを 1 行足すだけで今の仕組みで計上できる。売上比率の 3 費目（直営店は 2 費目）は、Value Chain の小さな改修が要る。発送が先行する例は、今のデータでは発送と売上を区別できないので、基本例と切り分けて後に回す。**

## 1. 今の WOM で分かったこと（コードと再集計）

| # | 事実 | 確かめ方 |
|---|---|---|
| F1 | 消費者への販売は、leaf の S の週の **1 つの事象**（`consumer_sale`）。売上（`kind=revenue`・`scope=external`、市場価格 × 個数）はこの週に立つ。WOM の中で「発送」と「売上の成立」は同じ事象で、別の記録は無い | コード `_consumer`、`records.py` |
| F2 | 同じ `_consumer` は、区間 `<leaf>->CONSUMER` の費用の行があれば、**売り手（E_SG）のその週の販売費**（`kind=expense`・`scope=selling`、（率 ＋ 固定額）× 個数、相手 `CONSUMER:<leaf>`、明細の `src_id` は販売の出荷 ID）として計上する。**ただし今のサンプルにこの行は無い** | コード `_consumer`、`ppc_edge_cost_rule.csv` |
| F3 | ノードの費用（`ppc_node_cost_rule.csv`）は、**入荷の週**（`_receipt` → `_node_costs`）に計上する。`basis=revenue` の行は、**同じ行の固定額ごと**計上せず、issues に `revenue_based_node_cost_not_supported` を出す。G1 の 281,015,748 円が落ちている理由 | コード `_node_costs`、M0 報告書 G1 |
| F4 | 費用の行は「ノード・SKU・費用の種類」で一意（同じ種類を 2 行書くとエラー）。費用の種類は `policy.py` の表に無いと止まる。今の種類は `sga_cost`・`marketing_cost` の 2 つで、**10％と 5％、35％と 10％を別の行に書けない** | コード `masters.py`、`policy.py` |
| F5 | PPC は直販の費用を `ppc_node_cost_rule.csv` から 1 個当たり（率 × 市場価格 ＋ 固定額）で計算し、`sga_cost`・`marketing_cost` の 2 つの合計に入れる。**PPC は `<leaf>->CONSUMER` の区間を読まない** | コード `ppc_profit_zone.py`、`ppc_tariff.py`・`ppc_backward.py`（区間の費用は DC → チャネルまで） |
| F6 | サンプルの **EC の lot は、754 件すべて入荷と販売が同じ週**（DC の出荷の翌週に入荷し、その週に売る）。**直営店の lot は 962 件すべて、入荷の 2 週後に販売** | 再集計（G3 検証の実行の出力） |
| F7 | EC のクリームの代表の候補：`COS_Cream:SG_EC:2028-W28:00001`。DC の出荷 2028-W27、入荷・販売 2028-W28、売上 3,144 SGD（24 × 131）。直営店：`COS_Cream:SG_Store:2028-W30:00001`。入荷 2028-W28、販売 2028-W30、売上 3,312 SGD（24 × 138） | 再集計 |

## 2. 対応表

### 2.1 同週の基本例（業務定義 §4）

| 業務条件 | 現行の入力 | 根拠事象 | 現行の出力 | 満たせる範囲と差分 | 確認方法 |
|---|---|---|---|---|---|
| EC 拠点への入荷だけでは G1 は 0 件 | `ppc_node_cost_rule.csv`（SG_EC の行は売上比率だけ） | 入荷（`_receipt`、到着の週） | 入荷の週に費用の行なし | **満たす**。ただし F6 のとおり EC は入荷と販売が同じ週なので、「入荷の週は 0」を EC で単独に示せない。**直営店の lot（入荷の 2 週後に販売）で示す** | 直営店の代表の lot で、入荷の週（2028-W28）に G1 の行が 0 |
| 売上比率の基準 ＝ 値引き反映後・税抜の外部売上 | `ppc_market_price.csv`（EC クリーム 131 SGD） | 消費者への販売（`_consumer`） | `revenue`・`external` の行（3,144 SGD） | **基準の金額はある** | 代表の lot の売上の行 |
| 販社販管費 10％・決済・EC 基盤手数料 5％・デジタル広告費 15％を、売上の週に費目別に 1 件ずつ | `sga_cost` 15％ ＋ 3 SGD の 1 行、`marketing_cost` 15％ の 1 行 | 計上されない（F3） | 行なし。issues だけ | **差分（改修が要る）**：(1) 費目に分けて書く場所が無い（F4）。(2) 売上の週に、売上の金額 × 率で計上する処理が無い | 改修後：費目ごとに 1 行、`src_id` ＝ 販売の出荷 ID |
| 配送・梱包費 3 SGD/個を、消費者向け発送の週に 1 件 | なし（3 SGD は売上比率の行の固定額に混ざっている） | 消費者への販売（＝発送） | 行なし | **設定で満たせる**：`ppc_edge_cost_rule.csv` に `SG_EC->CONSUMER` の行（`qty`・3 SGD）を足せば、F2 の経路で E_SG の販売費として 72 SGD が発送の週に 1 件立つ。**コードの変更は要らない**。名前が `logistics_cost`（運賃）になる点だけ誤読しやすい（§3 の改修で名前を足す） | 写しで実行し、代表の lot に 72 SGD の行が 1 件 |
| 4 件・計 1,015.20 SGD | — | — | — | 配送分は設定で、比率分 943.20 は改修で | 代表の lot の G1 の行が 4 件、合計 1,015.20 SGD |

### 2.2 発送が先行する例（業務定義 §4.1）

| 業務条件 | 今の WOM | 満たせる範囲と差分 |
|---|---|---|
| W28 に発送と販社負担の確定、W29 に売上の成立 | F1：発送と売上は同じ事象。販社負担の確定の記録も無い | **今のデータでは識別できない**。基本例と切り分ける |
| 売上が成立しない、配送が無いと確定、記録不足で保留 | 計画から作る販売には起きない | **対象外**（G3 の「未確認の保留」と同じく、実績の取り込みの論点） |

識別に追加で要る記録（後に回すときの仕様の種）：lot ごとの (1) 消費者向け発送の週、(2) 販社負担の確定（有無と週）、(3) 外部売上の成立の週と金額。どれも実績の記録（EC の受注・出荷・決済）から来るもので、計画からは作らない。

### 2.3 明細の照合（業務定義 §5）

| 業務条件 | 確認する出力 | 確かめ方 |
|---|---|---|
| 費目ごとに一度だけ | `vc_money_lines.csv.gz` の `kind=expense`・`scope=selling`、`entity=E_SG`、`node`＝SG_EC か SG_Store、`counterparty=CONSUMER:<leaf>` | 販売の出荷 ID（`src_id`）× 費目（`price_type`）で数えて、すべて 1 行 |
| 根拠事象ごとに対象の費目を 1 件 | 同上。EC は 4 費目、直営店は 2 費目 | 販売 1 件ごとの費目の数：EC 4、直営店 2 |

| 直営店：店舗運営費 35％（M5 の近似）と販社販管費 10％を区別 | 費目の名前で 2 行 | 代表の直営店の lot：1,159.20 ＋ 331.20 ＝ 1,490.40 SGD（2028-W30）。入荷の 2028-W28 は 0 |

## 3. 最小の改修（差分だけ）

| # | 変更 | 中身 |
|---|---|---|
| C1 | **Value Chain 用の費目の表を新しく置く** | 例 `vc_sales_cost_rule.csv`：ノード・SKU・費目（`hq_sga_allocation`・`payment_platform_fee`・`digital_ad`・`store_operating`）・PPC での種類（`sga_cost`／`marketing_cost`）・率・通貨。**PPC のファイルは変えない**（PPC の 2 つの合計は今のまま） |
| C2 | **売上の週に計上する** | `_consumer` で、グループの販売の売上の行の直後に、C1 の行ごとに「売上の金額 × 率」を、E_SG の販売費（`kind=expense`・`scope=selling`、`price_type`＝費目）として 1 行ずつ |
| C3 | **二重計上と警告を止める** | C1 にあるノード・SKU では、`ppc_node_cost_rule.csv` の売上比率の行を PPC 用として扱い、Value Chain では計上も issues も出さない。C1 が無いモデル（既存のサンプル）は今のまま |
| C4 | **二つのファイルのずれを止める** | 起動時に、C1 の率の合計と配送の区間の固定額が、PPC の行（EC：15％ ＋ 3 SGD、15％。直営店：45％）と一致することを確かめ、合わなければ止める |
| C5 | **配送・梱包の名前** | `policy.py` の区間の費用の種類に `delivery_packing_cost`（運賃と同じ扱い：グループから外部へは売り手の販売費）を足す。サンプルの `SG_EC->CONSUMER` の行はこの名前で書く |

PPC・golden・ほかのサンプル：変わらない（C1 が無ければ今の動き）。

取らなかった案：PPC の費用のファイルを費目に分ける案。PPC の計算と KPI の列が `sga_cost`・`marketing_cost` の 2 つを前提にしており、PPC にも手が入るため。

## 5. 大杉さんに決めてほしいこと

| 一言で | 中身 | 推奨 |
|---|---|---|
| **代表の EC の lot は、週を読み替える** | 業務定義の例は「W28 入荷、W29 売上」だが、サンプルの EC は入荷と販売が同じ週。代表は `COS_Cream:SG_EC:2028-W28:00001`（販売 2028-W28、4 件・1,015.20 SGD）。「入荷だけでは 0 件」は直営店の lot（入荷 W28、販売 W30）で確かめる | 推奨。金額・件数は業務定義のまま |
| **発送が先行する例は、今は作らない** | 計画から作る販売では、発送と売上が同じ事象。区別には実績の記録が要る。G3 の保留と同じく、実績の取り込みの設計で扱う | 推奨 |
| **費目の内訳は Value Chain 用の表に置き、PPC は変えない** | §3 の C1〜C5。PPC は 2 つの合計のまま照合に使う。二つのファイルのずれは起動時に止める | 推奨 |
| **直営店の基準は 138 SGD をそのまま使う** | 業務定義は「値引き反映後」を基準にするが、直営店の値引きは定めていない（EC の 131 は平均の値引きを反映済み）。直営店は店頭価格で売る、と置く | 推奨。違う前提なら GPT-MC に返す |
