## 0. 業務の要求と、確かめたいこと

### 0.1 業務の要求

> 採用済みの「代理店への最低供給量 5 割」の化粧品の計画を基準に、タイの代理店へ届けるクリームだけは、各要求週の元の需要の 7 割以上を、その週に届けたい。端数は lot 単位で切り上げる。工場の能力は増やさず、シンガポールとタイのクリームの配分の数量を見直すことで、この条件を満たせるかを調べたい。

これは新しい試行のための要求です。今採用している計画を、自動的に置き換えるものではありません。新しい案を採るかどうかは、試行の結果を見て大杉さんが判断します。

### 0.2 BS-SEAF として確かめたいこと

この依頼は、WOM の開発の方法（BS-SEAF）そのものの試験でもあります。

- WOM に初めて参加した AI が、`AGENTS.md` と `docs/WOM_Start_Here.md` を入口にして、リポジトリの知識を**自分で見つけ、根拠付きで使えるか**。
- 業務の要求と今のモデルの差を、**データ／パラメータ／既存の道具／実装の変更**に分けられるか。
- 計画として**選ぶ量**と、制約の下で**実際に届く量**を分けて考えられるか。
- 分からないことを推測で埋めず、**調べられた範囲と、人の判断が要る事項**を示せるか。

コードを変えないことだけを成果にはしません。変える必要があるかどうかを、業務の意味と実装の対応から説明できることを重視します。

## 2. 基準の案と、変えてよい範囲

基準は、**化粧品の能力が足りない状態の写しに、採用済みの最低供給量 5 割の方針を当てた案**です。正式なサンプルそのものの能力の設定と、この試行の設定が同じだとは仮定しないでください。

基準の案の作り方・数量枠・方針のファイル・週への当て方の規則・プラグイン・実行の手順・既存の結果は、リポジトリから特定してください。数量と条件には、根拠のファイルと節を添えてください。

| 項目 | 今回の扱い |
|---|---|
| 元の需要 | 基準と同じ。数量・要求週・需要の性質を変えない |
| 計画の期間・助走期間（warmup） | 基準と同じ |
| 工場の能力・歩留まり・リードタイム・在庫の方針・操業の条件 | 基準と同じ |
| SKU ごとの供給の対象の合計 | 基準と同じ |
| 直営店・EC の配分の数量 | 基準と同じ |
| 美容液の配分の数量と最低供給量 | 基準と同じ |
| シンガポールの代理店のクリームの最低供給量 | 基準と同じ（5 割・切り上げ・必ず守る） |
| **タイの代理店のクリームの最低供給量** | **新しい条件：7 割・切り上げ・必ず守る** |
| **変えてよい配分の数量** | **クリームの、シンガポールの代理店とタイの代理店の間だけ。二つの代理店の合計は保つ** |
| 製品の年齢（残存期間）の条件 | 基準の条件を保ち、根拠と許容の値を特定する |

最低 7 割を満たすために、需要を減らす、端数を切り捨てに変える、最低率を下げる、といった変更は、**業務の要求そのものを変えること**になります。配分の数量を変える案と混ぜないでください。そうした変更が要ると判断した場合は、理由を添えて大杉さんへ戻してください。

5. 業務の条件の衝突・実納品での条件の未達・入力や計算の不整合の違い。

### 3.2 基準の案を特定し、再現する計画を作る

基準の案を組み立てるモデル・数量枠の CSV・方針の CSV・週への当て方の規則・CLI・既存の報告書を特定してください。

最初の成果物では、再現の手順と、照らし合わせる数量・条件・ファイルを示します。資料の数値を再集計した場合は、その方法を書いてください。WOM を実行していなければ「再実行は未実施」と書いてください。

### 3.3 新しい条件と数量枠の関係を調べる

- タイの代理店のクリームについて、各要求週の最低数量（元の需要 × 7 割、切り上げ）を求め、その合計と、基準の数量枠を比べる。
- 要るなら、シンガポールとタイの配分の数量をどう変えるか、候補と理由を示す。過去の案を使う場合は、その所在と、今回に当てはめてよい条件を確かめる。
- シンガポールの最低 5 割と、変えてはいけない数量・条件も満たしているかを確かめる。
- 最低数量の合計が数量枠以下でも、その週に届けられるとは決めつけない。時間の制約と実納品の確認は、後の試行に含める。

**配分の数量の正解や、使うべき過去の案の名前は、この依頼書では示しません。** 根拠から導いてください。

### 3.4 既存の機能との対応と差を整理する

既存の機能について、所在・使う条件・入力・処理の間の受け渡し・出力と確かめ方を調べてください。

「今回は使えない」と判断した場合も、「WOM に機能が無い」とすぐに決めず、調べた機能・使えない理由・足りない表現を示してください。新しい配分のエンジンやコアの変更を前提にせず、まず既存の経路で表せる範囲を確かめてください。

提案は、変える CSV と行の条件・パラメータ・使う既存の道具・（要れば）実装の変更の候補に分けて書きます。今回の範囲では、実装の変更は行いません。

## 5. 後の試行で確かめること（作業計画に入れる事項）

この節は、作業計画に盛り込んでほしい確認の事項です。モデルの実行と担当は、計画のレビューの後に決めます。

| 観点 | 比べること・確かめること |
|---|---|
| 比べる条件 | 基準の最低 5 割の案と、今回の変更の案。同じ元の需要・期間・判定の時点・単位・受渡点を使う |
| 数量 | 元の需要 ＝ 供給の対象 ＋ 未配分、供給の対象 ＝ 実納品 ＋ 配分後の未充足。SKU・チャネル・要求週へ戻して確かめる |
| 最低供給量 | 各要求週の選んだ量と、その需要に対応する当週の実納品の両方が、下限を満たすか |
| 時間の制約 | 事前の診断は参考値として扱い、実納品と未充足は計画の実行の後に照らし合わせる |
| ほかの市場への影響 | シンガポールのクリーム、直営店、EC、美容液への影響。減らす区間の始まりの週・長さ、週の最低の充足率も比べる |
| 在庫・年齢 | 作り置きと、先入れ先出しで数えた年齢。Lot_ID の滞留を、物の年齢と取り違えない |
| 金額 | 評価する場合は、既存の仮定と比べ方を明示する。数量配分の経路の「財務は未評価」を 0 円と読まない。比べるための評価の額を営業利益と呼ばない |
| 根拠 | 入力・方針・数量枠のファイル、版、実行の commit、プラグイン、実行した担当、出力の場所を記録する |

業務の条件を満たせない結果も、有効な検証の結果です。原因と、試した範囲を残してください。一つの候補が未達だっただけで、すべての配分に解が無いとは決めつけないでください。
