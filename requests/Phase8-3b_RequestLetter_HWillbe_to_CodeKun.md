## 1. 作るもの

### J1. `P_bau` を view に足す

```python
x_bau[i] = blocks[i].demand_qty / Σ blocks[j].demand_qty
P_bau    = evaluate_point(x_bau, blocks, tp, sc, cap_wk)["profit"]
```

`base_qty_lot`（= `CostBlock.demand_qty`）は既にあるので、新しい入力も
新しい機構も要らない。

**名前について。** 設計書 §2.5 は経営の語彙として **H_willbe** を使うが、
補助パネルの「利益水準」は実装名（`P_opt` / `P_greedy` / `P_hier`）で並んでいる。
**view と画面では `P_bau` を使い**、`H_willbe = P_bau` の対応は設計書 §2.5 が
持つ——`H_*` は経営の語彙、`P_*` は実装名、という既存の切り分けに合わせる。
**2つの名前が同じものを指すことを、docstring に明記すること**（これを書かないと
次に読む人が別物だと思う）。

### J2. 補助パネル「利益水準」に1行足す

現在:

```
P_opt     125.011 億
P_greedy  125.011 億
P_hier    121.371 億
```

`P_bau` を同じリストに足す。**既存の並び規則（値の降順）はそのまま**で、
`P_bau` は自然に最下段に来るはずである（実測でそうなる——もし P_bau が
P_hier を上回るケースがあれば、それは報告に値する発見なので必ず知らせてほしい）。

`P_greedy < P_grid` のときの `highlight`（構造由来の取りこぼしの視覚信号）は
**触らないこと**。`P_bau` には highlight を付けない。

### J3. 幅を1行、`level_notes_ja` に出す

**結論行（③）は3行のままにする。** 設計書 §3.1 の「③はテキスト3行以内」を
守る（パネルも `for i in range(3)` で3行固定）。幅は補助パネル側の
`level_notes_ja` に置く。

文面はまず次の形で実装してほしい。

```
現状維持（需要どおり配る）72.3億 に対し +52.7億（+72.9%）
```

**これは私が決め打ちした形である。** 同じ事実に少なくとも3つの言い方がある。

```
W1  現状維持 72.3億 -> 推奨 125.0億（+52.7億）      金額で言う   <- 実装はこれ
W2  推奨配分は現状維持の 1.73倍                      倍率で言う
W3  需要どおり配ると、最適の 58% しか稼げない        損失で言う
```

どれを経営者に最初に読ませたいかは大杉さんの判断であり、**実機で見てから
決める**ことにした（このセッションの欠陥9件はすべてその経路で見つかっている）。
だから **文面を1箇所にまとめ、差し替えやすくしておくこと**——
`_format_bau_gap_ja()` のような関数に切り出し、W1 / W2 / W3 のどれにでも
変えられる形にしてほしい。

**番号の接頭辞について（本書で導入）。** 選択肢に裸の `(a)(b)(c)` を使わない。
設計書 §9 の **R**（レビュー事項）、§9.1 の **G**（Gate 1 の問い）と衝突して
読み違えを起こすためである。実際、本書の草稿では G6（BAU の配分を
(a) 前年実績 / **(b) 需要比例** / (c) 均等配分 のどれにするか）と、上の文面の
選択肢が**どちらも `(a)(b)(c)`** で、大杉さんが「(a) 金額で決め打ち」を
「(a) 前年実績に変えたのか」と読まれた。**設計書 rev.4 で R と G の衝突を
G に改番して潰した直後に、同じ誤りを chat の中で犯した。** 以後、
**W = 文面（wording）** の接頭辞を使う。

### J4. 地形図に BAU の点を打つ

星（`P_opt` の推奨配分）とは**別の印**で、同じ三角図／線分の上に打つ。
形・色は Code君の判断でよい。要件は2つ。

1. **星と見分けがつくこと**（同じ形・同じ色にしない）
2. **凡例か近傍のラベルで「現状維持」と分かること**——印だけでは意味が伝わらない

**本 Phase では ALL ノード（hierarchy）と triangle モードのルートにだけ打つ。**
子ノードに降りたときの BAU は、その節の子への射影（配下市場の `x_bau` を
足し上げて正規化）として定義できるが、配分ゼロの枝などの端ケースが増える。
**申し送りにして、まず根だけで形を確かめたい。**
