## 2. 作るもの

### 2.1 `wom/cockpit/cases.py`（案の置き場と記録。Tk を import しない）

置き場（設計書 §3）：

```
output/cockpit_cases/<作業の名前>/
  workspace.json     元のモデルの場所、作った時刻、Git の SHA、報告期間
  <案の ID>/
    case.json        案の名前、親の案、入力の要点、入力のファイルの hash、実行の状態・時刻・使ったプラグイン・止まった理由
    model/           モデルの写し
    inputs/          数量枠・最低供給量・費用の前提（使う案だけ）
    run/             計画・PPC・Value Chain・年齢の検査・Flow Check の出力
    udp/             上位 Demand Plan の出力（方針ありの案だけ）
  compare/<基準の ID>__<相手の ID>/   道具 2 の出力
```

操作（関数）：

| 操作 | 中身 |
|---|---|
| 作業を作る | 元のモデル（`data/sample/` の下でもよい）を写して最初の案を作る。**元のモデルには書かない** |
| 案を複製する | 親の `model/`・`inputs/` を写し、`run/`・`udp/` は写さない。親の ID を記録。ID は連番 |
| 入力を変える | (a) 投入の表の 1 つの鍵の `launch_week`、(b) SKU の計画の生産量（`capacity_plan.csv` の、その SKU の工場の全行の `cap_soft`。助走の行を含む。`max_supply` を超える値は止める）、(c) SKU の `max_supply` と `cap_soft` の組（C3a を当てるのに使う）、(d) 供給の方針（なし／数量枠・最低供給量のファイル・週の規則）、(e) 費用の前提（販路の週固定費：有償の開始・終了の週、週額〔空欄＝未設定〕）。変えたら実行の状態を「未実行」に戻す |
| 状態を読む | 未実行／実行中／済み／止まった（理由つき）／衝突（終了コード 3）／未達（終了コード 4）／**入力が変わった**（今の入力のファイルの hash が、実行の時の記録と違う） |
| 一覧 | 案の表の 1 行に要る値（入力の要点と、済みの案の結果の要点）を返す |

止める条件はメッセージに、ファイル・値・直し方を出す（黙った既定値を作らない）。投入の表・需要は、変えるたびに道具 1 で作り直す（需要 CSV を直接書き換えない）。
