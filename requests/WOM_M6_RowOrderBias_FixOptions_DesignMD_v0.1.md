# 能力を超えたとき「どの市場の lot を後回しにするか」を CSV の行の順で決めないための設計（直し方の比較）

## 0. 一言で

**業務の要件（大杉さん 2026-11-18、D1）：「CSV の行の順を供給の優先の根拠にしない」。** 今の Backward は、工場の能力を超えた週に、lot の並びの**末尾**を前の週へ押し戻す。並びは木の CSV の行の順で決まるので、最後の行の市場が欠ける（醤油の 21 シフト：ベルギー・オランダ 約 43%、ほかは約 98%）。

**推奨：押し戻す lot の選び方を「その週の市場の lot の数に比例」に替える（案 C）。** 最初は設定で選べる形（既定は今の動き）で入れて醤油で試し、結果を見てから既定を替える。明示の優先順位の表（案 B）は、業務で優先を決める必要が出たときに足す。

## 1. 今の仕組み（どこで「行の順」が効くか）

| # | 場所 | 何が起きるか | 行の順の効き方 |
|---|---|---|---|
| E1 | `backward_planner.py` `_ot_propagate`（出荷側を子から親へ） | 親の週の lot の並びに、子の順に lot を足す | 子の順 ＝ `sc_tree_master.csv` の行の順。工場の週の並びが「米国西・米国東・日本・フランス・ベルギー・オランダ」になる |
| E2 | `_apply_mom_cap_backward`（工場の能力） | `within_cap = s_lots[:cap_int]`、`overflow = s_lots[cap_int:]`。はみ出しを前の週の並びの**末尾**に足す | **ここで誰が後回しになるかが決まる。** 末尾に足すので、前の週でもまた末尾＝また押し戻される。計画の最初の週を超えた lot は落ちる（past_due） |
| E3 | 同（休業の週） | 休業の週は `cap_int = 0`。その週の lot がまるごと前の週の末尾へ | 休業の週の lot が次に削られる（C03 の NL ⑤ 458 の一部） |
| E4 | `forward_planner.py` Step 0a・休業の繰り越し | 能力を超えた P を翌週の先頭へ（古い lot を先に） | Backward が能力に合わせていれば、ほぼ起きない。今回の偏りの主因ではない（報告書 §3） |
| E5 | `sc_tree.bridge_backward(market_priority=None)` | 優先の置き場はあるが、使われていない | — |

能力が**欠ける量**を決め、E2 の選び方が**誰が欠けるか**を決めている（報告書 §3.3：行の順を入れ替えると、総納品は同じ 87,375 lot のまま、不足が日本に移る）。

## 2. 比べる案

| 案 | 一言で | 中身 | 要件を満たすか |
|---|---|---|---|
| A | **データの並びで避ける（エンジンは変えない）** | 木の CSV の行を並べ替える・注記する | **満たさない**（行の順が根拠のまま。業務の判断を CSV の並びに隠す）。直すまでの間の注記としてだけ使う |
| B | **優先順位の表で決める** | 市場（leaf_out）ごとの優先の順位を表で持ち、順位の低い市場の lot から押し戻す。同じ順位の中は案 C で | 満たす。ただし**業務が優先を決めることが前提**。醤油の R1 は「同順位」なので、結局 C が要る |
| C | **市場の lot の数に比例して押し戻す（推奨）** | 週 w の並びにある市場ごとの lot の数に比例して、はみ出しの数を最大剰余法で市場に割り振る。各市場の中では今の順（並びの後ろ）から選ぶ。端数の同点は、それまでに押し戻した累計の少ない市場を先に（期間でならす） | **満たす。** 業務の優先を決めていないときの「中立の既定」になる |
| D | **要求週の遅い lot から押し戻す** | 並びの中で、要求週（Lot_ID の週）の遅い lot を先に前の週へ | 一部。市場の偏りは減るが、同じ要求週の市場の間はまた並びの順になる。C の中の「市場の中の選び方」として使う余地はある |
| E | **能力の層（LP）に任せる** | 既存の `CapacityLayerPlugin`（既定 OFF）に、市場の公平・優先の目的を足す | 満たしうるが重い。直列の InBound だけ・push Mode 1〜3 で止まるなど適用条件が狭く、醤油（工場 2 段・push）に合うか不明。今回は比べるだけ |
| F | **Management の配分を必ず通す（エンジンは変えない）** | 配分をしない計画は診断用と位置づけ、能力を超える需要は上位で配分してから渡す | 一部。C03 でも、休業の週・計画の初めの週の分（NL ⑤ 458）は並びの順で欠けた（報告書 §4）。**配分をしても残る** |

### 2.1 案 C の見込み（醤油 21 シフト、R0）

毎週 1,000 lot（米国西 175・米国東 175・日本 300・フランス 150・ベルギー 100・オランダ 100）に対し、能力 800 で 200 がはみ出す。比例で割ると、米国 35・35、日本 60、フランス 30、ベルギー 20、オランダ 20 を押し戻す。

- **見込み**：総納品は今と同じ 87,375 lot 前後（能力が決める量は変わらない）。市場別の ④ ÷ ① は 6 市場とも約 87% にそろう。落ちる lot は全市場に散る。
- **確かめること**：本当に総納品が変わらないか。前の週へ押し戻された lot が、前の週の比例の母数に入ることで偏りが戻らないか（累計でならす端数の規則で抑える想定）。在庫・製品の年齢・供給ゼロの週がどう変わるか。

## 3. 推奨の進め方

1. **段 0（Code君、読むだけ）**：全 golden のモデル（16）で、E2 のはみ出し（工場の週の lot が能力を超える週）が起きる工場と、その週に市場が 2 つ以上並ぶかを数える。**golden が変わるモデルの一覧**を先に作る。休業の週（E3）も分けて数える。
2. **段 1（Code君、保護対象のコアの変更）**：E2 のはみ出しの選び方を一つの関数に切り出し、方式を選べるようにする。`planning_config.csv` の新しいキー（例 `overflow_policy` ＝ `tail`〔今の動き〕／`proportional`〔案 C〕）。**既定は `tail`** にして、golden は変えない。単体（合成の木で比例の割り振り・端数・累計でならす）、CSV からの結合（設定のキーの読み込み、知らない値で止める）、golden 不変、の 3 層のテスト。
3. **段 2（試行）**：醤油の写しで `proportional` にして R0・R1（C02・C03）を回し、§2.1 の見込みを確かめる。
4. **段 3（大杉さんの判断）**：既定を `proportional` に替えるか。替えるなら、段 0 の一覧のモデルの golden を意図して作り直す（差分が監査の記録）。
5. **案 B（優先の表）** は、業務で「この市場を先に」と決める必要が出たときに、同じ関数の別の方式として足す（`bridge_backward` の `market_priority` の置き場は、そのときに整理する）。

**Forward（E4）は今回触らない。** 段 2 で Forward 側に偏りが残ると分かったら、別に扱う。

## 4. 決めていただきたいこと

| # | 一言で | 中身 | 推奨 |
|---|---|---|---|
| Q1 | **既定の切り方は「比例」でよいか** | 業務の優先を決めていないとき、能力を超えた分を市場の lot の数に比例して後回しにする | **はい（案 C）** |
| Q2 | **比例の単位** | 週ごとに比例して、端数は期間でならす／期間の合計で比例する（週の中は偏りうる） | **週ごと＋端数は期間でならす**（計算が局所で、説明しやすい） |
| Q3 | **優先の表は今作るか** | 市場の優先の順位を業務の表で持つ（案 B） | **今は作らない。** 必要になったら同じ関数に足す |
| Q4 | **最初は設定で選べる形にするか** | 既定を今の動きのまま入れて試し、結果を見てから既定を替える | **はい**（golden を変えずに入れ、試行の後に一度だけ作り直す） |
| Q5 | **Forward は今回触らないか** | 能力を超えた P を翌週の先頭へ送る所（E4） | **触らない**（段 2 で残りが見えたら別に） |

## 5. しないこと（この設計の範囲の外）

製品をまたぐ共用の能力の配分（rice・能力の層の話）、利益で選ぶ配分（Management の層、U3）、要求週ごとの最低供給の保証（§6.1）、計画の最初の週の「置いたが作れない」lot の扱い（Start Here 4.3 の 12、別の未決）。
