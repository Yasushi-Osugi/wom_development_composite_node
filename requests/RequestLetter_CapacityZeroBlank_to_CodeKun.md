## 1. 今の動き（コードで確かめたこと）

- `PlanNode.processing_limit()`：開いている週で `cap_hard <= 0` なら None（未設定 ＝ 上限なし）。**CSV に 0 を書くと「上限なし」になる。** Forward の Step 0a（`CapHard > 0` のときだけ封印）、`cap_soft`（0 ＝ 無制限）、能力の読み込み・報告など、「0 ＝ 無制限」の前提が多くの箇所にある。
- 能力ゼロは今、休業（`is_open`、操業カレンダー）でしか表せない。rice の田は、非収穫週を 0 にできず 0.1 を入れている。

## 2. 直すこと

### 2.1 値の意味

| CSV の値 | 意味 |
|---|---|
| 空欄（列が無い、または値が空） | 未設定。上限なし（今の「0」の動き） |
| 0 | **能力ゼロ**。その週は処理できない。休業とは別の状態として持つ（休業は操業カレンダーの意味のまま。push の休業週の入庫の受け入れなど、休業の振る舞いは変えない） |
| 正の数 | その値が上限 |
| 数値でない、負の数 | **エラーで止める**（行の番号と値を出す） |

- `max_supply`（cap_hard）と `cap_soft` の両方に同じ規則を当てる。`cap_override.csv`（CapacityOverride プラグイン）など、能力を入れるほかの経路も同じ規則にする。
- 内部では「未設定」を None などで持ち、0 と区別する。「`> 0` なら有効」という判定を使っている箇所をすべて洗い出し、None ／ 0 ／ 正の値を区別する形に直す（Forward・Backward・能力の報告・Flow Check・World Map の表示・PPC の表示など）。

### 2.2 読めない行

- 計画の木に無いノード名の行：**エラーで止め**、行の一覧（ファイル・行・ノード名・製品）を出す。
- 計画期間の外の週の行：止めずに、件数を警告として出す（能力の表が計画期間より長いのは普通のため）。
- 止めたときのメッセージには、直し方（ノード名の綴り、製品の対応）を書く。

### 2.3 smartx の 408 行（決定 a）

- `AssemblyCN` の SmartX の行を `AssemblyCN_g1`、SmartXNext の行を `AssemblyCN_g3` に直す。値はそのまま。
- **予想される影響**：SmartX・SmartXNext の組立の能力は、今の CSV では毎年需要のほぼ半分（例：2026 年の SmartX は需要 61,347 に対して能力 30,104）。直すと大きな能力不足と注文残が出る。これは今のデータの値によるもので、ラインの能力は次の依頼書（`RequestLetter_GenerationLine_UpperLayer_to_CodeKun.md`）で決め直す。今回は、直したことでどれだけ変わったかを報告する。
