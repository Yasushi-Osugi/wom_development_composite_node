# 経営施策（4P）を WOM の設定に翻訳・変換する処理の定義と作業分解

## 0. 一言で

**「翻訳表」は、一つの経営施策を、それが動かす WOM のデータ・パラメータ・業務ルールの組へ対応づける辞書である。** この辞書を使う処理は、性質の違う二つに分けて作る。

- **翻訳**（意味を決める）：経営の物語（ケース・スタディ、SWOT、経営施策）から、構造化した「施策シート」を作る。人と AI の対話で行い、人が採否を決める。機械で自動にしない。
- **変換**（機械で行う）：施策シートを、案（コックピットの案のモデルの写し）の CSV の書き換えに落とす。決まった規則で、同じ入力からは同じ結果。止める条件と変更の記録を持つ。

最初は、**化粧品の 1 製品・1 市場で「販促なし／あり」を比べる縦の一本**で、翻訳 → 変換 → 計画 → 比較 → 施策までの追跡を通す（GPT君の推奨と同じ）。

## 1. 「翻訳表」の理解

### 1.1 何を対応づけるか

note 記事の表（4P × WOM の設定 × 確かめる影響）を、Code君が実際のファイル・列・単位・止める条件まで落とした（翻訳表 v0.1）。要点：

| 観点 | 翻訳表 v0.1 での扱い |
|---|---|
| 1 つの施策 → 複数の設定 | 例：「販路を足す」は、木の leaf_out・需要の `region`・LT・在庫方針・価格・費用に同時に効く |
| 三つの種類の条件 | **W**（WOM が計算する設定）、**H**（人が置く仮説。外側で数に換算して W に入れる）、**×**（今は表せない。黙って捨てずに止める） |
| 止める条件 | 既存のローダが止めるものと、翻訳の道具が足すべきもの |
| 確かめる影響 | WOM が計算する部分（採算・設備負荷・届く時期と量・在庫と資金） |

### 1.2 note 記事の議論から引き継ぐ原則

1. **経営が選ぶ施策／顧客反応の仮説／外部環境の条件を分けて記録する**（施策と一緒に都合のよい反応を選ばない）。
2. **元の需要と、仮説で足した需要を分けて残す**（①元需要・②供給対象・④実納品・⑤未充足の分離と同じ考え方。供給対象を減らしただけの改善を、施策の効果と読まない）。
3. **結果から施策へ戻れる**（どの施策のどの設定変更が、どの市場・どの週の差を生んだか）。
4. **黙った既定値を作らない**（価格や費用が無い所は未評価として見せる）。
5. **価格弾力性・販促の反応はエンジンに入れない**（外側の換算。OPEC+ のシナリオと同じ作り方）。

## 2. 全体の層（どこからどこまでを定義するか）

| 層 | 成果物 | 作る人 | 性質 | 検証 |
|---|---|---|---|---|
| L0 経営の物語 | ケース・スタディの記述（事業の状況、SWOT の要点、経営の問い） | 大杉さん・GPT-MC君 | 意味 | 人の採否 |
| L1 経営施策 | 施策の狙いと取り組みテーマ（何を変えたいか、誰に何の価値を） | 大杉さん・GPT-MC君 | 意味 | 人の採否 |
| L2 4P 施策 | **施策シート**・**仮説シート**・**外部環境シート**（§4） | GPT-MC君（業務定義）・Claude君（WOM の型への対応） | **翻訳** | 型カタログとの照合・人の採否 |
| L3 設定の変更 | 案のモデルの CSV の書き換えと**変更記録** | 変換の道具（Code君が作る） | **変換** | 止める条件・ローダ・headless の 1 回の実行 |
| L4 計画と比較 | 案の実行結果、比較の表と画面 | 既存のコックピット | W の計算 | 既存の照合（Flow Check・Value Chain） |
| L5 追跡と見直し | 施策 → 変更 → 差の説明、実績との照合（将来） | Claude君・大杉さん | 説明 | 施策ごとの差の帰属 |

**この設計書が定義するのは L2 と L3、およびその受け渡し（L1 → L2、L3 → L4、L4 → L5 の追跡の鍵）。** L4 は既存の仕組み（`tools/cockpit_cases.py`・比較の画面）を使う。

## 3. 三つの条件と、案の組み立て

| 種類 | 例 | 記録する所 | 比較での扱い |
|---|---|---|---|
| 経営が選ぶ施策 | 価格、販促の期間と予算、投入週、販路、増産の期間 | 施策シート | 案ごとに変える |
| 顧客反応の仮説 | 販促 → 需要の増え方、値下げ → 数量、立ち上がり | 仮説シート（低位・基準・高位） | **同じ施策を各水準で計算**し、感度を見る |
| 外部環境の条件 | 為替、関税、輸送の遅れ | 外部環境シート | **同じ組を全案に適用** |

**案 ＝ 施策の組 × 仮説の水準 × 外部環境の組。** 案の名前と記録にこの三つの鍵を持たせ、比較の画面で「施策の効果」と「仮説の置き方」を分けて読めるようにする。

### 4.1 単位と識別子（v0.2 で追加、GPT君のレビュー 2）

- **数量 lot と物量を分ける**。PPC は lot 数 × `cpu_size` で物量に直して単価を掛ける。化粧品は `cpu_size=24`、EC のクリームは 131 SGD／個なので、1 lot の売上は 3,144 SGD。翻訳表 v0.1 の「金額／lot」の書き方は、**列ごとに単位を確かめて直す**（化粧品の単価と定額の費用は原則 1 個当たり）。
- 型カタログの各型に、入力の単位（lot・物量・金額／物量・週額・総額）と通貨を持たせる。変換の道具は、単位の違う値を黙って掛け合わせない。
- **需要の `region` と、価格・費用のノード名を同じ文字列と仮定しない**。既存の対応（木の leaf_out・`ppc_market_price.csv` の `market_node`・`vc_node_assignment.csv`）を通して解決し、解決できなければ止める。

### 4.2 既存の仕組みの再利用（v0.2 で追加）

| 必要なこと | 使う既存の仕組み | 補うこと |
|---|---|---|
| 案の外の期間費用（金額・通貨・負担法人・発生週） | コックピットの案の費用の前提 `inputs/fixed_cost.csv`（列 `cost_item, entity, paid_start_week, paid_end_week, weekly_amount, currency, note`、`set fixed-cost`）。計画のハッシュに入らず、比較だけが読む。比較の道具が `P0 − 費用 ＝ 控除後`（`fixed_cost_breakeven.csv`）を出す | 比較の道具は週額 × 週数をそのまま P0 から引き、**円以外の通貨を換算しない**（境目の判定だけ「条件外」と出す）。初版は変換の道具が円に換算して書く（費用発生週の `ppc_fx_rate.csv`。期間内でレートが変わるなら止める）。比較の道具は、円以外の週額を控除後に使わない（止めるか未評価）よう直す |
| 案のモデルの需要を書く | コックピットの案の `model/demand_forecast.csv`（案ごとの写し）。変更は案の `changes` に残る | 基準需要 B は**凍結した元のモデル**から読む（案の写しの需要を基準にしない） |
| 案の実行・比較 | `tools/cockpit_cases`（copy・run・compare）、比較の画面 | 4 案を並べる要約の表（P0・追加費用・控除後・基準との差、①〜⑤） |
| 投入の表から需要を作る経路 | `market_entry_plan.csv` → `gen_demand_from_entry_plan`（案の中で一致を検査） | **初版は、投入の表のある案では止める**。正式な化粧品のサンプルには投入の表が無い。投入の表のある案への適用（基準需要の生成 → 販促の差分 → 需要の確定）は、次の版で既存の一致の検査と合わせて定義する（GPT君のレビュー 3） |

### 4.3 需要の三つの名前（v0.2 で追加）

| 名前 | 記号 | 意味 |
|---|---|---|
| 施策なしの基準需要 | B | 凍結した元のモデルの `demand_forecast.csv` |
| 販促の増減分 | d | 仮説から作る符号つきの整数の差分（反動減を含む）。丸めは業務定義 §3.3（区間ごとの累積の切り捨て） |
| 施策適用後の需要 | D ＝ B ＋ d | その案の **①元需要**。ここから ②供給対象・③未配分・④実納品・⑤未充足を追う |

B と ① を同じ言葉で呼ばない。
