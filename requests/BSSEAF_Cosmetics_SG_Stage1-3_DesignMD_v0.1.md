## 0. この実験の目的と読み方

### 0.1 目的

目的は化粧品のモデルを完成させることではない。BS-SEAF の手順（Self-Evolving Modeling Loop の 8 段階）が、**お米とは別の業務に使えるか**を確かめる。

- お米で残した知識（決定記録、Start Here、報告書）を、どこで再利用できたか。
- 新しい業務の意味のうち、どれをデータ・パラメータで表せ、どれが構造の話になるか。
- 各段階の判断が、根拠と検証結果まで追えるか。

### 0.2 記述の区分（Sol君の案）

本書のすべての記述に、次の区分のどれかを付ける。

| 印 | 区分 | 条件 |
|---|---|---|
| **[事実]** | 確認済みの事実 | 出典と確認日がある |
| **[仮定]** | 実験用の仮定 | 実験のために置いた値・前提。現実の値ではない |
| **[方針]** | 人間が決める方針 | 大杉さんが決める（§6 にまとめた） |
| **[未確認]** | 未確認事項 | 追加の調査や判断が要る |

### 0.3 対応状況の 3 段階（第3段階で使う）

| 印 | 意味 |
|---|---|
| **守れる** | 計画に反映され、計画そのものが条件を守る |
| **検出** | 計画は条件を守らないが、結果から違反を見つけられる |
| **未確認** | 対応できるかどうか、まだ確かめていない |

加えて、対応の手段を **Data／Parameter／Core** で記録する（Self-Evolving Modeling Loop の「変更方法の選択」）。**基準ケースの目標は Core の変更ゼロ**とする（既存 Core を固定して対応可能性を調べる）。

## 2. 第2段階：業務の意味モデル

### 2.1 自然言語の説明（出発点）

- 日本の工場で美容液とクリームを作る（調合・充填・包装）。
- 作った製品は、品質確認（出荷判定）を終えてから出荷できる。
- 判定を終えた製品を海上輸送でシンガポールの DC へ送り、直営店・公式 EC・代理店へ届ける。
- 直営店は開店週より前には売らない。開店時の店頭在庫は、計画の中の先行生産で用意する。
- 納品時には、使用期限まで一定の期間が残っていなければならない。
- 正規の販路にだけ供給し、値引きはしない。
- 工場には週ごとの能力の上限がある。

### 2.2 概念と関係

```
原料（日本で調達）
  └→ 日本の工場：調合・充填・包装（能力の上限あり、製造バッチに製造日）
       └→ 品質確認（判定の期間）
            └→ 判定済み倉庫（日本、輸出前）
                 └→ 海上輸送
                      └→ シンガポールの DC
                           ├→ 直営店（① 自社、開店週あり）
                           ├→ 公式 EC（③ 自社ネット）
                           └→ 代理店（② 外部の法人）
需要：SKU × チャネル × 週（lot）
法人：日本本社（JPY）／シンガポール販社（SGD）／代理店（外部）
```

### 3.2 中心の差分 2 件

#### COS-R04：品質確認前の製品を引き当てない

- **置き換え**：「倉庫に 100 個あり、判定前の 20 個は売れない」を、WOM では「状態」ではなく「場所と時間」で表す。判定前の 20 個は工場→判定済み倉庫の区間（判定の期間）の中にあり、判定済み倉庫の I に入るのは判定を終えた 80 個だけになる。Forward は I にある lot だけを出荷するので、判定前の製品は構造上引き当てられない。
- **見え方**：判定中の量は、World Map の「輸送中」や LOVEM の区間で見える。PSI のグラフには出ない。
- **限界**：
  - 判定の期間は週に切り上がる（数日の判定も 1 週）。在庫は過大に出る（`inbound_safety_stock.md` と同じ粒度の制約）。
  - 不合格・廃棄（歩留まり）は表せない。整数の lot と Lot_ID の同一性のもとで、量を減らす仕組みが無い（石油の三段階分割と同じ「WOM に入れない」判断の候補）。
  - 判定の結果によって出荷を止める（保留する）判断も表せない。基準ケースでは全量合格とする（A10）。

#### COS-R05：納品時の残存期間

- **計画で守る候補（条件付き）**：Capacity Layer（`wom/plugins/capacity_layer.py`、既定 OFF）の上位の LP は、市場の要求週 `dw` に対して内部の計画週を `dw − max_advance_weeks` から `dw` の範囲だけから選ぶ（`wom/capacity_layer/serial_adapter.py` の `problem_from_tree`）。`max_advance_weeks` を許容滞留（製造から納品まで 52 週）以下にすれば、割り当てた lot は残存期間を守る。割り当てられない lot は作らず、市場の注文残になる（期限切れの製品を出すより、届かない方を選ぶ動きと一致する）。
- **条件**：
  - Capacity Layer が ON であること（既定 OFF。golden も OFF）。
  - 直列の InBound であること（leaf_in 1 つ・分岐なし・bom_qty 1・push の Mode 1〜3 なし）。基準ケースは満たす。
  - OFF のときは、Backward の能力の押し戻しに**前倒しの上限が無い**（Start Here §7）。能力が足りない週があると、何十週も前に作り溜めて残存期間を割る可能性がある。
- **検出**：実出荷の記録から、lot ごとに「工場の製造週」と「市場への納品週」の差を数え、52 週を超える lot を一覧にする。照合の道具は既存の LOVEM（`tools.lovem_observe`）と段階 D の出荷の記録（`wom/valuechain/records.py`）で足りる見込み。
- **期限そのものは引当の条件として持たない**。Sol君の指摘どおり、「外部の検証で期限違反を見つけられる」ことと「WOM が期限を守って引き当てる」ことは別である。本件は「滞留の上限を計画で抑える（条件付き）」＋「結果で違反を検出する」の組み合わせであり、期限を守る引当（Core の拡張）ではない。
