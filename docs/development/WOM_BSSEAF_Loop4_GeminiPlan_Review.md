## 0. 結論

**一言で：今回は、知識を辿る試験の前に、Gemini君がリポジトリを読めないことが分かった。**

- Gemini君は、この会話で GitHub のリポジトリを読めなかった（本人がそう答えている）。リポジトリは公開されているが、会話の中から取りに行けなかった。
- そのため作業計画は、依頼書の文章を言い換えた一般的な手順になった。依頼書 §7 の受入条件のうち、**満たしたのは「業務の要求が明確」と「確かめ方が正確（文書確認だけと書いた）」の一部だけ**。
- 一方で、**読めないことを隠さず、実行もしていないと正直に書いた**点はよい。BS-SEAF の「分からないことを推測で埋めない」に沿っている。
- ただし一か所、食い違いがある：§8 の「読んだファイル」に `AGENTS.md` と `docs/WOM_Start_Here.md` を挙げているが、会話の中では「直接読めない」と答えている。実際に読んだのか（大杉さんが本文を貼ったのか）、確かめが要る。

この結果は失敗ではなく、試験の最初の事実として記録する：**新しい AI を迎えるとき、まず作業の環境（リポジトリを読めるか）を確かめる必要がある**。依頼書 §6 の「最初に、作業の環境でできることを記録してください」が、まさにここで効いた。

## 1. 受入条件ごとの評価（依頼書 §7）

| 条件 | 評価 | 理由 |
|---|---|---|
| 根拠へ辿れる | 満たさない | commit・ファイルの節・コードの所在が無い。`target_commit` は「直接アクセスできないため」 |
| 業務の要求が明確 | 満たす | タイのクリームだけ 7 割、ほかを固定、2 代理店の合計を保つ、を正しく書いている |
| 基準が正しい | 満たさない | 「C3a の作り方、P2-a2 の数量枠」は依頼書には無い語なので、どこかで読んだ可能性がある。ただし基準の作り方・方針のファイル・規則の名前を特定していない |
| 変更の案を説明できる | 満たさない | 最低数量の合計と数量枠の比較（タイのクリームで 299 lot 対 274 lot）が出ていない。候補の数も無い |
| 既存の機能を調べている | 満たさない | 機能の所在（上位 Demand Plan、`--policy-file` など）を調べていない |
| 検証の計画が具体的 | 一部 | 観点は依頼書 §5 のとおり並んでいるが、ファイル・数・手順が無い |
| 確かめ方が正確 | 一部 | 「文書確認だけ」と書いたのは正確。ただし §8 の読んだファイルの一覧と、会話での「読めない」が食い違う |
| 役割と 8 段階が対応する | 一部 | Code君への引き継ぎは書いている。8 段階との対応は無い |

**補足（ほめてよい点）**：引き継ぎの欄（YAML）を、共通の形で付けてきた（依頼書から形を読み取った）。冒頭に「業務の要求」と「固定する条件」をそろえた。人の判断が要る事項として、シンガポールへのしわ寄せの許容範囲を挙げた。

## 2. 「C3a」「P2-a2」の語について（要確認）

作業計画の §3 に「C3a の作り方、P2-a2 の数量枠」とある。これらは依頼書 v1.0 の本文には無い（依頼書は「能力が足りない状態の写し」「数量枠」とだけ書いた）。考えられるのは：

1. 大杉さんが、依頼書以外の資料（Start Here やシナリオの文書）の本文も会話に貼った。
2. Gemini君の前の会話（2026-11-05）で、何かを読めていた。
3. 依頼書 §8（正式化の記録）の「C3a の作り方、P2-a2 の数量枠」という記述を読んだ。

3 が最もありそう（§8 に「基準の案に要る原本（C3a の作り方、P2-a2 の数量枠、…）」と書いた）。**正式化の記録に、基準の名前を書いてしまった**ことになる。答えそのものではないが、自分で辿り着くべき名前の手がかりになる。次に依頼書を渡すときは、§8 を外した版にする（§4）。

## 3. BS-SEAF の記録

| 項目 | 中身 |
|---|---|
| 段階 | 段階 2（知識の検索）の前で止まった。原因は知識の不足ではなく、作業の環境 |

## 4. 次の進め方（大杉さんの判断）

| # | 一言で | 中身 | 推奨 |
|---|---|---|---|
| 1 | **まず、読めるかを確かめる** | Gemini君に、公開リポジトリの生のファイルの URL（例：`https://raw.githubusercontent.com/Yasushi-Osugi/wom_development_composite_node/wom-v1r6m0_BS-SEAF/AGENTS.md`）を一つ渡し、中身の最初の数行を答えてもらう。答えられれば、Start Here の中のリンクも同じ形の URL で辿れる | **推奨**。読めれば、試験の趣旨（自分で辿る）を保てる |
| 2 | **読めなければ、リポジトリを丸ごと渡す** | Gemini の、コードのフォルダや GitHub のリポジトリを読み込む機能（使える場合）か、リポジトリの zip を渡す | 1 がだめなときの次の手 |
| 3 | **依頼書の §8 を外して渡し直す** | 試験の条件の記録（§8）は、受ける側に渡す本文から外し、別のファイルにする。基準の名前の手がかりを渡さないため | 推奨（1・2 のどちらでも） |
| 4 | **ファイルを貼って渡すのは最後の手** | 大杉さんが必要なファイルを選んで貼ると、「自分で辿る」試験にならない（どれを選ぶかを人が決めてしまう）。それでも試すなら、貼ったファイルを記録し、「辿る力」ではなく「読んで組み立てる力」の試験として扱う | 他が全部だめなとき |

どの道を選んでも、今回の作業計画（v0.1）は、**環境が無いときの答え方の記録**として残す。
