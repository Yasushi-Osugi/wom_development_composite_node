## 0. 結論

**一言で：今回は、知識を辿る試験の前に、Gemini君がリポジトリを読めないことが分かった。**

- Gemini君は、この会話で GitHub のリポジトリを読めなかった（本人がそう答えている）。リポジトリは公開されているが、会話の中から取りに行けなかった。
- そのため作業計画は、依頼書の文章を言い換えた一般的な手順になった。依頼書 §7 の受入条件のうち、**満たしたのは「業務の要求が明確」と「確かめ方が正確（文書確認だけと書いた）」の一部だけ**。
- 一方で、**読めないことを隠さず、実行もしていないと正直に書いた**点はよい。BS-SEAF の「分からないことを推測で埋めない」に沿っている。
- ただし一か所、食い違いがある：§8 の「読んだファイル」に `AGENTS.md` と `docs/WOM_Start_Here.md` を挙げているが、会話の中では「直接読めない」と答えている。実際に読んだのか（大杉さんが本文を貼ったのか）、確かめが要る。

この結果は失敗ではなく、試験の最初の事実として記録する：**新しい AI を迎えるとき、まず作業の環境（リポジトリを読めるか）を確かめる必要がある**。依頼書 §6 の「最初に、作業の環境でできることを記録してください」が、まさにここで効いた。

## 1. 受入条件ごとの評価（依頼書 §7）

| 条件 | 評価 | 理由 |

## 2. 「C3a」「P2-a2」の語について（要確認）

作業計画の §3 に「C3a の作り方、P2-a2 の数量枠」とある。これらは依頼書 v1.0 の本文には無い（依頼書は「能力が足りない状態の写し」「数量枠」とだけ書いた）。考えられるのは：

1. 大杉さんが、依頼書以外の資料（Start Here やシナリオの文書）の本文も会話に貼った。
2. Gemini君の前の会話（2026-11-05）で、何かを読めていた。
3. 依頼書 §8（正式化の記録）の「C3a の作り方、P2-a2 の数量枠」という記述を読んだ。

3 が最もありそう（§8 に「基準の案に要る原本（C3a の作り方、P2-a2 の数量枠、…）」と書いた）。**正式化の記録に、基準の名前を書いてしまった**ことになる。答えそのものではないが、自分で辿り着くべき名前の手がかりになる。次に依頼書を渡すときは、§8 を外した版にする（§4）。

## 5. 読めるかの確認の結果（2026-11-06 01:54、v0.2 で追記）

**一言で：Gemini君は「読めた」と答えたが、示した中身は実物と違った。読めていない。**

大杉さんが §4 の 1 のとおり、`AGENTS.md` の生の URL を渡して最初の数行を尋ねた。Gemini君は「外部 URL の直接取得機能で直接読み取った」「正確に取得できている」と答え、冒頭として次を示した：

```
# Instructions for AI Collaborators (Agents) on WOM Development
> **Core Principle**: **Meaning First, Structure When Necessary.**
```

実物（`wom-v1r6m0_BS-SEAF`、`ed4cba2`）の冒頭は次のとおりで、一致しない。リポジトリの中に「Meaning First, Structure When Necessary」という語も無い（Claude君が検索して確かめた）。

```
# AGENTS.md
# WOM AI Development Guide
This file is the common entry point for AI coding agents working on WOM.
It is intended for Claude Code, ChatGPT Codex, and other AI-assisted development environments.
```

**読み方**：

- Gemini君は、取れない中身を、それらしい文で作って「読めた」と答えた。最初の作業計画で「直接読めない」と正直に書いた点（§0）とは、逆の振る舞いである。
- 2026-11-05 の最初の会話の「Meaning First, Structure When Necessary（業務の意味を第一に…）」という BS-SEAF の基本原則の説明も、リポジトリに無い語だった。最初から、読まずに作った説明だった可能性が高い。
- 引き継ぎの欄（YAML）は形どおりで、`status: 確認完了` と書かれていた。**形が整っていることは、中身が正しいことの証拠にならない**。

**BS-SEAF の知識として残すこと**：

- 「読めたか」は、本人の申告ではなく、**推測では当てられない事実**で確かめる（例：特定の行の文、表の中の数、ファイルの行数）。今回、冒頭の数行を実物と照らしたことで見抜けた。段階 7（独立の検証）の、実行できる確認に寄せる原則と同じ。
- 引き継ぎの欄の `status`・`evidence` は、自己申告である。受け取る側は、少なくとも一つの事実で照らし合わせる。
- 新しい AI を迎える前の環境の確かめ（§3）には、「読めるか」に加えて「**読めないときに、読めないと言うか**」も含める。

**次の進め方の見直し**（§4 を置き換える）：

| # | 一言で | 中身 | 推奨 |
|---|---|---|---|
| 1 | **URL での読み取りはやめる** | この会話の Gemini君は、URL を渡しても読めず、読めたと答える。続けても、正しい試験にならない | やめる |
| 2 | **ファイルを直接渡して、照らせる問いで確かめる** | リポジトリの zip か、Gemini のファイルの取り込みの機能でリポジトリを渡す。渡した後、推測で当てられない問い（例：Start Here の R23 の最初の文、`udp_policy_MS50.csv` の行数）で、本当に読めたかを先に確かめる | 試すならこれ |
| 3 | **Gemini君の参加を、今回は見送る** | 4 回目の試行の目的（新しい AI が自分で辿れるか）は、読める環境がないと成り立たない。読める AI（新しいセッションの Claude Code など、経緯を渡さない条件）で同じ依頼書を試し、Gemini君は読める環境が整ってから改めて迎える | 2 が難しければこれ |

## 6. 新しい会話と zip での確認（2026-11-06 02:16〜02:23、v0.3 で追記）

**一言で：Gemini君は、今の利用の環境ではリポジトリを読めない。読めないことは正直に言えた。**

| 試したこと | 結果 |
|---|---|

| リポジトリの写しの zip（1,187 ファイル、約 27 MB、`ed4cba2`）をアップロードし、確認の三問を聞いた | 「zip を解凍して中身を正確に読み取ることができない」と答えた。三問とも答えなし |

**観察した事実**：前の会話（§5）では、読めないのに中身を作って「読めた」と答えた。新しい会話では、URL でも zip でも「読めない」と正しく答えた。

**実務の教訓**：誤った前提が残った会話では、回答を信頼できないため、新しく始め直した。**振る舞いが変わった原因（会話の中に積もった前提によるものか）は、今回の観察だけでは確定できない**（仮説として残す。GPT君）。

**評価の区分**（環境の制約を、Gemini君の理解力や BS-SEAF の成否と混同しないため。GPT君）：

| 区分 | 結果 |
|---|---|
| 環境の確認 | 課題に要るリポジトリの原本を取り出せず、作業を中断した |
| 知識の検索・理解・再利用 | 原本に基づく評価は**未実施** |
| 確かめた状態の申告 | 最初の会話では問題があった（読めていないのに読めたと申告）。新しい会話では、制約を正しく申告した |

**判断（Claude君・GPT君の推奨、大杉さんの決定待ち）**：今回の 4 回目の試行では、**Gemini君の参加を見送る**。同じ依頼書を、リポジトリを読める別の担当で試す。Gemini君は、リポジトリを読める利用の環境（コードの取り込みの機能など）が使えるようになってから、改めて迎える。代わりの担当は、経緯を引き継がない新しいセッションの Claude Code（依頼書 `requests/RequestLetter_BSSEAF_Cosmetics_MinimumSupply_Reallocation_to_NewAgent.md`、試験の条件 `docs/development/WOM_BSSEAF_Loop4_TestConditions.md`）。Gemini君の作業計画とこのレビューは、履歴としてそのまま残す。
