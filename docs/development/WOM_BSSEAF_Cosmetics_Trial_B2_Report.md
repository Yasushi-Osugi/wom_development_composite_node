### 3.4 B3 の作り置きと、warmup の週の cap_soft

**52 週を超える lot（B3）**：

- 195 lot、すべて代理店（`SG_Distributor`）の lot。需要週は 2028-W04〜2029-W50、工場の出荷週は 2026-W44〜2027-W06、滞留は 53〜163 週。
- 待った場所は**すべて supply point**（工場の完成品在庫、前回の Q5）。DC・倉庫・店では待っていない。
- 作り置き（滞留がリードタイムより長い lot）は SKU ごとに **130 lot**。これは、需要が良品の平準化の上限を 1 lot 上回る週（直営店が定常になる 2027-W27 から 2029-W52 までの 130 週）× 1 lot とちょうど同じ。Backward がこの不足を一つずつ前の週の余裕へ押し戻し、押し戻しが立ち上げの 13 週と warmup の期間まで遡って、そこで作られた 130 lot が最長 3 年待つ。130 lot のうち 65 lot（2 SKU 合計）は 52 週以内に出ていく。
- 代理店の lot だけが作り置きになるのは、Backward の押し戻しが**工場の需要のリストの後ろの lot**（`s_lots[cap_int:]`）を前の週へ送るため。このモデルではリストの後ろが代理店の lot だった。どのチャネルの lot が古くなるかは、業務の規則ではなくリストの並びで決まっている（§4.2）。

**warmup の週の cap_soft が空になる**（設計書・依頼書に無かった発見）：

- headless の起動時の warmup の materialize（`wom/engine/warmup.py`）は、warmup の 17 週の能力の行に**`max_supply` だけを写し、`cap_soft` を空欄にする**（B3 の `capacity_plan.csv` で warmup の 34 行すべて `cap_soft` が空欄）。materialize は最初の需要週より前の行を消して作り直すので、手で書いても同じになる。
- soft の工場は、cap_soft が未設定の週では充填の目標が cap_hard の良品の上限に戻る（`backward_planner.py` の `_apply_mom_cap_backward`：`soft かつ cap_soft あり` のときだけ cap_soft）。そのため B3 では、押し戻しが warmup に入ると、その週は 12 ではなく **15（Serum）・11（Cream）**まで作る（V06 (a) が上限ちょうどになった理由）。Forward の cap_soft の記録も、warmup の週は cap_soft が無いので数えない（V06 (b) が 0 の理由の一部）。
- **B3s（warmup にも cap_soft を入れた参考）**：工場は全期間 12・9 で平準化し（最大 P 12・9）、作り置きの開始が 2026-W47・W42 に早まる（B3 は W48・W44）。それでも**52 週超は 195 lot（最大 165 週）、作り置きは 130 lot／SKU で B3 と同じ**。→ warmup の cap_soft の空欄は「warmup の週の作り方の形」を変えるが、B3 の結論（不足の分だけ作り置きが起き、52 週を大きく超える）は変わらない。
- **数量の保存・充足には影響なし**（B3・B3s とも V01 OK、注文残 0）。

## 4. BS-SEAF の記録

### 4.1 B2：前回の誤り（設計書 §8.2 E1・E2）を直した結果

| 誤り | 直した Mapping（設計書 v0.3 §3.1） | 表せたか |
|---|---|---|
| E1 店頭在庫 | `SG_Store` の `init_stock_days`＝14 | **表せた**。X2 を leaf_out に置く使い方（どのサンプルにも無い）で、店頭在庫が `SG_Store` の I に立った。lot はすべて需要の Lot_ID 付きで、計画の中で作られている（外から置いていない） |
| E2 envelope | `Factory_JP` の `demand_envelope`＝soft | **表せた**。B2 では上限がピーク需要と同じなので前倒しは起きず、B3 で soft の前倒しが起きることで、定義（Production_Qty × 歩留まり）どおりに計画していることが確かめられた |

**店頭在庫を「開店前から常に 2 週分」と読めるか**：

- **読める**。X2 は数量ではなく時間（その lot の需要週の 2 週前に着く）なので、店頭在庫は「これからの 2 週分の需要」になる。定常（2028 年）では毎週 8・6 で減らない。
- ただし **2 週分の量は需要に比例する**：開店の直前は 4・4（立ち上げ 2 lot／週 × 2 週）、定常になって 8・6。「開店時に 8 lot 並べる」という意味ではない。開店時に定常の量を並べたい業務なら、X2 では表せず（X2 は時間で持つため）、別の表し方が要る。
- 計画の最後の 2 週は、計画期間の外の需要が無いので 0 に向けて減る（どのモデルにも出る端の効果）。

**既存の知識の適用条件（前回の誤りからの教訓）**：X2 は「lot ごとに着く週を早める」仕組みで、需要が 0 の週（開店前）より前には効かない（開店前の 2 週＝W12・W13 にだけ在庫ができ、それより前は 0）。

### 4.2 変更課題⑤（B2 → B3）：知識の再利用と手間

| 項目 | 内容 |

**Core の変更が要りそうな所（変えずに報告）**：

1. **前倒しの上限が無いことと、残存期間の要件がぶつかる**（Start Here §7 の課題が、初めて業務の要件として数字に出た）。歩留まり 0.90 で能力がわずかに足りないと、WOM は不足を前倒しで全部まかない、充足 100%・注文残 0 の計画を作る。その代わり 195 lot が使用期限の残り 24 か月を割る（工場の出荷から最長 163 週）。業務としては「残存期間を割ってまで作り置きしない（＝注文残にする）」か「能力を足す」かの判断になる。WOM がこれを計画の中で守るには、前倒しの深さに上限（例：最大で何週前まで）を持たせる仕組みが要る（Backward の carry-back。保護対象コア）。今は「検出」（判定の道具）で見つけられる。
2. **作り置きになる lot がリストの並びで決まる**：古くなる lot がチャネルの規則でなく、Backward の押し戻しの順（リストの後ろ）で決まる。代理店（sell-in）の lot が 3 年待つのは業務の意味としては不自然。先入れ先出し（作った順に古い需要へ）にするかは、上の 1 と合わせて決める課題。
3. **warmup の materialize が cap_soft を写さない**（`wom/engine/warmup.py`）：soft の工場では warmup の週の平準化が効かず、cap_soft の記録も数えられない。直すなら、materialize が `cap_soft` の列も最初の実週の値で写す（`wom/engine/warmup.py` は保護対象コアではないが、golden への影響を調べる必要がある。warmup を使い、cap_soft の列を持つモデルがあれば計画が変わる）。
4. **`init_stock_days`／`ss_days` の空欄で木の読み込みが止まる**（§2）：止まること自体は「黙った既定値を作らない」に合うが、メッセージが `cannot convert float NaN to integer` だけで、ファイル・行・列が出ない。`yield_rate` と同じ形のメッセージにするか、空欄＝0 とするかの判断が要る（`sc_tree_builder.py`）。

## 5. 第5段階で大杉さんに決めてほしいこと

1. **B3 のように前倒しが残存期間を割るときの業務の扱い**：
   - (a) 能力を足す（cap_soft を上げる＝シフトを増やす）、
   - (b) 残存期間を割る前倒しをしない（注文残として出す）、
   - (c) 計画は今のまま、判定の道具で検出して人が見る。
   (b) を WOM で守るには、前倒しの深さの上限が Core に要る（§4.2 の 1）。(c) なら今のままで進める。
2. **作り置きになる lot の順**（§4.2 の 2）：先入れ先出しにするか。1 と一緒に決めるのがよい。
3. **warmup の materialize が cap_soft を写さない件**（§4.2 の 3）：変更課題①（海上 4 週、warmup が足りるか）に進む前に直すか。①では warmup の週の工場の作り方が結果に効くので、先に直すほうが読みやすい。
4. **`init_stock_days`／`ss_days` の空欄**（§4.2 の 4）：空欄＝0 とするか、メッセージを直して止めるか。
5. **店頭在庫の意味**（§4.1）：「次の 2 週分の需要」（X2、開店時は 4 lot）でよいか。開店時から定常の量（8 lot）を並べたいなら、別の表し方を検討する。
6. **残存期間の判定の道具**（設計書 D9）：B3 で 52 週超が 195 lot 出て、判定が意味を持った。`tools/` に入れるか（入れるなら入力は `records.build_records`、起点は工場の出荷週）。
