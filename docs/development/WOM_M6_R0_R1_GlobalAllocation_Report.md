## 3. R0 の偏りの原因（読むだけで調べた）

### 3.1 仕組み

1. **Backward**：市場の要求は、出荷側の木を子から親へ（post-order）、リードタイムの分だけ前の週へ移される。親の週の lot の並びには、子の順に lot が足される。子の順は `sc_tree_master.csv` の行の順で、FG 倉庫の子は DC_US_SF・DC_US_NY・DC_JP・DC_EU_RTM、欧州の DC の子は FR・BE・NL。このため瓶詰の工場（`Bottling_Noda`）の各週の lot の並びは、**米国西 → 米国東 → 日本 → フランス → ベルギー → オランダ** になる。
2. **瓶詰の能力**（`_apply_mom_cap_backward`）：週の並びの先頭から能力の数（21 シフトで 800）だけを残し、残りを前の週の並びの**最後**に足す。前の週でも自分の週の lot が先に並ぶので、繰り越した lot はさらに前へ押され続ける。計画の最初の週（2026-W28）を超えた lot は落ちる。
3. **最初の 7 週**：プッシュの設定（`push_lead_time_weeks` ＝ 7）は、瓶詰の 7 週前に原料を買う。瓶詰の計画が最初の 7 週（2026-W28〜W34）に置かれた lot は原料が買われず、作られない。醸造（LT 4 週）・原料（LT 2 週）が計画の前に当たる lot も Backward で落ちる。

### 3.2 証拠（21 シフト、C02）

`sc_tree_master.csv` の行の順だけを入れ替えた写し（欧州の DC を先に、その子を NL・BE・FR の順に）で、同じ計画を回した（付録 `r0/order_test/`）。

### 3.4 18 シフトでフランスも欠け、21 シフトで増分がフランスに回った理由

同じ並びで能力が 686 のとき、残るのは 175 ＋ 175 ＋ 300 に、フランスの 150 のうち 36 まで。フランスの 114・ベルギー 100・オランダ 100 が毎週はみ出す（付録 `r0/C01/`）。21 シフト（800）では能力がちょうどフランスの終わりまで届くので、増えた 114 lot／週はすべてフランスに回った。

### 3.5 申し送り（エンジンは変えていない）

原因は保護対象のコアの `wom/engine/backward_planner.py`（`_ot_propagate` の lot の足し方と、`_apply_mom_cap_backward` が並びの先頭を残すこと）にある。配分をしないときの「誰を後回しにするか」が、業務の判断ではなく CSV の行の順で暗黙に決まっている。直すなら、別の依頼で、保護対象のコアの手続き（3 層テスト・golden）に従う。
