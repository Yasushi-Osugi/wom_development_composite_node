### B1 使える週の数え方（入力だけで固定）

読むのは `demand_forecast.csv`・`capacity_plan.csv`・`sc_tree_master.csv` だけで、実行の結果は読まない（`build.py` の `usable_weeks()`）。

### 読み取り

- **最後の週の形は、期間が変わっても同じ。** A3 の終わりはどの期間でも最後の週の 2 週前で、最後の 2 週は全量に戻る。需要データの終わりから生じる形（前回の §6）で、延ばすとその形が後ろへ移る。
- **E0 → E13 の変化と E13 → E26 の変化は別の形。** A3 の共通の期間の ③ は E0 の 192 から E13 で 206 に増え、E26 でも 206 のまま。増えた 14 lot は 2029-W51・W52 の分で全部。鍵の間の比例の分け方は延ばすと変わるので、週の合計が同じでも、SG と TH の分け方は少し違う（鍵・週で 18 と 24）。
- **代理店の率は鍵によって上下した。** A3 の後半の率は、SG 美容液 62.5 → 61.5 → 63.5%、TH 美容液 75.0 → 70.3 → 67.2% で、同じ向きに動かない。週の最低は SG 美容液 50%、SG クリーム 40% のままで、期間を延ばしても戻らなかった。前半は全鍵 100% のまま。
- **A0e は外す量が増えた分、全期間の率が下がる。** 代理店の共通の期間の率は 91.62 → 89.06 → 86.84%。A3 は 91.79 → 91.20 → 91.20%。

## 6. 止める理由と申し送り

申し送り：

1. **毎期の作り直しではない**：今回は一度に長い期間を計画した。計画を毎期作り直して、実績・在庫・未充足を引き継ぐときの動きは調べていない（判断資料 §2.3）。
2. **B1 の数え方の前提**：工場が一つで、能力の行がそろうモデルで確かめた。`_sku_resources()` の私的な関数を `build.py` から使っている。ほかのモデルに広げるなら道具に切り出す必要がある。
3. **共通の期間の評価の額**：共通の要求週の ④ だけを数えた。E13・E26 は 2030 年の分の貢献利益を含まないので、E0 より小さい値になる。これは期間を切り分けた比較で、案の優劣を直接示すものではない。
4. **smoke の 1 skipped**：前回 1 回目だけ出た件の理由は未特定。今回の `--smoke` は skipped 0 で再現しなかった。
5. **Lot_ID の滞留**：52 週超の lot は A3 で 447 のまま。A0e は 471 → 479 → 489。年齢とは別の数で、原因は調べていない。
