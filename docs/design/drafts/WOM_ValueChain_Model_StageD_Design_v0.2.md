## 0. v0.1 からの変更（Astra君のレビューによる）

1. V1 → V2 → V3 の間の**二種類の調整**を明記した（§1）。V2 は V1 の単純な合計ではない。
2. 記録を**出荷の記録・金額の明細・在庫と加工の記録**の三つに分けた。「出荷と 1 対 1」は出荷の記録だけ（§2）。
3. 加工・組立（Kitting）での原価の引き継ぎの例を加えた（§3・§4）。
4. 第 1 回と第 2 回の境目を直した。**在庫原価の台帳と warmup からの原価の接続は第 1 回**、内部の未実現利益の消去が第 2 回（§6）。
5. warmup についての v0.1 の書き方を直した。「今の PPC が原価を販売週にまとめている」ことだけでは、費用の欠落や利益の過大は証明されない。正しくは「発生週で計上する新しい方式に移るとき、期首の原価を引き継がなければ欠落する危険がある」（§6）。
6. 為替は、単一通貨の手計算で確定した後に、二通貨・別の週の例を 1 つ加えて決める（§5）。
7. 外部の相手は、一括して「外部」とせず、相手の ID を持たせる（§2.3）。今の移転価格が「法人間の価格」か「法人内の管理価格」かは、法人の割当（§7）で決まる。

## 1. 三つの視点と二つの調整

| 視点 | 内容 |
|---|---|
| V1 ノード・区間の管理評価 | 全ノードで、実出荷した Lot 数 × Lot 単価。同じ法人の中の移動も、管理価格で売上・仕入を立てる |
| V2 法人別の損益 | 法人ごとの外部・他法人への売上と、その原価 |
| V3 グループ全体 | 連結の範囲から外部への売上と、その原価 |

| 集約 | 必要な調整 |
|---|---|
| V1 → V2 | **同じ法人の中の管理売上・管理仕入を除く。** 管理価格に含めた内部の利益を、法人の在庫・原価に持ち込まない（法人の在庫は、その法人が外部または他法人から得た原価で持つ） |
| V2 → V3 | **連結範囲の中の法人間の取引を消す**（売上と仕入）。第 2 回で、グループの在庫に残る内部の未実現利益も消す |

## 2. 記録の三つの種類と識別

### 2.1 出荷の記録（出荷の事実。LOVEM の実出荷と 1 対 1）

誰が、何を、いつ、誰へ渡したか。

| 項目 | 例 |
|---|---|
| 計画 ID | 計画の実行ごとの識別子（P1 で作った `ppc_run_info` の計画 ID） |
| 出荷イベント ID | 1 件の出荷を一意に表す |
| Lot_ID | 需要の Lot_ID |
| 品目の区別 | 完成品か、部材（どの部材か）か。Kitting では同じ Lot_ID に複数の部材が対応するため |
| 出荷ノード・受け手 | 受け手はノード、またはモデルの外の相手（§2.3） |
| 区間 | edge（受け手がモデルの外なら空） |
| 出荷週・到着週・売上認識週 | 第 1 回は「出荷時に支配が移転する」前提で、売上認識週＝出荷週 |
| 数量 | lot 数と物量（単位を明記） |

### 2.2 金額の明細（1 件の出荷から複数生まれる）

売上、売上原価、運賃、関税、保険、内部取引の消去など。各明細は、どの出荷の記録から生まれたかを持つ。

**出荷の無い週にも生まれる明細**がある：在庫の保有費用（§3.3）。これは在庫の記録から生まれる。

### 2.3 在庫と加工の記録

どの原価を、どの法人・ノードが、どの週に保有しているか。どの部材の原価を完成品へ引き継いだか。

### 2.4 モデルの外の相手

- 最終市場からの顧客への販売など、相手のノードや区間が無い取引も表す。
- 外部の相手は**相手の ID**を持つ（例：`EXT_CUST_JP_RETAIL`、`EXT_SUP_CN_INGR`）。連結範囲の外として分類する。同じ物流モデルで、連結範囲を変える実験ができるようにする。

## 3. 原価の増え方と引き継ぎ

### 3.1 どこで原価が増え、どこへ引き継がれるか

| 場面 | 原価の扱い |
|---|---|
| 購入（外部の供給者から） | 仕入の価格が在庫原価になる |
| 輸送（仕入側・移動のため） | 運賃・関税・保険は、物を今の場所にするための費用として**在庫原価に含める**（IAS 2） |
| 保管 | 在庫の保有費用は**その週の費用**（在庫原価に含めない。管理上の独立した項目） |
| 加工・組立 | 部材の原価＋加工費が完成品の原価になる（§3.2） |
| 販売 | 在庫原価を売上原価として払い出す。販売のための運賃はその週の費用 |

### 3.2 組立（Kitting）の例

```
部材 A の原価 30 ＋ 部材 B の原価 40 ＋ 組立の加工費 10 → 完成品の原価 80
```

- 部材を完成品へ振り替えるとき、**部材の在庫から 30・40 を払い出し、完成品の在庫に 80 を入れる。** 部材の在庫と完成品の在庫の両方に同じ原価を残さない。
- Kitting Gate の成立の記録（どの Lot_ID で、どの部材がそろったか）を、この振替の根拠にする。

### 3.3 在庫の保有費用

Lot・週あたりの管理上の保有費を独立した項目として持つ。倉庫費や資金費用と重ならないよう、モデルごとにどちらか一方で設定する。

## 4. 週ごとの手計算表（単一通貨、1 Lot）

設定：部材 A（外部の供給者 S1 から 30）、部材 B（外部の供給者 S2 から 40）、工場 F（法人 E1）で組立の加工費 10。F から販売会社 D（法人 E2、連結の範囲内）へ、法人間の価格 100 で販売。F→D の運賃 5 は D が負担。D から外部の顧客へ 150 で販売し、販売のための運賃 3 は D が負担。保有費用は 0 とする。

| 週 | 出来事 | E1（工場）の損益 | E1 の在庫 | E2（販社）の損益 | E2 の在庫 | V3 グループの損益（第 2 回の完成形） | グループの在庫（同） |
|---|---|---:|---:|---:|---:|---:|---:|
| W1 | 部材 A・B を仕入れ | 0 | 70（部材） | 0 | 0 | 0 | 70 |
| W2 | 組立（加工費 10）→ 完成品 | 0 | 80（完成品） | 0 | 0 | 0 | 80 |
| W2 | F → D へ出荷（100、運賃 5 は D） | 売上 100、原価 80、**利益 20** | 0 | 0 | 105（輸送中、D の所有） | 内部の売上 100 と仕入 100 を消去、内部の利益 20 も消去：0 | 85（80＋運賃 5） |
| W3 | D に到着 | — | 0 | 0 | 105 | 0 | 85 |
| W4 | D → 外部の顧客へ 150（運賃 3） | — | 0 | 売上 150、原価 105、運賃 3、**利益 42** | 0 | 売上 150、原価 85、運賃 3、**利益 62** | 0 |

照合：E1 の利益 20 ＋ E2 の利益 42 ＝ 62 ＝ グループの利益。V1 では、F・D の各ノードに売上・原価・利益がそのまま残る。

**第 1 回の見え方**（内部の未実現利益を消さない）：W2・W3 のグループの損益は **20**（「内部の未実現利益 20 は未消去」と表示）、グループの在庫は **105**。W4 に販売されると、第 1 回でも第 2 回でも、グループの利益は 62 になる（第 1 回では W2 に 20、W4 に 42 と、計上の週がずれるだけ）。

**売れ残りの場合**（W4 に売れず、期末に D の在庫に残る）：

| | E1 | E2 | グループ（第 1 回） | グループ（第 2 回） |
|---|---:|---:|---:|---:|
| 利益 | 20 | 0 | 20（**「内部の未実現利益 20 は未消去」と表示**） | 0 |
| 在庫 | 0 | 105 | 105 | 85（内部の利益 20 を消去） |

次の変化を 1 つずつ加えて表を増やす（v0.2 の確定までに、Claude君が作って大杉さんと合意する）：

1. F と D が**同じ法人**の場合（管理価格 100 は V1 だけ。V2 で除く）
2. D が**連結の範囲の外**（外部の取引先）の場合（E1 の売上 100 がグループの外部売上になる）
3. 輸送中に**期末**を迎えた場合
4. 仕入・組立が **warmup の助走週**に起きた場合（期首の在庫原価として報告の開始時点へ引き継ぐ）

## 5. 為替（D-4）

単一通貨の §4 で確定した後に、次の 1 例を加えて決める。

- F は中国の法人（CNY）、D は日本の法人（JPY）。法人間の価格は JPY で決め、W2 に出荷、W4 に販売。W2 と W4 で為替が違う。

この例で決めること：

| 論点 | 案 |
|---|---|
| 取引を換算する週 | その取引の週の為替（出荷週） |
| 取得した在庫原価を、後の販売週に換算し直すか | し直さない（取得時の換算額のまま払い出す） |
| 法人間の取引の売り手・買い手・消去で、同じ換算の根拠を共有するか | 共有する（同じ出荷の記録の為替を使う）。これで、換算の方法だけから消去の差が生まれないようにする |
| 為替換算差額 | 第 1 回・第 2 回とも扱わない。報告通貨での比較だけを行う |

## 6. 第 1 回と第 2 回の境目（修正）

| 第 1 回に必要なもの | 第 2 回へ回すもの |
|---|---|
| 出荷の記録・金額の明細・在庫と加工の記録（§2） | グループの在庫に含まれる内部の未実現利益の消去と、販売時の解除 |
| 法人別の在庫原価の台帳（受け入れ・払い出し・残高） | |
| **warmup の助走週から、報告の開始時点への在庫原価の接続**（期首の在庫原価） | |
| 販売時の原価の払い出し、Kitting での原価の振替 | |
| V1 → V2 の調整（同じ法人の中の取引の除外）、V2 → V3 の法人間の売上・仕入の消去 | |

- 完全な貸借対照表は作らない。**売上原価を説明するための在庫原価の台帳**を第 1 回に含める、という意味である。
- warmup について：今の PPC は原価を販売週にまとめて計上しているので、今の方式では助走週の費用は販売された lot の原価に含まれている（Flow Check・warmup の報告書 §5.5）。**新しい方式（発生週で記録し、在庫原価として持つ）に移るとき、助走週に積み上げた在庫原価を報告の開始時点へ引き継がなければ、費用が欠落する危険がある。** これを防ぐのが、上の「warmup からの接続」である。

## 9. 第 1 回の受入条件（案）

1. §4 の手計算表（売れ残り、同じ法人、連結範囲の外、期末の輸送中、warmup の各変化を含む）を、実装が同じ数字で再現する（単体テスト）。
2. Cookie と soysauce-jpy-alloc で、次が成り立つ。
   - 出荷の記録が、LOVEM の実出荷のイベント（Flow Check の実出荷 Σ）と件数で一致する。
   - V1 の全ノードの売上・原価・利益が、出荷の記録と単価から説明できる（金額の明細から出荷の記録へたどれる）。
   - V2 の法人の売上の合計 − 法人間の売上 ＝ V3 の外部売上。
   - V3 の外部売上 ＝ 連結範囲から外部の相手への出荷の記録 × 外部の価格。
   - 在庫原価の台帳で、期首（warmup からの接続）＋ 受け入れ − 払い出し ＝ 期末。
3. 利益の表示には、第 1 回では「内部の未実現利益の消去は未実施」と明記する。
4. 今の PPC の結果との対応表（どこが同じで、どこがなぜ違うか）を報告する。
