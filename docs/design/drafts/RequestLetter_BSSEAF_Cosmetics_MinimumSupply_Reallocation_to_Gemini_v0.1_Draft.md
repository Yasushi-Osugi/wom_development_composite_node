## 0. 今回の業務要求と検証目的

### 0.1 業務要求

> 採用済みの「代理店への最低供給量5割」の化粧品計画を基準に、タイの代理店へ届けるクリームだけは、各要求週の元需要の7割以上を当週に届けたい。端数はlot単位で切り上げる。工場能力を増やさず、シンガポールとタイのクリームの配分数量を見直すことで、この条件を満たせるか調べたい。

これは新しい試行のための要求案です。現在の採用済み計画を自動的に置き換えるものではありません。新しい案の採否は、試行結果を見て大杉さんが判断します。

### 0.2 BS-SEAFとして確かめたいこと

Gemini君が、Start Hereから業務の意味・既存機能・適用条件・根拠へ辿り、新しい要求に対する作業計画を作れるかを確かめます。

- リポジトリにある知識を、自分で発見して根拠付きで使えるか。
- 業務要求と現行モデルの差を、Data／Parameter／既存の道具／実装変更に分けられるか。
- 計画として選ぶ量と、制約下で実際に届く量を分けて確認できるか。
- 分からないことを推測で埋めず、調査の限界と人の判断が必要な事項を示せるか。

コードを変更しないことだけを成果にはしません。変更の必要性を、意味と実装の対応から説明することを重視します。

## 2. 基準案と変更できる範囲

基準は、化粧品の**能力不足の写しに、採用済みの最低5割方針を適用した案**です。正式サンプルそのものの能力設定と、この試行の設定が同じとは仮定しないでください。

基準案の作り方、数量枠、方針ファイル、週別規則、プラグイン、実行手順、既存結果を、リポジトリから特定します。数量と条件には、根拠ファイル・節を添えます。

| 項目 | 今回の扱い |
|---|---|
| 元の需要 | 基準案と同じ。数量、要求週、需要の性質を変えない |
| 計画期間・助走期間 | 基準案と同じ |
| 工場能力・歩留まり・LT・在庫方針・操業条件 | 基準案と同じ |
| SKUごとの供給対象総量 | 基準案と同じ |
| 直営店・ECの配分数量 | 基準案と同じ |
| 美容液の配分数量と最低供給方針 | 基準案と同じ |
| SG代理店のクリームの最低供給方針 | 基準案と同じ5割・切り上げ・必須 |
| TH代理店のクリームの最低供給方針 | 新しい条件として7割・切り上げ・必須 |
| 変更できる配分数量 | クリームのSG代理店とTH代理店の間だけ。2代理店の合計は維持する |
| 使用期限・納品年齢の条件 | 基準案の条件を維持し、根拠と閾値を特定する |

最低7割を満たすために、需要を減らす、切り捨てへ変える、最低率を下げる、といった変更は今回の要求変更になります。数量枠の変更案と混ぜないでください。

## 3. Gemini君にお願いする調査と計画作成

### 3.1 入口から知識を取得する

次を、根拠ファイルと節を付けて短く整理してください。

1. BS-SEAFの8段階と、今回の作業がどの段階に当たるか。
2. Managementの配分判断、Backwardの配置、Forwardの供給計算の役割分担。
3. 元需要、供給対象、未配分、実納品、配分後の未充足の意味と数量の関係。
4. 最低供給量を、選択時と当週の実納品の二段階で確認する理由。
5. 業務条件の衝突、実納品での条件未達、入力・計算の不整合の違い。

本文の実際の記述、コードで確認したこと、既存報告書で実行が報告されていること、自分で実行したことを区別します。AIの回答や公開記事の要約だけで、コードを確認したことにはしません。

### 3.2 基準案を特定し、再現する計画を作る

基準案を構成するモデル、数量枠CSV、方針CSV、週別規則、CLI、既存報告書を特定してください。

最初の成果物では、再現の実行手順と、照合する数量・条件・ファイルを示します。資料の数値を再集計した場合はその方法を記録します。WOMを再実行していなければ「再実行は未実施」と書いてください。

### 3.3 新しい条件と数量枠の関係を調べる

- TH代理店のクリームについて、各要求週の最低数量を元需要×7割の切り上げで求め、その合計と基準の数量枠を比べる。
- 必要なら、SGとTHの配分数量をどう変更するか、候補と理由を示す。過去の案を再利用する場合は、所在と今回への適用条件を確認する。
- SGの最低5割と、変更できない数量・条件も満たしているか確認する。
- 最低数量の合計が数量枠以下でも、当週に納品できるとは断定しない。時間の制約と実納品の確認は、後続の試行に含める。

配分数量の正解値や、再利用すべき過去案の名前は、この依頼書では指定しません。根拠から導いてください。

### 3.4 既存機能との対応と差を整理する

既存機能について、所在、有効化の条件、入力、処理間の受け渡し、出力と確認方法を調べます。

「今回使えない」場合も、「WOMに機能がない」と即断せず、調べた機能、使えない理由、追加で必要な表現を示してください。新しい配分エンジンやCore変更を前提にせず、まず既存経路で表せる範囲を確かめます。

提案には、変えるCSVと行の条件、パラメータ、使用する既存の道具、必要であれば実装変更の候補を分けて書きます。本依頼の最初の範囲では実装変更は行いません。

## 5. 後続の試行をどう検証するか

この節は作業計画に盛り込む確認事項です。モデル実行とその担当は、計画レビュー後に正式な依頼範囲へ定めます。

| 観点 | 比較・確認すること |
|---|---|
| 比較条件 | 基準の最低5割案と、今回の変更案。同じ元需要・期間・判定時点・単位・受渡点を使う |
| 数量 | 元需要＝供給対象＋未配分、供給対象＝実納品＋配分後の未充足。SKU・チャネル・要求週へ戻して確認する |
| 最低供給量 | 各要求週の選択量と、その需要に対応する当週の実納品の両方が下限を満たすか |
| 時間の制約 | 事前の診断は参考値として扱い、実納品と未充足は計画実行後に照合する |
| 他市場への影響 | SGのクリーム、直営店、EC、美容液への影響。削減の開始週・長さ、週の最低充足率も比較する |
| 在庫・納品年齢 | 作り置きとFIFOの年齢。Lot_IDの滞留を物の年齢と混同しない |
| 金額 | 追加評価する場合は既存の仮定と比較方法を明示する。数量配分モードの財務未評価を0円と読まず、比較評価額を営業利益と呼ばない |
| 根拠 | 入力・方針・数量枠のファイル、版、実行commit、プラグイン、実行者、出力先を記録する |

業務条件を満たせない結果も、有効な検証結果です。原因と試した範囲を残します。一つの候補が未達だっただけで、すべての配分に解がないとは断定しません。
