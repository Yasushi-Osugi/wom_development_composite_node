## 1. TOBE：経営トップが何を問い、何を見て、何を決めるか

> **どの製品を、どの市場・チャネルに、いつ、どの条件で投入し、どの順番で供給能力を整えると、狙った事業成果を実現できるか。**

製品×市場のマトリクスを、事業の打ち手を選ぶ入口にする。各セルで立てた需要の仮説を週次の供給計画に接続し、**需要がどれだけ見込めるか、制約の下でどれだけ届けられるか、その結果どれだけ売上・コスト・利益が動くか**を一つのシナリオとして比較する。

| 経営上の問い | コックピットで見て操作するもの | 決めること |
|---|---|---|
| どこに、どんな価値を届けるか | SWOT・ブルーオーシャンの検討結果を、製品の訴求点と候補市場としてマトリクスに置く | 検討する製品×市場、狙う顧客と提供価値 |
| 何を変えると、どの需要が動くか | 4P（製品・価格・販売チャネル・販促）の仮定と、そこから見込む週別需要の根拠・幅 | 投入週、価格、チャネル、販促、需要の基準案と上下振れ |
| 実際にどれだけ届けられるか | 需要の基準案、供給対象の需要、実行可能な供給、未配分・配分後の未充足、制約と在庫の時系列 | 供給の優先方針、能力を足す時期、投入時期の見直し |
| どの順序で進めるか | What-Ifの比較。売上・コスト・試算利益の推移、供給不足、前提や未評価項目。差が出た週から理由をたどる | 採用する施策の順序と条件。前提が変わったときの見直し点 |

**「最善の道筋」の意味。** `the best path` は、比較した施策の順序の中で、合意した評価指標と制約に照らして推奨できる道筋を指す。どの制約が効き、どの前提が変わると判断が変わるかも示す。例えば、供給水準を満たす案の中で累積の試算利益を比較する。優劣を決めるのに必要な費用が未評価なら、その前提で判断できる範囲を示す。

**WOMとの接続。** 4Pは需要の根拠となる業務仮定。**初回から、投入の表（製品×市場・チャネルごとの投入週・定常の需要・立ち上がり・価格・販促の前提）を入力として残し、そこから週別需要を作る**（エンジンの外の小さな道具。価格と販促は初回は記録だけで、需要への効果を推定するのは次の段階）。シナリオの製品・市場・チャネル・週を、既存需要CSVの `sku_id`・`region`・`week`・`quantity` に対応させる（`region` は需要の販売先・チャネルを指すキー）。既存の上位Demand Planを使う場合は、元需要、供給対象、除外理由を記録する。Backwardで配置し、Forwardの実行結果から供給量・未充足を読み、Value Chainで採用ルールに従って金額を評価する。需要仮説・配分・実行結果・金額を同じシナリオからたどれるようにする。

## 2. 現在の到達点と、金額基盤の棚卸し

化粧品の正式サンプル `cosmetics-sg-th-2027-2029` では、採用したG1〜G5の規則を代表ロットと全期間で照合済み。G4では、タイ向けで指定した区間の課税価格に価格未算入の運賃を一度だけ加え、G5では、シンガポール向けの指定区間の海上運賃を売り手が負担するようにした。G5の法人別の利益は変わり、消去後の連結利益とグループ在庫は照合上不変だった。正式サンプルの税率0%の条件では、Value ChainとPPCの全期間の利益差は0円。税率30%の感度試行では、課税価格の定義差により関税差347,256円が残る。照合では、差の有無とともに、どの規則・区間・週・法人から差が出たかを確かめる。

確認範囲は、架空のサンプルに採用した規則。店舗運営費は売上比率での近似、日本本社の固定費は未設定、歩留まり損は原価に未反映であり、表示する利益は**設定済みの範囲の試算利益**。他サンプルでの適用可否と実務の金額定義は別に確認する。

**方針：確かめる範囲は全サンプル、直す順は影響で決める。** 最初の比較の結論に効く不足を先に扱い、ほかは根拠付きで一覧に残す（WOM の基本機能としての整合は、この一覧で見える形にして進める）。**誤った金額が警告なしに出る共通の問題（運賃の二重計上など）は、初回比較の対象外でも優先度を下げない。** 全サンプルに同じ規則を一度に導入する計画は立てない。

棚卸し表 v0.1 は作成済み（[`requests/WOM_MoneyBase_Inventory_v0.1.md`](../../../requests/WOM_MoneyBase_Inventory_v0.1.md)、`1814788` の CSV とコードを読んだ結果。実行はしていない）。要点：

- 金額を業務と照合したのは化粧品だけ。Value Chain（法人別・連結）のマスターがあるのは 3 モデル。7 モデルは運賃がノードの費用に残り、そのままでは Value Chain で評価できない。
- **先に確かめるもの**：smartx で、同じノード×製品にノードの運賃と区間の運賃の両方がある組が 3（二重計上の疑い）。
- **最初の比較に効くもの**：週固定費（未実装）、在庫の保有費（未設定）。次に歩留まりの原価（未実装、水準に約 3%）。

棚卸しの起点にした観点は次のとおり。

| 観点 | 先に見る対象 | 確かめること |
|---|---|---|
| 運賃の置き場所 | `ev`・`oil` 系、Start Here R8 | 同じ輸送がノードと区間に重複していないか。Value Chainで評価できるか |
| 関税の区間と課税価格 | `soysauce` 系・`apparel` 系、R9 | 国境区間に置かれているか。課税価格に何を含むかが明示されているか |
| 評価に必要なマスター | `smartx` など | 価格・通貨・法人・取引の情報が揃うか。欠けていればどの評価ができないか |
| 採算を左右する費用 | 週固定費（F型）、歩留まりの原価反映（Part B）、在庫保有費 | 設定・実装・適用条件のどこに差があるか。どの経営判断を変え得るか |

棚卸し表は **対象／規則と適用条件／現状と根拠／金額・判断への影響／優先度** を列にする。「確認済み」「試行要」「対象外」を分け、未設定と明示の0も区別する。既存の試験・報告で判定できるものは根拠を示し、判定できないものには再現手順を添える。ここで金額を直すのは、最初に選ぶ経営判断に影響する範囲から。**初回の比較では、週固定費を WOM に実装せず、固定費を引く前の試算利益で比べたうえで、「週いくらの固定費なら案の順位が逆転するか」を別欄で示す。** 誰が負担し、契約・稼働のどの週から発生するかは GPT-MC君が定義する。例えば出店・撤退を比較するなら、F型の扱いを採算評価の前に決める。投入時期を比べる場合でも、在庫差や歩留まり損が案の順位を変え得るなら先に扱う。

## 3. 開発の順序と、次へ進む条件

| 到達点 | 作る・確かめるもの | 次に進める条件 |
|---|---|---|
| **1. TOBEと現状を合わせる** | 本文§1の経営上の問いと、§2の既存サンプルの棚卸し。既存GUI・Planning Stateの利用可否も照合する | 大杉さんが、最初に比べる案・評価指標・外せない制約を選ぶ。金額上の前提と未評価項目を特定できる |
| **2. 最小の事業計画比較を通す** | 問い：**今の供給能力でタイに早く入ると、追加で得られる利益に対して、どの市場でどれだけ供給を失うか。** 化粧品の写し（能力不足の条件 C3a）で、クリーム1製品・SG／THの2市場。SGの条件を固定し、タイの投入週だけが違う早期案と後期案を、**投入の表 → 週別需要を作る道具 → 既存WOM → 2案を並べる道具**で比較する。能力・計画期間・配分の方針は2案で同じ。対応は [`requests/WOM_Cockpit_FirstComparison_Mapping_v0.1.md`](../../../requests/WOM_Cockpit_FirstComparison_Mapping_v0.1.md) | 投入週の変更から、週別需要・供給不足（未配分と配分後の未充足を分ける）・試算利益の差までを、代表週・ロットからたどって説明できる。順位が逆転する週固定費を示せる。どちらの案が勝つかは条件にしない |
| **3. 対話型GUIにする** | マトリクスで案を複製・変更し、既存の計画・評価を実行して、2案の時系列と差の理由を表示する | 大杉さんがGUIで仮定を変更し、同じ設定を開き直して比較を再現できる。元需要と実行可能値を読み分けられる |
| **4. 適用範囲を広げる** | 複数製品と市場の組合せ、供給能力を変える案。棚卸しで選んだ別サンプルで同じ比較手順を試す | 共通に使える前提とモデル固有の前提を特定できる。必要なモデル変更を絞り、既存サンプルの期待結果への影響を確認できる |

初回の2案では、比較期間・助走期間・供給能力・評価に使う通貨や費用規則をそろえ、タイの投入週とそれに伴う需要の変化を明示する。早期案は需要をずらすのではなく足す（タイで売る期間が延びる）ので、不足の合計も増えうる。恒常的な能力不足なら、投入を遅らせても不足の始まりが後ろへずれるだけかもしれない。能力を足す効果は、同じ投入週で能力だけを変える追加の案で切り分ける。能力不足を作り置きで埋めた分は、在庫と製品の年齢（先入れ先出し、許容 52 週）で確かめる。期末の売上・在庫・未充足の差には、計画期間の切れ目による差が含まれ得る。変更した施策の影響と区別して読む。**まずこの比較が一度つながってから、GUIの画面構成を決める。**

旧ロードマップのPlanning Stateと経営上の問いに沿う画面案は、現行実装と照合し、使えるものを引き継ぐ。候補案・採用案・実行結果を結び付ける役割を生かし、4P・週別需要との接続に必要な差分を確認する。本案の採用後、合意した版をリポジトリの `docs/` に置き、Start Hereから案内する。旧ロードマップは経緯と設計材料として残し、新しい正本を示す。**BS-SEAF Loopの自動化は中断を継続**し、採用判断・適用条件・実行の根拠は人が確認して記録する。
