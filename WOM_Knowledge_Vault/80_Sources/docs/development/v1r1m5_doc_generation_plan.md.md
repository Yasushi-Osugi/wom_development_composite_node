````markdown
# WOM v1r1m5 Documentation Generation Plan

## Objective

WOM v1r1m5 prepares an AI-neutral Vibe Coding Ready Release.

The purpose of this documentation work is to move WOM development knowledge
from AI-specific context files and chat logs into repository-based Markdown documents.

## Source of truth policy

WOM repository documents should distinguish between:

1. Current implementation behavior
2. Design intent
3. Scenario assumptions
4. Open questions

Current implementation behavior should be derived from source code, tests, sample data,
and reproducible execution results.

Design intent may be derived from CLAUDE.md, note articles, prior design discussions,
and owner decisions.

If implementation behavior and design intent differ, do not hide the difference.
Record it as an open question or future refactoring item.

## Documentation tracks

### Track A: Implementation-derived documents

Generated by reading the current WOM source code and sample data.

Target files:

- docs/architecture/repository_map.md
- docs/architecture/runtime_entrypoints.md
- docs/architecture/planning_engine.md
- docs/architecture/plugin_architecture.md
- docs/architecture/ppc_engine.md
- docs/development/current_status.md

These documents should describe what the code currently does.

### Track B: Design-intent documents

Generated by reading CLAUDE.md, AGENTS.md, note articles, and prior design discussions.

Target files:

- docs/design/wom_canonical_concepts.md
- docs/design/demand_anchored_lot.md
- docs/design/inbound_outbound_tree.md
- docs/design/psi_ppc_separation.md
- docs/design/scenario_modeling_principles.md
- docs/development/ai_vibe_coding_workflow.md

These documents should describe why WOM is designed this way.

### Track C: Scenario documents

Generated from sample data and article explanations.

Target files:

- docs/scenarios/oil-global-2027.md
- docs/scenarios/japanese-rice.md
- docs/scenarios/smartphone.md
- docs/scenarios/cookie.md
- docs/scenarios/ev.md

These documents should explain scenario intent, fictional assumptions, model structure,
and how to run or inspect each scenario.

## Rules for AI agents

AI agents should not modify Python code during this documentation phase
unless explicitly requested.

AI agents should not silently change canonical WOM concepts.

Each document should include:

- Purpose
- Source basis
- Key files or concepts
- Current behavior or design intent
- Open questions

## Done criteria for v1r1m5

The release is considered documentation-ready when:

1. AGENTS.md exists as the AI-neutral entry point.
2. docs/ contains architecture, design, scenario, and development documents.
3. CLAUDE.md is no longer the only place where WOM context exists.
4. A new AI agent can start from AGENTS.md and understand how to work on WOM.
5. Implementation facts and design intent are clearly separated.
````
