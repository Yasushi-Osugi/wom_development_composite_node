前提: `79b78e1`（Phase 8-3b 実装・487 passed / 3 skipped）

## 0. なぜこの回が要るか — 実機で起きたこと

Phase 8-3b 追補・K2 で「子ノードでは『利益水準』ブロックを出さない」と決めた。
これ自体は正しい（値を変えないより、出さないほうが強い）。

しかし実機で、大杉さんが **「ドリルダウン機能が削除されている」** と判断された。

実際には削除されていない。バインドも `_on_child_click()` も無傷で、
Gate 0 条件4（降りられる枝にはバインドがある）も通っている。
**起きたのは、クリック対象が約200px 上へ跳ねたこと**である。

```
根（ALL）                          子（EUR）
  利益水準        <- 4行            （消える）
  注記            <- 5行            （消える）
  このノードの走査結果              このノードの走査結果   <- ここまで上へ跳ぶ
  JPY / EUR / USD                   SP_Oil_EU_Local / ...
```

**同じ場所を見ていた人には「消えた」と見える。** これは誤読ではなく、
画面が起こした誤解である。Phase 8-2・C1（結論行と子パネルが別々の配分を
無印で並べていた）以来の「黙って壊れる」欠陥家族に、**位置で誤解させる**
という新しい型が1つ加わった。

そして、この往復を消費してから分かったことがもう1つある。
**Gate 0 の6状態は、遷移を1つも通していない。**

```python
panel = AllocationPanel(root)
panel._view = view
panel._render(view)      # <- 常に「初期状態からの1回目」
```

K2 で入れた `_levels_header_visible` は状態機械で、`pack_forget()` する経路と
`pack(..., before=...)` で戻す経路は、**根→子→根と遷移して初めて走る**。
条件8（view の levels と描画行数が一致する）を足したときに「回帰で示された」
と判断したが、**塞げていなかった**——条件8が見ているのも1回描いたときの
整合だけである。これは依頼した私（Claude君）の誤りである。

## M1. 補助パネルのブロック順序を入れ替える

**大杉さんのご提案そのままである。**

> 「配分比率の表示とドリルダウンのクリック操作」の領域を右側パネルの最上部に
> 配置して、飛び跳ねを防止する。そして、その下に「利益水準」の領域を配置する。

### 原則

**常に在るもの・操作するものを上に固定し、条件つきで現れるものを下に置く。**

子ノード欄は葉以外のすべてのノードに在り、しかもクリック対象である。
利益水準ブロックは条件つきである。条件つきのものを上に置いたから、下にある
クリック対象が動いた。**順序を入れ替えれば原因が消える。**

空ブロックの高さを確保する案（Claude君の当初案）は採らない。原因を残したまま
症状を埋める対処で、**次に何かブロックが増えたらまた同じことが起きる。**

### 直すこと

`wom/cockpit/s1_allocate.py` の `__init__` で、`aux` フレームに pack する順序を
入れ替える。**ウィジェットの生成内容・ロジックは一切変えない。順序だけ。**

```
【現在】                          【変更後】
  1 利益水準 見出し                 1 子ノード 見出し      <- 常に在る・操作する
  2 利益水準 欄                     2 子ノード 欄          <- クリック対象
  3 注記                            3 利益水準 見出し      <- 条件つき
  4 子ノード 見出し                 4 利益水準 欄          <- 条件つき
  5 子ノード 欄                     5 注記                 <- 条件つき
  6 ノード情報                      6 ノード情報
  7 帯(円)行                        7 帯(円)行
```

`_levels_header_label` を隠す・戻す処理（`_render()` 内、K2）は**変えなくてよい**
——`pack(..., before=self._levels_frame)` は相対指定なので、スタック内の位置が
変わっても正しく戻る。**変えていないことを確認してほしい**（変える必要が
出たなら、それ自体が報告に値する）。

### 残る動きについて（承知のうえで受け入れる）

ノード情報と帯(円)行は、条件つきブロックの**下**に残るので、根と子で位置が
変わる。これは受け入れる。理由は2つ。

1. **帯(円)はドリルダウン中に連打する対象ではない**（クリック対象の跳ねとは
   深刻さが違う）
2. 入力欄を根拠の**上**に置くと、読む順序が壊れる

そして申し送りの L1〜L3（子ノードにその枝自身の利益水準を出す）を入れれば
**ブロックが条件つきでなくなるので、この残りも自動的に消える。**

## M2. Gate 0 条件9 — 遷移を通す

### 何を見るか

いまの6状態は「新しいパネルを作って1回だけ描く」。条件9は**1つのパネルを
実際に歩かせる**。

```
load() で根を描く
  → node["children"][0] を _on_child_click() で降りる（葉に着くまで繰り返す）
  → _on_up_click() で根まで戻る
```

各段で、次の3つを検査する。**特定の市場名・特定の node_path を名指ししない**
——`children[0]` を辿るだけにすること。S3 以降の画面でも同じ網がそのまま効く
必要がある（この網の価値はそこにしかない）。

```
(1) len(panel._levels_frame.winfo_children()) == len(panel._view["levels"])
(2) panel._levels_header_visible == bool(panel._view["levels"])
(3) 子ノード欄の y 座標が、歩いている間ずっと変わらない
    panel._children_frame.winfo_rooty() - panel.winfo_rooty()
```

**(3) が新しい不変条件である**——「**ドリルダウンしてもクリック対象は動かない**」。
(1)(2) は条件8を遷移の上で再掲したもの。

期待する y の値は**書かないこと**（画面が変われば変わる値であり、正典に
してはいけない）。「最初の段で得た値と同じであり続ける」だけを見る。

### 網を壊して発火を確認すること

**M1 の並べ替えを入れる前に条件9を書き、その時点で (3) が落ちることを確認して
から、M1 を入れて緑にすること。** 順序が逆だと「この網が何を守っているか」が
誰にも分からなくなる。Phase 8-1b から続けている作法である。

落ちたときのメッセージには、**最初の y と、跳ねた後の y の両方**を入れてほしい
（「200px 跳ねた」が数字で読めるようにする）。

### 対象

`triangle` モードにはドリルダウンが無いので `skip`。`hierarchy`（oil）だけ。
`load()` を使うこと——遷移させるには `_model_dir` 等がセットされている必要が
あり、いまの `_make_panel()`（view を直接渡す）では歩けない。**`_make_panel()`
は変えず、条件9用のヘルパーを別に足す**のが安全だと思う（既存7条件の挙動を
動かさないこと）。
