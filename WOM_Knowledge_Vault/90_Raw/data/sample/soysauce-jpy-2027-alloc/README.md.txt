## 1. 派生元からの変更点

### 1.1 `capacity_plan.csv` — max_supply を 1500 → 800

**これが本ケースの本質的な変更である。**

| | 派生元 | 本ケース |
|---|---|---|
| Bottling_Noda / Brewing_Noda | 1,500 lot/週 | **800 lot/週** |
| 総能力(104 週) | 156,000 lot | **83,200 lot** |
| 総需要 | 100,501 lot | 100,501 lot |
| 充足率 | 155.2% | **82.8%** |

**変更の理由**: 派生元では能力が需要を大きく上回るため、全市場の需要を同時に満たせる配分が多数存在し、**最適点が 28 格子点にわたる台地となって不定になる**(仕様書 §5.6 / Request Letter §5.6)。配分の意思決定が意味を持たない。

能力を 800/週 に絞ることで、総需要の 82.8% しか生産できなくなり、**市場間の配給(rationing)が必要**になる。これにより最適点が一意に定まる。

**業種としての妥当性**: 醤油の醸造は 4 週の発酵期間を要し(`sc_tree_master.csv` の `Brewing_Noda: lt_wks=4`)、設備投資なしに短期増産できない。「限られた醸造能力を、国内・米国・欧州にどう配分するか」は実在の経営問題である。

なお 1,000/週(充足率 103.5%)では最適点は一意になるものの「全需要を満たす」だけの自明な解となるため、**800/週 を採用する**。

`Materials_JP` の max_supply(50,000)は変更しない。

## 2. `ga_market_aggregation.csv` の根拠

`demand_forecast.csv` の実数量(総需要 100,501 lot)から算出。

| 集約先 | 内訳 region | 数量 | 比率 |
|---|---|---|---|
| JP | JP | 30,150 | 30.0% |
| US | US_W, US_E | 35,176 | 35.0% |
| EU | FR, BE, NL | 35,175 | 35.0% |

`internal_ratio` は集約先内での構成比。**US は 1:1、EU は FR:BE:NL = 1.5:1:1** となる。

**この内部比率は固定であり、最適化の対象外である。** これは市場軸の粒度束縛(仕様書 §2.4)であり、6 市場を独立に動かすと 5 次元単体となって地図として描けなくなるため。

基準配分 (x_JP, x_US, x_EU) = **(0.300, 0.350, 0.350)**

```
交互作用 = (s4 − s1) − (s2 − s1) − (s3 − s1)
```

## 4. `ga_fx_policy_master.csv` の根拠

### 4.1 社内管理レート(`applied_to = decision`)

| 年度 | USD | EUR | 根拠 |
|---|---|---|---|
| FY2027 | 140.0 | 151.2 | 前年度(2026)の実勢を保守的に反映 |
| FY2028 | 150.0 | 162.0 | 前年度(2027)の実勢 150 を反映 |

`revision_lag_q = 4`(年 1 回改定)。

**この設定が生む論点**:

```
FY2028: 社内レート 150 円 / 実勢 200 円 → 乖離 +33%
```

事業部は米国・欧州向けの収益性を **USD 150 円** で評価し続ける一方、実際の決済は 200 円で行われる。すなわち**輸出の魅力を過小評価し、国内に配分しすぎる**。

`ga_fx_decision_gap.csv`(仕様書 §7.8)はこの機会損失を金額化する。日本企業の社内レート改定は年 1〜2 回が通例であり、**この乖離は実務で日常的に発生している**。

保守的(円高寄り)に社内レートを置くのは輸出企業の一般的な慣行だが、円安局面ではそれが配分判断を歪める、という構造がここで可視化される。

### 4.2 為替予約(`applied_to = settlement`)

| 年度 | forward rate (USD) | coverage_ratio |
|---|---|---|
| FY2027 | 145.0 | **0.00** |
| FY2028 | 155.0 | **0.00** |

**v0r3 では `coverage_ratio = 0.00`(ヘッジ無効)とする。**

理由: 仕様書 §9.3 の回帰値(単位マージン・最適配分・交互作用)は**すべてスポットレート前提**で算出されている。ヘッジを有効にすると決済レートが変わり、回帰テストが通らなくなる。

forward rate の値自体は記載してあるため、**`coverage_ratio` を書き換えるだけでヘッジ有効化を試験できる**。ヘッジ有効時の挙動確認は回帰テストとは別に行うこと。

`forward` の水準(FY2028 = 155 円)は「前年度に締結するため当年度の実勢 200 円に追随できない」という実務を反映している。ヘッジは円安メリットを削る方向に働く。

### 5.6 切替点

```
USD 119 円 を下回る → EU > US > JP から EU > JP > US（米国が最下位に）
USD 117 円 を下回る → JP が 2 位に浮上
USD 100 円 付近     → JP > EU > US（国内が最優先）
```

## 6. 注意事項

- **`data/sample/soysauce-jpy-2027/` は変更しないこと。** golden 対象である
- 本ケースは golden 対象外。`tests/test_golden.py` に追加しない
