## D1. 配分ゼロの枝から降りられない（機能の欠落・最優先）

### 何が起きているか

`USD` ノード（`cap_lots == 0`）に降りると、子ノードのリンクが1つも出ない。
パンくずは上にしか進めないので、**`Retail_US_TX` 等の米国5市場の葉に
到達する手段が画面上に存在しない。**

```python
# allocation_panel.py:302  _render_children()
if node["is_unallocated"]:
    tk.Label(self._children_frame, text=node["unallocated_message"], ...)
    return          # ← 子のリンクが1つも作られない
```

### これは私の letter の書き方が悪い

Phase 8-2 の依頼書 C2 にはこう書いた。

> 1. `child_x` を画面に出さない
> 2. 図を描かない
> 3. 台地サイズを出さない
> 4. 代わりに1行 …

**「降りる手段を消す」とは書いていない。** 消すべきだったのは
「意味の無い比率」であって「移動」ではなかった。C2 の本文が
「`child_x` を出さない」という**データの話**と「子ノードの一覧」という
**操作の話**を区別していなかったので、同じ `_render_children()` の中で
両方が消えた。依頼書の不備である。

### なぜ直したいか

**「なぜ USD がゼロなのか」を最もよく説明する画面が、その先にある。**

```
Retail_US_TX（15市場中 15位）  単位マージン 19,500 円/lot（14.4%）  出荷 0 lot
Retail_EU_DE（15市場中  5位）  単位マージン 171,240 円/lot（60.4%）  出荷 24,960 lot
```

この2つを見比べれば理由は即座に分かる。C4（葉の単位経済）は
**まさにこの説明のために作った**のに、C2 がその入口を塞いでいる。
2つの修正が互いを打ち消している状態である。

### 直すこと

`is_unallocated` のときも**子ノードを従来どおりクリック可能に並べる**。
違いは**比率を出さない**ことだけ。

```
（現在・ゼロの枝）  ［子ノードのリンクが無い］
（あるべき姿）      SP_Oil_US_Local   配分なし     ← クリックで降りられる
                    SP_Oil_US_Import  配分なし
```

比率の代わりに何を添えるかは Code君の判断でよい（「配分なし」「— 」など）。
要件は2つだけ:

1. **降りられること**
2. **意味の無い比率（100% / 0%）を出さないこと**

説明の1行（`unallocated_message`）は、子の一覧の**上**に置くか
`_node_info_label` 側に移すか、読みやすいほうでよい。

### view model は変更不要

`build_s1_view()` は既にこの経路を通せる（実測）。

```
node_path=('USD','SP_Oil_US_Local')            -> is_unallocated=True
node_path=('USD','SP_Oil_US_Local','Retail_US_TX') -> leaf_economics あり・rank 15
```

**塞いでいるのはパネルだけである。** ただし tkinter はテストできないので、
view 側に**経路が生きていることを固定するテスト**を1件足してほしい:

> 配分ゼロのノードを経由する `node_path` で `build_s1_view()` を呼ぶと、
> 葉の `leaf_economics` が返る（`rank == 15` / `shipped == 0`）。

これが落ちたら「降りられない」が再発したということになる。

## D2. 「全市場の配分」がウィンドウ幅に追従せず、狭いと消える

### 何が起きているか

同じモデル・同じシナリオで、窓幅だけを変えて撮った2枚を比べる。

```
狭い窓: … / Local_KANSAI 0 / U
        0 / US_Import_MW_I 0 / US_Import_NE_I 0
広い窓: … / Local_KANSAI 0 / US_TX 0 / US_CA 0 / US_NY
        0 / US_Import_MW_I 0 / US_Import_NE_I 0
```

狭い窓では **`US_TX 0 / US_CA 0 / US_NY` がどこにも表示されていない。**

データは完全である（実測: 224文字・15市場すべて含む）。描画だけの問題。

```python
# allocation_panel.py:106-109
self._full_allocation_label = tk.Label(
    self, text="", ..., wraplength=1100)     # ← ピクセル固定
```

`wraplength` が固定値なので、窓がそれより狭くなると折り返されずに
右へはみ出し、フレームに切られる。

### これは C3 で潰したはずの欠陥の再発である

C3 は「結論行が右端で切れて、切れた部分（配分ゼロの市場）が答えだった」
という事故を直した。その際、**畳んだぶんの詳細をこの控え欄に移した**。
つまりこの欄は「答えを画面外に落とさないための受け皿」であり、
**ここが切れると C3 は成立していない。**

### 直すこと

1. `wraplength` をウィンドウ幅に追従させる。`<Configure>` を label（または
   パネル）にバインドし、`wraplength = event.width - (左右パディング)` を
   都度設定する
2. **市場名と数字を折返しで分離しない。** 現状は広い窓でも `US_NY` と `0` の
   間で折れている。`"EU_DE 31"` の中の空白を **` `（ノーブレークスペース）**
   にすれば、区切りの `" / "` でしか折れなくなる。整形は
   `format_market_name()` と同じく **1箇所**に置くこと（A5/A8 の教訓）

` ` を使う場合、**テストの期待文字列も変わる**ことに注意してほしい。
既存テストが `"EU_DE 31"` を半角スペースで期待しているなら、そこも更新する。

## D3. 下の操作行がウィンドウ下端で切れる

### 何が起きているか

⚑ ボタンの行が縦に半分欠けており、「（計画するのは上の推奨配分です）」が
読めない。窓によっては操作行そのものが見えない。

`app.py:4403` の `self.geometry("1280x820")` は Phase 8-2 の前から同じで、
**Phase 8-2 で「全市場の配分」の欄（実測2行）が増えたぶん、下がはみ出した。**
C3 の副作用である。

### 原因（推定・Code君に確認してほしい）

`_build()` の pack 順が

```
入力行 → headline → full_allocation → breadcrumb
      → mid（fill="both", expand=True・Figure figsize=(6.4, 5.2) dpi=95）
      → drill → ops
```

となっており、`mid` が先に要求サイズを取るため、最後に pack される
`drill` / `ops` が窓に収まらないとき押し出される。

### 直すこと

`drill` と `ops` を `side="bottom"` で**先に**pack し、`mid` を後から
`fill="both", expand=True` で pack する（tkinter の定石）。こうすると
窓が縮んでも操作行の高さが先に確保され、縮むのは図のほうになる。

Figure の `figsize` を小さくして逃げる手もあるが、**図が主役なので
それは最後の手段**にしてほしい。`app.py` の `geometry()` は触らないこと
（既存9タブに影響する）。

判断は Code君に委ねる。要件は「**1280x820 の既定サイズで操作行が全部見える**」
ことである。
