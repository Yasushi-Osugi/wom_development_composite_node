## 0. この Request Letter の位置づけ

`ask_global_allocation` は、**生産配分比率の空間全体を走査して利益地形を生成する** Management 層のモジュールである。

既存 WOM との関係は「置き換え」ではなく「上流への拡張」である。具体的には、**`soysauce-us-2027`(S1: 米国集中)と `soysauce-eu-2027`(S2: 欧州分散)という 2 つのフォルダで手作業により比較していた 2 点を、231 点に自動拡張する**ものと理解してよい。

```
現状(v1r2m0 で確立された運用):
  soysauce-us-2027 フォルダ ─┐
                              ├→ demand_forecast.csv の配分だけが違う 2 点を比較
  soysauce-eu-2027 フォルダ ─┘

本 Request:
  ask_global_allocation ──→ 配分比率 231 通りの demand_forecast.csv を生成
                        ──→ 各点で PPC を回し、利益地形を得る
```

したがって **sc_tree は不変**であり、変わるのは `demand_forecast.csv` の region 別配分のみである。これは v1r2m0 で確立された case1 方式(CLAUDE.md 1029 行)の延長線上にある。

### 本 Rev のスコープ

本 Rev では **Phase 1(コアエンジン)と Phase 2(静止画可視化)** までを対象とする。Phase 3(GUI 組込)は地形図の妥当性が確認された後に別 Rev とする。

| 4 | 形態選択(FG/SKD/CKD)・FTA 判定 | 対象外(v0r3/v0r4) |

## 1. 設計の前提(実装前に必ず理解すべきこと)

実装者が「より良い方法」として提案しがちだが、**意図的に採用していない**選択肢がある。以下は既に検討し、棄却した設計である。

### 1.1 なぜ LP/MILP による最適化を使わないのか

**採用しない。** グリッド全数評価を用いる。

理由は三つある。

1. **出力しているものが違う**。LP の出力は一点(最適配分)、グリッドの出力は面(比率空間全域の利益分布)である。経営意思決定に必要なのは後者であり、「最適は 38% です」より「30〜45% の範囲では差が 2% 以内なので、この幅は他の理由で決めてよい」の方が使える。
2. **説明可能性**。LP は最適点のみを返し、地形情報を失う。現場で反証にさらされたときに根拠を示せない。
3. **将来の不連続性**。v0r4 で FTA の原産地規則(付加価値比率の閾値)を導入すると、利益地形が不連続化する。LP では 0-1 変数が必要になり MILP 化するが、グリッドなら各格子点で判定するだけで済む。

なお本方式は README の「It is not a solver that hands you *the optimal answer*; it is a model you run, watch, and reason about」という WOM の設計思想と矛盾しない。**231 回「run, watch」しているだけ**であり、最適化問題を解いているわけではない。

### 1.2 なぜ粒度を粗くするのか

**四半期 × 製品クラス × 配分比率**に束縛する。これは計算量削減の手段ではなく、**モデルの妥当性条件**である。

モデルの粒度は上下から挟まれる。

| 軸 | 下限(これより細かくできない) | 上限(これより細かくしても使われない) |
|---|---|---|
| 時間 | 価格改定ラグ・在庫回転が四半期単位でしか観測できない | 配分の意思決定周期が四半期 |
| 製品 | 関税率は HS6 桁 = 製品クラス相当 | 経営が扱う単位が製品クラス |
| フロー | 価格弾力性 ε は SKU 週次では推定不能 | 戦略層はロット整数性を持たない |

**下限を割ってモデルを細かくした場合、その細部は精緻化ではなく捏造になる。** 関税率が製品クラス単位でしか与えられないのに SKU 別の関税影響を出力すれば、その差分は実在しない。

したがって刻み幅 δ を 0.05 より細かくする要求が出た場合、**拒否してよい**。δ=0.05 は「配分比率を 5% 未満の精度で主張しない」という宣言そのものである。

### 1.3 外部パラメータの層構造

依存関係は直列であり、順序を入れ替えられない。

```
第3層  金利 i        ← 数量に依存(数量が決まった後の残余に効く)
第2層  関税 τ        ← CIF に依存(価格・需要・数量を動かす)
第1層  原油 o(円建て) ← 為替に依存
第0層  為替 e        ← すべての起点
```

**第2層(関税)だけが数量を動かす。** 価格弾力性を経由する増幅経路を持つのは関税のみであり、為替・原油は「どこに売っても同じように効く」ため配分の切替では回避できない。この非対称性が UI 設計(§3.4)に直結する。

### 1.3b Demand Anchored — 需要を超えて生産しない

WOM は Demand Anchored Lot を基礎とするため、**需要を超えた生産は行わない**。

```
production[m] = min( x[m] × Capacity , Demand[m] )
```

余った能力は遊休となり、売れ残り在庫は発生しない。この `min()` により利益地形には**必ず折れ線(尾根)が入り、地形は常に非線形になる**。

仕様書 v0r2 の Step 7 は「余剰生産は当期の機会損失として記録」としていたが、これは WOM の挙動と異なる。**v0r3 で修正すること。**

### 1.4 層の独立性は保証されていない

上記 4 層の効果は加算的に見えるが、**厳密には独立ではない**。

- 原油 ↑ → 輸送費 ↑ → CIF ↑ → **従価関税額 ↑**
- 関税 ↑ → 需要 ↓ → 在庫・売掛 ↓ → **運転資本費用 ↓**(悪影響が自己緩和する)

スマートフォンケースの試算では交互作用は総効果の約 1% に留まったが、**これはパラメータ水準が偶々成立させているだけ**であり、構造的な保証ではない。輸送費比率の高い品目(醤油は液体で嵩張るため該当する可能性が高い)では大きくなりうる。

**この残差を UI 上で隠してはならない**(§3.2)。

## 3. Phase 2: 可視化仕様(本 Request の主眼)

### 3.0 全体構成

```
左: 配分地形図(231 点・等高線)        右: 層別断面(選択した 1 点の内訳)
     ┌─────────────────┐                ┌─────────────────┐
     │ x_EU            │                │ 為替      ▁ +0.3 │
     │  ╲    ● ←選択点  │                │ 原油     ██ −1.2 │
     │    ╲            │                │ 関税   ████ −4.2 │
     │      ╲          │                │ 金利      ▁ −0.3 │
     │        ╲        │                │ 交互作用  ▏ +0.1 │
     └─────────────────┘ x_US           │ ───────────────  │
                                        │ 合計       −5.3  │
                                        └─────────────────┘
```

地図上の点を選択すると、右側の断面が切り替わる。「なぜこの点が低いのか」が即座に読める構造とする。

**これは WOM の既存 UI パターンと同型である**。World Map / Network でノードを選ぶと Management タブに Node P&L が出る、あの操作系。地図が「地理」ではなく「配分比率空間」になっただけであり、`ManagementCockpitPanel` の Node P&L 表示ロジックが実装の参考になる。

### 3.1 左パネル: 配分地形図

#### 座標系(方式 A: 直角三角形を採用)

```
X 軸 = x_US（米国向け配分比率）
Y 軸 = x_EU（欧州向け配分比率）
x_JP = 1 − X − Y   ← 国内は「残余」として読む

定義域: X ≥ 0, Y ≥ 0, X + Y ≤ 1
```

正三角形(重心座標)方式は**採用しない**。X 軸に物理的意味がなく(x_US と x_EU の混合になる)、経営資料では軸の読み方の説明が必要になるため。直角三角形なら軸ラベルがそのまま「米国向け %」「欧州向け %」となり、説明が不要である。

頂点の意味:
- `(0, 0)` = 全量国内
- `(1, 0)` = 全量米国
- `(0, 1)` = 全量欧州
- 斜辺 `X + Y = 1` 上 = 国内向けゼロ(全量輸出)

格子点は `X = i/20, Y = j/20` で `i + j ≤ 20` を満たす整数格子。点数 = C(22,2) = **231**。

#### Z 値(等高線の高さ)

**基準シナリオからの差分**を用いる。絶対額ではない。

| 選択肢 | 採否 | 理由 |
|---|---|---|
| 営業利益(絶対額) | × | 桁が大きく、差が潰れる |
| **基準比 差分** | **○** | **ゼロ等高線が「基準より良いか悪いか」の境界になる** |
| 基準比 変化率 % | △ | 製品クラス間の重ね合わせ時に使用 |

ゼロ等高線は他の等高線と**異なる色・太さ**で描画すること。これが意思決定の境界線になる。

#### 描画方法

`matplotlib.pyplot.tricontourf` + `tricontour`。三角形領域の非構造格子をそのまま扱える。

#### 実行不能領域の扱い(重要)

以下の領域は **山として描かず、グレーアウトする**。

1. `capacity_shared_group` 制約に抵触する領域
2. `unsold_supply_qty` が閾値を超える領域(作っても売れない)

**実行不能領域に高い山があると、読み手は必ずそこを見る。** 塗り分けではなく、等高線自体を描かないこと。

soysauce の場合、`Bottling_Noda` が単一の終端 MOM であるため、能力制約が効く可能性がある。

#### 尾根線(ridge)の明示

伝達式 Step 7 の `Q = min(supply, D)` は、サーフェスに折れ線を生む。

```
supply < D の領域: 作れば売れる    → 配分を増やすと利益が増える(登り)
supply > D の領域: 作っても売れ残る → 増やしても利益は増えない(平坦 or 下り)
```

この境界には明確な経営的意味がある——**「この線から先は、その市場向けに作っても売れない」**。等高線とは別色の線で明示すること。地形の副産物ではなく、地図から読み取れる最も実用的な情報の一つである。

#### FXB 等値線の重ね描き(オプション表示)

`fx_exposure_balance = 1.0` の線を破線で重ねられるようにする。

**利益最大点と為替中立点は一致しない。** この 2 本を重ねることで、地図は次のように読めるようになる。

> 「山頂は破線の外側にある。最大利益を取りに行くと為替エクスポージャーを抱えることになる。破線上まで下がると利益は N% 落ちるが、為替中立になる。この N% をリスクプレミアムとして払うかどうか」

これが本来の経営判断の形である。利益の一点を指すのではなく、利益とリスクのトレードオフを地図上で見せる。

**実証的裏付け**: soysauce-jpy-2027 の実測(CLAUDE.md 1076–1077 行)では、同一製品・同一原価構造にもかかわらず、円安に対して US/EU の lot GM は 28-30% → 33-34% に改善し、Rest_JP は 19.5% → −2.7%(逆ザヤ)に悪化した。**市場によって為替の符号が反転する**という FXB の中核的主張は、既に実データで観測されている。

**描画位置(Rev 2 で確定)**: soysauce の基準配分 (0.300, 0.350, 0.350) における FXB = **0.747**。FXB = 1.0 の等値線は **輸出比率 42.4%(国内 57.6%)** を通る。すなわち破線は基準点より**原点寄り(国内寄り)**を走る。詳細は §5.7。

### 3.2 右パネル: 層別断面

#### 積む値

**基準シナリオからの差分**を積む。絶対額を積んではならない。

```
【絶対額 — 不可】          【基準差分 — 採用】
 売上 ████████████          為替      ▁ +0.3
 原価 ██████████ ←ほぼこれ   原油     ██ −1.2
 関税 █                     関税   ████ −4.2
 利益 ██                    金利      ▁ −0.3
```

絶対額では COGS が大半を占め(soysauce は GM 28% なので原価が 7 割)、外部パラメータ 4 層の差が読めない。基準差分ならゼロ線を中心に、上が改善・下が悪化として 4 層が対等に見える。

#### 交互作用項の明示(必須要件)【Rev 3 で重要度が大幅に上昇】

§1.4 のとおり、4 層の和は総効果と厳密には一致しない。断面図は視覚的に「和 = 総効果」を主張してしまうため、**残差を隠すと嘘になる**。

**Rev 2 までは「交互作用は総効果の 1% 程度の細い残差」と想定していた。これは誤りであった。**

soysauce のプロトタイプ実測(能力 800/週、円安 USD 150→200 × 原料 $6→$8):

| 評価点 | 為替単独 | 原料単独 | 合計(実測) | **交互作用** |
|---|---|---|---|---|
| 基準配分 (0.30/0.35/0.35) | +54.0M | −25.0M | +20.7M | **−8.3M(総効果の −40%)** |
| 最適点 (0.10/0.45/0.45) | +75.1M | −23.6M | +43.6M | **−7.9M(−18%)** |
| 国内厚め (0.60/0.20/0.20) | +23.6M | −19.0M | **−1.8M** | **−6.3M(符号を反転させる)** |

**交互作用は残差ではなく主役である。**

原因は原料が USD 建てであることによる**乗法的相互作用**である。$2 の原料値上がりは USD 150 円なら 300 円/lot、200 円なら 400 円/lot となり、**円安時ほど原料ショックの打撃が大きい**。CLAUDE.md 1078 行の「円安"単独"なら耐えるが、複合ショックが臨界を超える」という記述の正体はこれである。

国内厚めの点では、単独効果の和が +4.6M であるにもかかわらず実測は −1.8M。**層分解で説明すれば結論の符号を誤る。**

**第 5 の帯として交互作用を明示すること。帯は主役級の太さで出る前提で設計する。**

```
 為替       ████████  +54.0
 原油       ████      −25.0
 交互作用   ██▨▨      −8.3    ← ハッチングで「層ではない」ことを示す
 ─────────────────────────
 合計       ███       +20.7   ← ga_profit_surface.csv の実測値と一致すること
```

要件:
- 交互作用帯は他の層と**視覚的に区別**する(ハッチング、枠線の破線化など)
- **合計は実測値と一致しなければならない**(層の和 + 交互作用 = 総効果)
- **帯が他の層と同程度の長さになることを想定してレイアウトすること**(細い残差を前提とした固定幅レイアウトにしない)
- 交互作用が総効果の **5% を超えた場合、警告表示を出す**

#### 5% 閾値の意味(Rev 3 で格上げ)

Rev 2 では「色を変える程度の警告」としていたが、**閾値超過は「層分解による説明の禁止宣言」として扱う**。

```
|交互作用| ≤ 5% of 総効果
    → 層として読んでよい。地層図による説明を許可
|交互作用| > 5% of 総効果
    → 層分解は説明として無効。地層図に
      「この条件では層の和が総効果と一致しません。
        層ごとの対策を独立に立てないでください」
      という明示的な注記を出す
```

**soysauce では常に閾値を超える(−18〜−40%)。** これは仕様の失敗ではなく、規準が正しく機能している証拠である。実装者は「閾値超過が例外ケース」と考えてはならない。

この扱いにより、地層図は「原油対策」「為替対策」を独立の施策として立てるという典型的な誤りを防ぐ装置になる。soysauce の場合、正しい読み方は「**円安と原料高は別々の問題ではなく、掛け算で効く一つの問題である**」となる。

#### 操作可能性の区別(必須要件)

各層が**配分の変更で回避できるか**を視覚的に区別する。

| 層 | 配分で回避できるか | 表示 |
|---|---|---|
| 為替 | **不可**(どこに売っても効く) | 枠線なし / 淡色 |
| 原油 | **不可** | 枠線なし / 淡色 |
| **関税** | **可能**(市場で税率が違う) | **実線枠 / 濃色** |
| 金利 | 部分的(リードタイム経由) | 破線枠 |

理由: これがないと「為替層が厚いから配分を変えよう」という**誤った結論**に導いてしまう。

第0層(為替)と第1層(原油)は、生産配分をどう変えても逃げられない。どの市場に売っても同じように効くためである。経営が配分で動かせるのは第2層(関税)が主であり、第3層(金利)がリードタイム経由で部分的に効く。

**断面図の本当の役割は「何が経営の裁量下にあり、何がないかを分けること」である。** 判断できる領域を絞り込む図として設計すること。

### 5.1 原価ブロック — 既存 CSV から導出可能【実証済み】

**判定: `ga_cost_block_master.csv` は不要。導出器として実装する。**

#### 導出元

| ブロック種別 | 出典ファイル | 通貨の決まり方 |
|---|---|---|
| 原料費 | `ppc_supplier_cost.csv` | `currency` 列(soysauce は USD) |
| 物流費(エッジ) | `ppc_edge_cost_rule.csv` | `currency` 列(soysauce は全 USD) |
| 加工費・倉庫費・SGA(ノード) | `ppc_node_cost_rule.csv` | `currency` 列(国内 JPY / 海外は現地通貨) |
| 経路 | `sc_tree_master.csv` | チャネルごとのノード・エッジ列挙 |
| 関税 | `ppc_tariff_rule.csv` | `tariff_basis = transfer_price` |

#### 導出アルゴリズム

```
for each leaf_out チャネル c:
    経路 = sc_tree を leaf_out から root まで遡って得たノード列・エッジ列
    for each ノード n in 経路:  ppc_node_cost_rule の (n, product) 行を通貨別に加算
    for each エッジ e in 経路:  ppc_edge_cost_rule の (e, product) 行を通貨別に加算
    原料費:                     ppc_supplier_cost の leaf_in 行(週次 latest-prior 参照)
    → 通貨別ブロック集合 {(currency, amount)} を得る

FCR(c) = Σ(外貨建ブロック × FX) / Σ(全ブロック × FX)
```

`fx_exposure_flag` は不要。**`currency != base_currency` が外貨建の判定条件**となる。

#### 検証結果(実測 4 点の完全再現)

`Rest_JP` チャネルの導出値:

```
外貨建(USD): 原料 6.0 + 物流(M→B 0.3, B→Bo 0.4, Bo→FG 0.4, FG→DC_JP 1.0, DC_JP→Rest 1.0)
             = 9.1 USD
円建(JPY):   醸造 750 + 瓶詰 750 + FG倉庫 75 + 国内DC 150 = 1,725 JPY
関税:        JP→JP = 0
売価:        3,840 JPY(sku_master / ppc_market_price)
FCR(JP チャネル) = 1,365 / 3,090 = 44.2%   ※ FX=150 時
```

| 条件 | 導出値 | CLAUDE.md 1077 行の実測 | 差 |
|---|---|---|---|
| 2027(USD 150、原料 $6.0) | **19.53%** | 19.5% | 0.03pp |
| 2028 円安のみ(USD 200、$6.0) | **7.68%** | +7.7% | 0.02pp |
| 円安×原油(USD 200、$8.0) | **−2.73%** | −2.7% | 0.03pp |
| ショック後(USD 200、$6.5) | **5.08%** | +5.1% | 0.02pp |

**4 点すべてが 0.1pp 以内で一致。** 導出ロジックの妥当性は実証済みである。

輸出チャネルも同様に導出でき、US_W / EU とも FX=150 時 **29.75%**(CLAUDE.md の「28-30%」と整合)。

- 導出結果を `output/allocation/ga_cost_block_derived.csv` に書き出し、監査可能にする

### 5.5 原油の扱い — spec 側を WOM に合わせる。ただし β は未実装

#### WOM の実装

原油は**独立パラメータとして存在しない**。`Materials_JP` の USD 購入価格の週次ステップとして表現されている。

```
ppc_supplier_cost.csv:
  Materials_JP, Soy_Sauce, 2027-W01, 6.0, USD
  Materials_JP, Soy_Sauce, 2028-W10, 8.0, USD   ← ホルムズ想定のスパイク
  Materials_JP, Soy_Sauce, 2028-W26, 6.5, USD   ← 床が上がって戻らない

`ppc_rules.py` の `get_supplier_cost` は latest-prior-week 参照のため、値が変わる週だけ行を置けばステップ関数になる。

これは仕様書の γ(素材原価感応度)より直接的であり、**spec 側を WOM に合わせるべき**である。`ga_scenario_master.csv` の `oil_brent_usd` は、`material_price_usd`(原料価格の直接指定)に置き換える。

#### β(輸送費の燃費感応度)は未実装

`ppc_edge_cost_rule.csv` の物流費は **USD 固定額**であり、原油に反応しない。

```
FG_WH_Noda->DC_US_SF   4.0 USD
FG_WH_Noda->DC_US_NY   4.5 USD
FG_WH_Noda->DC_EU_RTM  6.0 USD
FG_WH_Noda->DC_JP      1.0 USD

醤油は液体で嵩張るため輸送費比率が高く(輸出チャネルの外貨建 17.6 USD のうち物流が 8.0〜9.5 USD)、β を導入すれば効果は大きい。

**ただし本 Rev では β を実装しない。** 既存モデルとの整合(実測 4 点の再現性)を優先し、**v0r3 送りとする**。実装する場合は `ppc_edge_cost_rule.csv` に `fuel_beta` 列を追加する形になるが、これは既存 21 CSV の変更にあたるため別 Request Letter が必要。

### 5.6 【重大】このままでは最適点が台地化して不定になる

**実装前に必ず対処すること。受け入れ基準 #11 に対応。**

> **Rev 3 訂正**: Rev 2 では「利益が配分の線形関数になり、地形が傾いた平面に退化する」と記述したが、**これは誤りであった**。WOM は Demand Anchored であり需要を超えて生産しないため、`Q = min(x·Cap, D)` の折れ線が必ず入り、地形は常に非線形になる。実際の失敗モードは**平面化ではなく台地化(plateau)** である。プロトタイプ実測により確定。

#### 問題

現状の soysauce は以下の条件を満たしている。

| 要素 | 現状 | 帰結 |
|---|---|---|
| 市場価格 | `ppc_market_price.csv` で**固定** | 数量を増やしても価格が下がらない |
| 価格弾力性 ε | **WOM に存在しない** | 需要が価格に反応しない |
| 関税吸収率 α | **WOM に存在しない** | 関税が価格に転嫁されない |
| 需要 | `demand_forecast.csv` で**外生固定** | 上限としてのみ機能 |
| 能力 | Bottling / Brewing = **1,500/週** | 需要平均 966/週 → **非拘束** |

能力が需要を上回る(充足率 155%)ため、**全市場の需要を完全に充足できる配分が多数存在する**。それらの点はすべて同一の利益を与えるため、最適解が一意に定まらない。

```
需要天井: x_JP ≥ 0.193, x_US ≥ 0.225, x_EU ≥ 0.225
上限の和 = 0.644 < 1  →  すべて同時に満たす領域が広く存在する
```

#### プロトタイプ実測

| 能力 | 充足率 | 台地サイズ(最大値の 0.1% 以内の格子点数) | 判定 |
|---|---|---|---|
| **1,500/週(現状)** | 155.2% | **28 / 231 点** | **☓ 台地。意思決定が不定** |
| 1,000/週 | 103.5% | 1 点 | 一意だが「全需要を満たす」だけで自明 |
| **800/週** | **82.8%** | **1 点** | **★配給が必要 → 意思決定が意味を持つ** |

#### 対処(推奨: 能力を絞る)

| # | 条件 | 実装コスト | 業種整合性 | 推奨 |
|---|---|---|---|---|
| 1 | **能力制約を拘束させる(800/週)** | 小(CSV のみ) | **高** | **採用** |
| 2 | 価格弾力性 ε の導入 | 中(新パラメータ) | 中 | v0r3 |
| 3 | 関税吸収率 α の導入 | 中(新パラメータ) | 中 | v0r3 |

**能力を絞ることを推奨する理由は、業種として自然だからである。**

> 醤油の醸造は 4 週の発酵期間を要し(`sc_tree_master.csv` の `Brewing_Noda: lt_wks=4`)、設備投資なしに短期増産できない。**限られた醸造能力を、国内・米国・欧州にどう配分するか。**

1,000/週 では不足(充足率 103.5% で全需要が満たせてしまい、最適解は自明)。**800/週(充足率 82.8%)を採用すること。**

#### 具体的な設定

```
data/sample/soysauce-jpy-2027/              ← 変更禁止(golden 対象)
data/sample/soysauce-jpy-2027-alloc/        ← 新規。capacity_plan.csv のみ変更
                                               max_supply: 1500 → 800
```

派生ケースは golden 対象外とし、`tests/test_golden.py` に追加しないこと。

#### 検証項目(受け入れ基準 #11)

- 能力 800/週 の下で **台地サイズが 1 点**になること
- 能力 1,500/週 の下で **台地サイズが 28 点**になること(退化の再現)
- 需要天井の折れ線(尾根)が `x_US = 0.423` / `x_EU = 0.423` / `x_JP = 0.362` に現れること

**能力 800/週 で台地サイズが 6 点以上になる場合、実装かモデル設定のいずれかに誤りがある。**

### 5.6b 台地が出た場合の扱い — `robust_point` の導入【Rev 3 新規】

台地は「利益基準では決められない」という**情報**であって、「どこでもよい」という意味ではない。台地上の点は利益こそ同じだが、以下の点で異なる。

| 軸 | 台地上での違い |
|---|---|
| **FXB** | 台地を FXB=1.0 線が横切る。左下(国内厚め)は円安デメリット型、右上(輸出厚め)は円安メリット型。**同じ今期利益でも、来期の利益が正反対** |
| **遊休能力の配分** | どの市場に余力を残すかが違う。需要上振れに応えられる市場が変わる |
| **他シナリオでの標高** | 基準シナリオで同一高度でも、円安・円高シナリオでは標高がばらける。**台地は「今の前提が続けば同じ」であって「何が起きても同じ」ではない** |

したがって台地が検出された場合、**判断基準を利益から別軸へ移す**必要がある。

#### 出力仕様: `ga_plateau.csv`

```
scenario_id            基準シナリオ
plateau_size           台地サイズ（格子点数）
plateau_points         台地に含まれる配分のリスト
fxb_min, fxb_max       台地内での FXB の幅
robust_point           全シナリオでの最低標高が最大の配分（ミニマックス点）
robust_worst_profit    その点の最低標高
argmax_worst_profit    基準最適点の最低標高（比較用）
```

**`robust_point` の算出**: 台地に含まれる各点を全シナリオで評価し、**最低利益が最大の点**を選ぶ。

```
robust_point = argmax_{x ∈ plateau} ( min_{s ∈ scenarios} profit(x, s) )
```

計算コストはゼロである(`ga_profit_surface.csv` に既にある値の集計にすぎない)。**台地が出るケースでは、これが実質的な推奨解となる。**

#### 出力仕様: `ga_constraint_cost.csv`

非経済的制約のコストを定量化する。

```
constraint_id          例: domestic_floor_20pct
constraint_expr        例: x_JP >= 0.20
scenario_id
profit_unconstrained   制約なしの最適利益
profit_constrained     制約下の最適利益
cost_of_constraint     差額
```

**必要性**: プロトタイプでは、円安×原油の複合シナリオにおける最適解が `x_JP = 0.00` ——**国内供給の完全停止**であった。数値上は正しいが、醤油という商材で実行できる企業はまずない。

このとき地図の正しい使い方は「国内 20% を維持すると利益がいくら落ちるか」を読むことである。**制約のコストを定量化する**ことで、経営判断の材料になる。

---

### 5.7 FXB の実測値と為替中立線の位置

基準配分 (0.300, 0.350, 0.350) における実測(FX = 150 時):

```
FCR（外貨建コスト比率） = 0.588
FRR（外貨建収入比率）   = 0.787
FXB                     = 0.747   → 円安メリット型
```

そして **FXB = 1.0 となる為替中立線は、輸出比率 42.4%(国内 57.6%)を通る**。

基準配分は輸出 70% であるため、地図上では **FXB = 1.0 の破線が基準点より国内寄り(原点寄り)を走る**。これにより §3.1 の FXB 等値線重ね描きが、次の形で読めるようになる。

> 「現在の配分は為替中立線より輸出側にある。円安局面では有利だが、円高に振れると逆に効く。中立線まで国内比率を上げると利益は N% 落ちるが、為替感応度はゼロになる。」

**この 42.4% という数値は Unit テストの期待値として使えること**(受け入れ基準 #12)。
