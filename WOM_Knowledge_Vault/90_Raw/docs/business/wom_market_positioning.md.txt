# WOM 市場ポジショニングと提供モデル

**検討記録（2026-08-25）。** 本書は事業側の位置づけを整理したもので、コード・スキーマには一切関与しない。

`docs/design/` 配下の技術文書（三層可視化、三層生産配分）と対になる。前者が「何をどう作るか」を扱うのに対し、本書は「誰に、何として売るか」を扱う。

**匿名化方針**：本書では固有の企業名・案件名・個人名を記載しない。WOM のケーススタディと同じ方針に従う（後述 §6）。具体的な相手先は別途、非公開で管理する。

---

## 0. 要約

2026-08 の外部評価と実案件接触を経て、**WOM の市場定義を修正した。**

| | 修正前の想定 | 修正後 |
|---|---|---|
| 位置づけ | S&OP ツールの低価格版 | **新規事業・投資判断の事業性評価ツール** |
| 破壊の型 | ローエンド型 | **新市場型** |
| 非消費者 | 既存ツールが高すぎる中堅企業 | **定量的な事業構造評価の道具を持たない新規事業開発者・投資家** |
| 現状の代替手段 | Excel と勘 | Excel、PowerPoint、コンサルタントの定性判断 |
| 価格帯 | 低価格 | **高付加価値** |
| 競合 | S&OP ベンダー | **原理的に不在** |

## 1. 修正の根拠

### 1.1 実案件からの逆算

2026-08 に、コンサルティングファーム経由で二つの適用テーマが提示された。

- **A：新規事業の海外展開の事業性評価**（政府系プログラム予算による F/S）
- **B：M&A のオペレーショナル・デューデリジェンス**（総合商社の M&A 部門）

両者の共通点は「**実績データが答えを与えてくれない状況で、事業構造を定量的に評価する**」ことである。既存事業の効率化ではない。

A については、提示された資料をもとに AI 支援下で**約30分で完全なモデル**（22 CSV・104週・ヘッドレス完走・GM 20.0%・全ノード CO=0）が構築された。

### 1.2 既存 S&OP ベンダーが構造的に入れない理由

S&OP ツール（o9、Kinaxis、SAP IBP 等）は、いずれも**実在するサプライチェーンのマスタデータを前提**にしている。品目マスタ、BOM、拠点、実績、リードタイムの実測値。それらを取り込んで、既にあるものを最適化する。

**まだ存在しない事業には、マスタデータが存在しない。** 価格でも機能でもなく、**入力の前提が異なる**ため、原理的に立ち上がらない。

WOM は CSV に「宣言」を書けばモデルが成立する。実績がなくても、想定を書けば動く。30分で成立したのは速度の話に見えて、実は「**実在しないものをモデル化できる**」という性質の話である。

### 1.3 設計思想との整合

`ask_global_allocation` が LP 最適化を採らず、231格子点の全数評価で利益地形を描く設計は、この文脈で意味が変わる。

**まだ無い事業に「最適解」は存在しない。** あるのは「どの前提が成り立てば、どの構造が有利か」という地形だけである。設計思想が、そのまま新規事業評価の要件と一致している。

## 2. 破壊の型：新市場型（ローエンド型ではない）

クリステンセンの分類に照らすと、WOM はローエンド型破壊ではない。

- **ローエンド型**：既存市場の過剰満足された顧客を、安く十分な製品で奪う
- **新市場型**：既存製品が高すぎる・複雑すぎるという理由でそもそも消費していなかった非消費者に届ける

WOM が当たっているのは後者。ただし**「安いから」の非消費ではなく「道具が存在しないから」の非消費**であり、価格帯は低価格ではなく高付加価値領域になる。

**実務上の帰結**：自らを「S&OP ツールの廉価版」と位置づけた瞬間に、機能比較表を作られて負ける。「経営が事業構造を評価する道具」であれば、比較対象は Excel と PowerPoint とコンサルタントの人月になる。

**方針**：「10〜20年かけて機能で追いつく」のではなく、**別の土俵で先に地歩を固める**。並行して、目前の実案件は常に取る（新しい経験とノウハウの源泉であるため）。

## 3. 優位の所在：機能ではなく経済構造

AI 支援は WOM の最大のアドバンテージだが、**機能開発の速度としての優位ではない。** 同じ AI は競合も使え、資本と人員の多い側が有利になる。

非対称性は以下の三点にある。

### 3.1 規模の経済が逆に効く

既存ベンダーは営業・導入コンサル・サポートを抱えており、**数千万〜数億円の案件でないと採算が合わない組織構造**を持つ。年商10億円規模の企業のサプライチェーン評価は、構造的に引き受けられない。

これはサービス提供組織のコスト構造の差であり、**AI では埋まらない。**

### 3.2 モデル定義の速度が、案件の形そのものを変える

通常の SC 導入は「要件定義に数ヶ月、構築に一年」。30分でモデルが立つなら、**会議の中で前提を変えて再実行できる。** これは同じ商品の速い版ではなく、別の商品である。

さらに、モデル定義工数が下がり続けるため、価格を下げずに利益率を上げるか、価格を下げて市場を広げるかを選べる。一方、導入コンサルタントを抱える側は AI で速くなるほど「なぜまだ高いのか」を問われる。

### 3.3 設計者本人がクライアントの前に座る

ベンダーの現場コンサルタントは自社製品の内部構造を知らない。WOM は設計者が直接、前提と限界を説明できる。

## 4. 二つの適用領域

### 4.1 新規事業の事業性評価（F/S）

**買い手**：政府系プログラム（産業振興・国際協力予算）、開発金融、事業会社の新規事業開発・経営企画。

**問い**：この事業は成立するか。どの前提が成り立てば成立するか。

**WOM の適合理由**：具体的なサプライチェーン・モデルを定義しながら、新規ビジネスのシミュレーションを行える。実績データを必要としない。

### 4.2 M&A オペレーショナル DD

**買い手**：総合商社・事業会社の M&A 部門、PE / VC の産業案件。

**問い**：買収後のオペレーションはどうなるか。シナジーの根拠は何か。その効果はどの前提が崩れたら消えるか。

M&A の財務 DD は過去実績の分析と将来 CF 予測で構成される。しかし製造業・流通業の買収で本当に効くのは**オペレーションの構造**であり、そこを定量評価する道具が現在存在しない。

| M&A の問い | 対応する WOM 機能 |
|---|---|
| 買収後、どの拠点からどの市場へ供給すべきか | ネットワーク定義 / `lane_assignment` |
| 拠点統合でどれだけ在庫が減るか | PSI の週次在庫遷移 |
| 関税・FX が動いたら結論は変わるか | PPC、切替点分析 |
| その効果はどの前提が崩れたら消えるか | **決定反転テスト** |

**最後の行が投資委員会で最も価値がある。** 「シナジーは X 億円です」より「**この前提が崩れるとシナジーは消えます。境界はここです**」の方が、意思決定の材料として強い。

### 4.3 提供モデル（三層）の修正

F/S は原理的に一回きりであり、S&OP のような継続ライセンスにはならない。この領域の継続は別の形をとる。

```
① 事業性評価（F/S / DD）        投資判断の前
② 前提の見直し                   環境変化のたび（関税・FX・需要）
③ 事業立ち上げ後の運用計画       同じモデルが操業計画に移行する
```

**①で作ったモデルが③でそのまま動く**ことが WOM の固有の強み。通常のコンサルティングでは F/S の Excel は事業開始とともに捨てられる。WOM なら同一スキーマのまま週次計画に接続できる。

また M&A 部門は年に複数案件を見るため、**同一スキーマの再利用が前提**になり、業種テンプレートの蓄積が自然に継続収益へつながる。

## 5. 守秘要件と二段階運用

### 5.1 この領域の参入条件

新規事業 F/S も M&A DD も、**案件そのものが機密**である。対象企業名も伏せられる。したがって守秘設計は付加価値ではなく**参入条件**になる。

### 5.2 採用する運用

```
第1段階  モデル構造の設計
         実在企業名・実データを一切使わない
         業界構造をもとにした匿名モデルとして AI 支援下で定義・完成
         　↓ サニタイズ（構造を保ったまま名称を匿名化）
第2段階  実データによる評価
         AI から隔離したローカル環境（ネットワーク非接続）
         実企業名・実データを投入し、決定反転テスト等を実行
         データはクライアント管理下から出ない
```

**根拠**：WOM はモデル定義（構造）とデータ（数値）が CSV スキーマで分離されているため、両者を別環境に置ける。構造には機密が無く、機密は数値側にある。

第2段階に AI の支援は不要（Python がローカルで走ればよい）。**Local-First アーキテクチャ（ローカル PC、Tkinter、Python、クラウド依存なし）が、守秘のための必須条件として機能する。**

依存が薄い（Anaconda + pandas/numpy/matplotlib）ため、隔離環境は1時間程度で構築できる。

### 5.3 クラウド型 S&OP に対する構造的優位

クラウド型ツールは実データをベンダーのクラウドに置くことが前提であり、「隔離環境で動かす」選択肢が構造的に存在しない。

**説明としては「保存しない」より「そもそも送っていない」の方が強い。**

### 5.4 AI プラットフォームのデータ取扱い（2026-08 時点の確認）

参考情報として記録する。**規約は変わるため、クライアント説明の直前に必ず最新を確認すること。**

| | 訓練利用 | 保持 | ZDR |
|---|---|---|---|
| 消費者プラン（Free/Pro/Max） | 設定で選択（既定は要確認） | 許可時は最大5年（非識別化）、不許可時は短期 | **対象外** |
| Commercial（API、Team/Enterprise） | 消費者規約の変更は非適用 | 契約による | **API・Claude Code は対象**（組織単位で要申請） |

ZDR 下でも、法令要請または自動化された安全性システムのフラグにより、最大2年の保持が起こりうる。

**結論**：上記 §5.2 の二段階運用を採る限り、**機密データはプラットフォームに到達しないため、ZDR 契約は必須ではない。**「送らない」は「保存しない」の上位保証である。

ただし以下のいずれかが生じた場合は Commercial + ZDR を検討する。

- クライアント法務が契約上の保証（DPA 等）を書面で求めてきたとき
- 第2段階でも AI 支援が必要と判明したとき
- ファーム側が自社の契約枠での作業を求めてきたとき

### 5.5 最大のリスクは規約ではなく運用規律

第2段階で異常が出たとき、「AI に聞いてみよう」となる瞬間が必ず来る。**エラーメッセージを貼った時点でノード名が漏れる。** 一行に拠点構成と需要規模が含まれうる。

**対策は物理的な遮断**（第2段階の PC に AI ツールを入れない／アクセスできない状態にする）。規約や契約では防げない。

## 6. 知的資産の公開方針

### 6.1 基本方針

**「WOM のノウハウは人類と AI の共通の知的資産であるべき」**という立場を採る。方法論はまだ未完成であり、closed にすると発展速度が落ちる。多くの人が英知を吹き込んで方法論を確立することが望ましい。

### 6.2 継承の形式：ハーバード式ケーススタディ

**固有の企業名とクリティカルな数字は出さない。業界名と業界特有の構造をもとにした Case Study として記述し、「ハーバード式ケーススタディの手法による」と明示する。**

WOM の既存7ケースは、既にこの形式で作られている（企業名を出さず、業種を明示し、数値は例示）。方法論として自覚的に整理されていなかっただけで、実践は先行していた。

### 6.3 HBS ケースとの違い

| | HBS ケース | WOM ケース |
|---|---|---|
| 素材 | 実企業への取材 | **業界構造の再構成** |
| 許諾 | 必要 | 不要 |
| 中身 | 記述と数表 | **動くモデル（22 CSV）** |
| 読者ができること | 議論する | **前提を変えて再実行する** |
| 更新 | されにくい | 関税・FX を書き換えれば現在化 |

**「読んで議論する」から「動かして反転を見る」へ。**

「ハーバード式」と明示することは、匿名化の正統性を説明する根拠にもなる。

### 6.4 公開と非公開の切り分け

```
公開（帰属あり・改良の循環あり）
  エンジン           MIT ライセンス
  ケーススタディ     業界構造ベース、企業名なし、数値は例示、動くモデル一式
  方法論の文書       設計文書、論文、記事

非公開
  実企業名・実データ  隔離環境のみ
  クライアント固有の判断
```

**ケーススタディが、公開と非公開の橋になる。** 実案件から学んだ構造を、匿名化した教材として還元する。

### 6.5 訓練データ提供との区別

GitHub・論文・Zenodo DOI は**帰属を伴って広がり、他者が改良を返せる**。訓練データは**帰属なく能力として溶け、改良を返す先が存在しない**。

「人類と AI の共通資産にする」という目的に対しては、**前者の方が効率が良い。**

また、共同での検討記録には他者（評価者、案件関係者）の情報が混在するため、公開の可否を単独で判断できない。**「クローズドにする」のではなく「開く場所を選ぶ」。**

## 7. 教育としての WOM

### 7.1 位置づけ

論文（Weekly Granularity Thesis）、7ケーススタディ、記事、公開方針 — これらが同時に成立する場が教育である。

コンサルティングは一件ずつしか進まないが、講義は一度に多数へ届く。受講生は数年後に事業側の意思決定に近い位置にいる。

### 7.2 講義設計（案）

```
第1週  ケースを読む         なぜ直感に反する構造が有利になるのか
第2週  モデルを開く         CSV が何を宣言しているかを読む
第3週  前提を動かす         パラメータを変えると結論が反転する
第4週  切替点を求める       境界はどこか、余裕は何ポイントか
第5週  自分でモデルを作る   受講生が自社／関心業界の構造を定義する
```

### 7.3 第5週が本質

**受講生が何人モデルを立てられるかが、そのまま「モデル定義の再現性」の測定になる。**

これは事業の中核仮説（WOM が開発者以外にも運用可能か）を、**商業リスクなしに検証できる唯一の場**である。実案件と違い、教室では失敗が学びになる。

### 7.4 経路

大学の専任職は公募サイクルが年単位で、業績が問われる（論文を進めておくことが正しい順序）。一方、講義自体は所属なしでも始められる（ゲスト講義、企業研修、業界団体セミナー）。

**教育は、他者の判断を待たずに進められる領域**でもある。

## 8. 検証の根拠という未解決問題

### 8.1 問題

実在するサプライチェーンなら、モデルの妥当性は実績との照合で確認できる。**まだ存在しない事業には照合対象がない。**「このモデルは正しいか」に、事実で答えられない。

### 8.2 対応

- **V&V 方法論**：三軸の粒度制約（時間・製品・フロー）による「意図した用途」の明示
- **決定反転テスト**：宣言した誤差の範囲内で前提を動かし、推奨される意思決定が反転しないことを示す
- **三層可視化**（静的 lint / E2E マトリクス / スイムレーン）：モデルの妥当性を第三者が納得するための根拠

「答えが正しい」ことは証明できない。しかし「**宣言した範囲内で意思決定が反転しない**」ことは示せる。投資判断において、意思決定者が本当に知りたいのはこちらである。

**実績と照合できない世界では、三層可視化が唯一の納得の根拠になる。** 技術文書側の設計が、事業側の参入条件と直結している。

## 9. 市場境界（2026-08 の外部評価から）

現役の SCM コンサルタントとの対話から、明確な線引きが得られた。

| | 対象 | 時間粒度 | 意思決定の段階 |
|---|---|---|---|
| SCM 実行系 | 動いている業務の効率化・IT 自動化 | 日・時間・分 | 実行 |
| **WOM** | **まだ決まっていない事業構造の評価** | **週** | **投資・構造決定** |

**アンマッチという結論は失敗ではなく、市場境界の確定である。** 時間軸の違いに見えて、実際には意思決定の段階が違う。

また、この線引きは Weekly Granularity Thesis を否定せず裏付ける。週次が正しいのは「経営判断の粒度と一致するから」であって、実行系の粒度と一致するとは主張していない。
